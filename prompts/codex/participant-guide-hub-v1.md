# Codex 작업 지시서

## 작업 이름

참여자 안내 허브 v1

## 목표

프로젝트 리디파인 디스코드 봇의 참여자 진입 UX를 단순화한다.

현재 참여자용 명령어는 `/안내`, `/포인트`, `/상점`, `/교환`, `/체크인`, `/미션`, `/인증`, `/질문`, `/리디` 등으로 많아졌다. 기능은 늘었지만 참여자 입장에서는 어떤 명령어를 언제 써야 하는지 헷갈릴 수 있다.

이번 작업에서는 기존 `/안내` 명령어를 참여자용 메인 허브로 개편한다.

핵심 목표:

- 참여자는 우선 `/안내` 하나만 기억하면 되게 한다.
- `/안내` 응답에서 버튼 또는 드롭다운으로 주요 기능 안내를 볼 수 있게 한다.
- 포인트, 상점, 미션, 인증 방법, 문의 방법을 한 화면에서 시작할 수 있게 한다.
- 참여자가 `/교환`, `/인증` 같은 세부 명령어를 몰라도 흐름을 이해할 수 있게 한다.
- 반응 승인 방식의 미션 인증 채널 안내를 포함한다.
- 기존 `/포인트`, `/상점`, `/교환`, `/미션`, `/인증` 기능은 유지한다.
- 새 Slash Command는 추가하지 않는다.
- Google Sheets 연동, PostgreSQL 연동, 웹 관리자 페이지는 구현하지 않는다.

## 중요 UX 원칙

### 참여자는 명령어를 많이 외우지 않아도 되어야 한다

참여자에게 적극 안내할 명령어는 우선 아래 정도로 줄인다.

- /안내
- /포인트
- /상점
- /미션
- /체크인

/교환과 /인증은 직접 사용할 수도 있지만, 기본적으로는 /안내, /상점, /미션, 미션 인증 채널을 통해 자연스럽게 이해하게 한다.

### /안내는 메인 허브 역할을 한다

/안내 실행 시 아래 항목을 버튼 또는 선택 메뉴로 제공한다.

- 처음 왔어요
- 오늘 뭐 하면 되나요?
- 내 포인트 확인하기
- 상점/교환 알아보기
- 미션/인증 방법 보기
- 운영진에게 문의하기

Discord 버튼은 한 줄에 최대 5개까지 표시 가능하므로, 너무 많으면 select menu를 사용해도 된다.

추천 방식:

- 메인 화면은 Embed + Select Menu
- Select Menu placeholder: 궁금한 내용을 선택해 주세요
- 선택 항목:
  - 처음 안내
  - 오늘 할 일
  - 포인트
  - 상점과 교환
  - 미션과 인증
  - 문의하기

버튼 방식이 더 적합하면 버튼으로 구현해도 된다. 다만 모바일에서 보기 편해야 한다.

### 응답은 기본적으로 본인만 보이게 한다

/안내 허브 응답은 ephemeral을 유지한다.

참여자 개인에게만 보이는 안내가 기본이다.

### 모달은 사용하지 않는다

이번 작업에서 모달은 안내용으로 사용하지 않는다.  
모달은 입력받는 용도에 더 적합하므로, 안내는 Embed + 버튼/드롭다운으로 처리한다.

## 중요 주의사항

- 새 Slash Command는 추가하지 않는다.
- 기존 Slash Command 이름은 변경하지 않는다.
- /안내 명령어를 허브로 개편한다.
- .env 파일은 수정하지 않는다.
- 실제 토큰, 실제 채널 ID, 실제 개인정보는 작성하지 않는다.
- data/*.local.json은 커밋하지 않는다.
- package.json, package-lock.json은 수정하지 않는다.
- Railway, GitHub 설정은 변경하지 않는다.
- Google Sheets 연동은 구현하지 않는다.
- PostgreSQL 연동은 구현하지 않는다.
- 웹 관리자 페이지는 구현하지 않는다.
- npm run deploy는 실행하지 않는다.
- git commit, git push는 하지 않는다.
- 기존 /포인트, /상점, /교환, /체크인, /미션, /인증 동작을 깨지 않는다.
- 반응 승인 공개 답글/DM 전환 작업은 이번 범위에서 제외한다.

## 작업 3. 처음 안내 화면

사용자가 “처음 안내”를 선택하면 아래 내용을 보여준다.

권장 문구:

처음에는 천천히 둘러봐도 괜찮아요.

리디파인 디스코드는 안내, 미션, 포인트, 상점, 문의가 한곳에 모여 있는 공간이에요.  
모든 활동은 강제 과제가 아니라, 가능한 범위에서 참여하는 선택형 활동입니다.

먼저 해볼 수 있는 것:

- `/체크인`으로 오늘의 상태를 가볍게 남기기
- `/미션`에서 참여 가능한 활동 확인하기
- `/포인트`로 내 여정 포인트 확인하기
- `/상점`에서 교환 가능한 항목 둘러보기

문구는 부드럽고 부담 없게 작성한다.

## 작업 4. 오늘 할 일 화면

사용자가 “오늘 할 일”을 선택하면 오늘 참여 가능한 흐름을 짧게 보여준다.

권장 문구:

오늘은 이렇게 시작해도 좋아요.

1. `/체크인`으로 오늘의 상태를 가볍게 남겨요.
2. `/미션`에서 지금 참여 가능한 미션을 확인해요.
3. 인증이 필요한 활동은 미션 인증 채널에 글이나 사진을 올려요.
4. 운영진이 확인하면 여정 포인트가 지급돼요.

가능하면 현재 active 미션 수를 표시할 수 있으면 좋다.

예시:

현재 참여 가능한 미션: 2개

어렵다면 active 미션 수 표시는 생략해도 된다.

## 작업 5. 포인트 안내 화면

사용자가 “포인트”를 선택하면 여정 포인트 설명을 보여준다.

권장 문구:

여정 포인트는 참여를 기록하기 위한 작은 보상이에요.

포인트는 경쟁이나 순위를 위한 점수가 아니에요.  
체크인, 미션 참여, 프로그램 활동 등을 통해 받을 수 있고, 운영진이 정한 항목으로 교환할 수 있어요.

확인 방법:

- `/포인트`로 내 포인트 확인
- `/상점`으로 교환 가능한 항목 확인

가능하다면 이 화면에서 현재 사용자 포인트를 함께 보여준다.

예시:

현재 내 포인트: 120P

단, 구현이 복잡하면 안내만 제공해도 된다.

## 작업 6. 상점과 교환 안내 화면

사용자가 “상점과 교환”을 선택하면 상점/교환 흐름을 안내한다.

권장 문구:

상점에서는 여정 포인트로 교환 가능한 항목을 볼 수 있어요.

사용 방법:

1. `/상점` 또는 `/교환`을 입력해요.
2. 목록에서 원하는 항목을 선택해요.
3. 신청 전 내용을 한 번 더 확인해요.
4. 교환 신청이 접수되면 운영진이 순차적으로 확인해요.

안내:

- 선택만으로는 포인트가 차감되지 않아요.
- 교환 신청을 완료하면 포인트가 차감돼요.
- 단순 변심에 따른 취소나 환불은 원칙적으로 어려울 수 있어요.

가능하면 이 화면에서 상점 보기 버튼 또는 “/상점 명령어를 사용해 주세요” 안내를 둔다.

Slash Command를 버튼으로 직접 실행할 수 없다면, 안내 문구만 제공한다.

## 작업 7. 미션과 인증 안내 화면

사용자가 “미션과 인증”을 선택하면 미션 참여 방법을 안내한다.

권장 문구:

미션은 가능한 범위에서 참여하는 선택형 활동이에요.

기본 참여 방법:

1. `/미션`으로 참여 가능한 미션을 확인해요.
2. 글로 남길 수 있는 활동은 미션 선택 후 제출할 수 있어요.
3. 사진이나 영상 인증은 미션 인증 채널에 올려 주세요.
4. 운영진이 확인하면 여정 포인트가 지급돼요.

반응 승인 안내:

미션 인증 채널에 올린 글/사진/영상은 운영진이 확인해요.  
운영진이 ✅로 확인하면 여정 포인트가 지급됩니다.  
지급 대상이 아니면 ❌로 확인될 수 있어요.

기존 `/인증` 명령어는 직접 제출이 필요할 때 사용할 수 있다고 안내한다.

## 작업 8. 문의하기 안내 화면

사용자가 “문의하기”를 선택하면 문의 방법을 안내한다.

권장 문구:

궁금한 점은 편하게 남겨 주세요.

가벼운 질문은 `/질문`으로 물어볼 수 있어요.  
운영진 확인이 필요한 내용은 운영진 문의 채널을 이용해 주세요.

예시:

- 프로그램 일정이 궁금해요.
- 포인트가 지급되지 않은 것 같아요.
- 교환 신청을 확인하고 싶어요.
- 미션 인증 방법이 헷갈려요.

주의:

- 민감한 개인정보는 공개 채널에 자세히 남기지 않도록 안내한다.
- 위기 표현, 자해/자살 표현 등은 운영진이 확인할 수 있다는 기존 안전 안내 방향과 충돌하지 않게 한다.

## 작업 9. 안내 허브에서 기존 기능 재사용

가능하다면 안내 허브의 일부 선택지가 기존 기능 화면을 재사용하게 한다.

예:

- 포인트 안내 화면에서 현재 포인트 조회 helper 재사용
- 상점 안내 화면에서 /상점 렌더 helper로 이어질 수 있게 구조화
- 미션 안내 화면에서 /미션 렌더 helper로 이어질 수 있게 구조화

단, 구현이 과도하게 커지면 이번 작업에서는 안내 화면만 제공하고, 실제 기능 실행은 기존 slash command로 안내한다.

우선순위:

1. /안내 허브가 명확하게 보이는 것
2. 참여자가 다음 행동을 알 수 있는 것
3. 기존 기능을 깨지 않는 것
4. 과도한 내부 구조 변경을 피하는 것

## 작업 10. 기존 /안내 문구 정리

기존 /안내 응답에 너무 많은 설명이 있다면 허브 구조로 줄인다.

원칙:

- 첫 화면은 짧게
- 자세한 내용은 선택 후 표시
- 명령어 목록을 한꺼번에 길게 나열하지 않는다
- 참여자에게 필요한 최소 행동만 안내한다

## 작업 12. 테스트 보강

scripts/test-participant-ux-flow.js를 보강한다.

테스트 항목:

- 안내 허브 embed 생성 테스트
- 안내 허브 select menu 생성 테스트
- start/today/points/shop/mission/question 선택값 처리 테스트
- 각 안내 화면 문구가 비어 있지 않은지 테스트
- 안내 허브 customId가 기존 customId와 충돌하지 않는지 테스트
- 기존 /상점, /미션, /교환, /인증 helper가 깨지지 않는지 확인 가능하면 포함

성공 시 기존 출력 또는 아래 출력 포함:
