# Codex 작업 지시서

## 작업 이름

참여자 안내 허브 v2 및 온보딩 안내 정리

## 목표

프로젝트 리디파인 디스코드 봇의 참여자 안내 구조를 더 짧고 자연스럽게 다듬는다.

현재 `/안내` 명령어는 참여자 안내 허브로 동작하고 있으며, 드롭다운을 통해 처음 안내, 오늘 할 일, 포인트, 상점과 교환, 미션과 인증, 문의하기 안내를 볼 수 있다. 또한 미션 인증 채널에 참여자가 글/사진/영상을 올리고 운영자가 ✅ 반응을 누르면 포인트가 지급되며, 참여자에게 DM이 전송되는 구조도 정상 작동한다.

이번 작업에서는 기능을 크게 늘리기보다, 실제 참여자가 처음 들어왔을 때 덜 헷갈리도록 `/안내` 허브 문구와 온보딩 안내 문서를 정리한다.

핵심 목표:

1. `/안내` 첫 화면 문구를 더 짧고 명확하게 정리한다.
2. 드롭다운 항목 이름을 더 직관적으로 수정한다.
3. 미션 인증 방식 안내를 “채널 업로드 + 운영자 확인” 중심으로 재정리한다.
4. `/인증` 명령어는 기본 기능이 아니라 보조 수단으로 낮춰 안내한다.
5. `#처음-안내` 또는 `#이용방법` 채널에 고정할 수 있는 공지문을 작성한다.
6. 참여자용 “처음 오면 이것만 보면 됨” 안내문을 문서로 정리한다.

이번 작업에서는 새 Slash Command, Google Sheets 연동, PostgreSQL 연동, 웹 관리자 페이지, 관리자 페이지는 구현하지 않는다.

## 현재 전제

현재 참여자 주요 흐름:

- `/안내`로 전체 사용법 확인
- `/포인트`로 내 리디파인 포인트 확인
- `/상점` 또는 `/교환`으로 교환 항목 확인
- `/미션`으로 참여 가능한 미션 확인
- 미션 인증 채널에 글/사진/영상 업로드
- 운영자가 ✅ 반응 시 포인트 자동 지급
- 참여자는 DM 또는 `/포인트`로 지급 확인
- `/인증`은 직접 제출이 필요할 때 사용하는 보조 수단

현재 참여자 명령어:

- /질문
- /리디
- /포인트
- /상점

- /미션
- /인증

현재 운영자 명령어:

- /포인트로그

## 중요 방향

### 참여자에게 많이 설명하지 않는다

참여자에게 모든 명령어를 한 번에 설명하지 않는다.

우선적으로 기억하게 할 것은 다음 정도다.

- `/안내`
- `/포인트`
- `/상점`
- `/미션`
- `/체크인`

`/교환`과 `/인증`은 사용할 수 있지만, 처음 안내에서는 보조 수단으로 설명한다.

### 미션 인증은 채널 업로드 중심으로 안내한다

기본 인증 방식은 아래처럼 안내한다.

1. `/미션`으로 오늘 참여 가능한 미션을 확인한다.
2. 미션 인증 채널에 글/사진/영상을 올린다.
3. 운영자가 확인 후 ✅ 반응을 누른다.
4. 리디파인 포인트가 지급된다.
5. DM 또는 `/포인트`로 확인한다.

`/인증` 명령어는 “직접 제출이 필요한 경우 사용할 수 있는 보조 방식”으로 안내한다.

### /안내 첫 화면은 짧게

현재 `/안내` 첫 화면이 너무 길어지지 않게 한다.

권장 구조:

제목:
처음 오셨다면 여기서 시작해요

설명:
리디파인 봇은 미션, 포인트, 상점 이용을 도와주는 안내 봇이에요.  
아래 메뉴에서 궁금한 내용을 골라 확인해 주세요.

하단:
처음에는 `/안내`, `/포인트`, `/미션`, `/상점`, `/체크인` 정도만 기억해도 충분해요.

### 드롭다운 이름은 직관적으로

현재 드롭다운 항목이 너무 딱딱하다면 아래처럼 정리한다.

추천 항목:

- 처음 왔어요
- 오늘 뭐 하면 되나요?
- 내 포인트
- 상점/교환
- 미션/인증
- 문의하기

value는 기존 구조를 유지해도 된다.

예:

- start
- today
- points
- shop
- mission
- question

## 중요 주의사항

- 새 Slash Command는 추가하지 않는다.
- 기존 Slash Command 이름은 변경하지 않는다.
- 기존 `/안내` 허브 구조를 유지하되 문구와 안내 흐름을 개선한다.
- `.env` 파일은 수정하지 않는다.
- 실제 토큰, 실제 채널 ID, 실제 개인정보는 작성하지 않는다.
- `data/*.local.json`은 커밋하지 않는다.
- package.json, package-lock.json은 수정하지 않는다.
- Railway, GitHub 설정은 변경하지 않는다.
- Google Sheets 연동은 구현하지 않는다.
- PostgreSQL 연동은 구현하지 않는다.
- 웹 관리자 페이지는 구현하지 않는다.
- npm run deploy는 실행하지 않는다.
- git commit, git push는 하지 않는다.
- 기존 `/포인트`, `/상점`, `/교환`, `/체크인`, `/미션`, `/인증`, 반응 승인 기능을 깨지 않는다.

`/안내` 실행 시 나오는 첫 화면을 더 짧고 명확하게 다듬는다.

권장 문구:

제목:
처음 오셨다면 여기서 시작해요

본문:
리디파인 봇은 미션, 포인트, 상점 이용을 도와주는 안내 봇이에요.  
아래 메뉴에서 궁금한 내용을 골라 확인해 주세요.

주의:

안내 허브 드롭다운 항목명을 더 자연스럽게 수정한다.

추천 label:

- 오늘 뭐 하면 되나요?
- 내 포인트
- 상점/교환

오늘 참여할 수 있는 흐름 보기

내 포인트:
리디파인 포인트 확인 방법

상점/교환:
포인트 사용과 교환 신청 안내

미션/인증:

- customId 충돌을 만들지 않는다.

## 작업 3. 미션/인증 안내를 채널 업로드 중심으로 수정

`미션/인증` 선택 시 나오는 안내를 아래 방향으로 수정한다.

권장 문구:

미션은 가능한 범위에서 참여하는 선택형 활동이에요.

기본 참여 방법:

1. `/미션`으로 참여 가능한 미션을 확인해요.
2. 미션 인증 채널에 글, 사진, 영상을 올려요.
3. 운영진이 확인하면 ✅ 반응으로 승인해요.
4. 승인되면 리디파인 포인트가 지급돼요.
5. 지급 여부는 DM 또는 `/포인트`에서 확인할 수 있어요.

보조 방법:

직접 제출이 필요한 경우에는 `/인증` 명령어를 사용할 수 있어요.

주의:

- `/인증`을 기본 방식처럼 강조하지 않는다.
- “미션 ID”, “제출 ID”, “pending” 같은 표현은 참여자 화면에서 사용하지 않는다.
- 채널 업로드와 운영자 확인 방식을 가장 먼저 안내한다.

## 작업 4. 오늘 할 일 안내 다듬기

`오늘 뭐 하면 되나요?` 선택 시 나오는 안내를 실제 참여 흐름 중심으로 다듬는다.

권장 문구:

오늘은 이렇게 시작해도 좋아요.

1. `/체크인`으로 오늘의 상태를 가볍게 남겨요.
2. `/미션`에서 참여 가능한 미션을 확인해요.
3. 인증이 필요한 활동은 미션 인증 채널에 올려요.
4. 운영진 확인 후 포인트가 지급돼요.
5. `/포인트`로 내 포인트를 확인해요.

주의:

- 과제처럼 느껴지지 않게 작성한다.
- “가능한 범위에서”, “가볍게”, “선택형 활동” 같은 톤을 유지한다.

## 작업 5. 포인트 안내 다듬기

`내 포인트` 선택 시 나오는 안내를 다듬는다.

권장 문구:

리디파인 포인트는 참여를 기록하기 위한 작은 보상이에요.

경쟁이나 순위를 위한 점수가 아니며, 체크인·미션·프로그램 참여를 통해 받을 수 있어요.

확인 방법:

- `/포인트`로 내 포인트 확인
- `/상점`으로 교환 가능한 항목 확인

주의:

- “비교나 경쟁”이 아니라는 방향 유지
- 청년동 포인트 전환은 운영 정책에 따라 달라질 수 있다는 점은 너무 길게 설명하지 않는다.

## 작업 6. 상점/교환 안내 다듬기

`상점/교환` 선택 시 나오는 안내를 다듬는다.

권장 문구:

상점에서는 리디파인 포인트로 교환 가능한 항목을 볼 수 있어요.

사용 방법:

1. `/상점` 또는 `/교환`을 입력해요.
2. 원하는 항목을 선택해요.
3. 신청 전 내용을 한 번 더 확인해요.
4. 신청이 완료되면 운영진이 순차적으로 확인해요.

안내:

- 선택만으로는 포인트가 차감되지 않아요.
- 교환 신청을 완료하면 포인트가 차감돼요.
- 단순 변심에 따른 취소나 환불은 어려울 수 있어요.

주의:

- 안내가 너무 길어지지 않게 한다.
- 교환 정책은 운영 문서에 더 자세히 남긴다.

## 작업 7. 문의하기 안내 다듬기

`문의하기` 선택 시 나오는 안내를 다듬는다.

권장 문구:

궁금한 점은 편하게 남겨 주세요.

가벼운 질문은 `/질문`으로 물어볼 수 있어요.  
운영진 확인이 필요한 내용은 운영진 문의 채널을 이용해 주세요.

예시:

- 프로그램 일정이 궁금해요.
- 포인트가 지급되지 않은 것 같아요.
- 교환 신청을 확인하고 싶어요.
- 미션 인증 방법이 헷갈려요.

주의:

- 민감한 개인정보는 공개 채널에 자세히 남기지 않도록 안내한다.
- 위기 표현, 자해/자살 표현 등은 운영진이 확인할 수 있다는 기존 안전 안내 방향과 충돌하지 않게 한다.

## 작업 8. #처음-안내 채널 고정 공지문 작성

새 문서 `docs/participant-onboarding-notice.md`를 생성한다.

목적:

운영자가 `#처음-안내`, `#이용방법`, `#리디파인-가이드` 같은 채널에 복사해서 고정할 수 있는 공지문을 제공한다.

공지문 형식:

- Discord에 그대로 붙여넣기 좋은 형태
- 너무 길지 않게
- 참여자가 처음 해야 할 것 중심

권장 초안:

# 처음 오셨다면 여기부터 확인해 주세요

안녕하세요. 프로젝트 리디파인에 오신 것을 환영합니다.

처음에는 모든 채널을 다 살펴보지 않아도 괜찮아요.  
아래 순서로 천천히 확인해 주세요.

1. `/안내`를 입력해 전체 사용법을 확인해 주세요.
2. `/체크인`으로 오늘의 상태를 가볍게 남길 수 있어요.
3. `/미션`에서 참여 가능한 활동을 확인할 수 있어요.
4. 미션 인증은 미션 인증 채널에 글, 사진, 영상을 올리면 됩니다.
5. 운영진이 확인하면 리디파인 포인트가 지급됩니다.
6. `/포인트`로 내 포인트를 확인할 수 있어요.
7. `/상점`에서 교환 가능한 항목을 볼 수 있어요.

리디파인은 완벽하게 참여해야 하는 공간이 아닙니다.  
가능한 만큼, 편한 속도로 함께해 주세요.

주의:

- 실제 채널명은 placeholder로 둔다.
- 특정 채널 ID를 쓰지 않는다.
- 운영자가 쉽게 수정할 수 있게 작성한다.

권장 구성:

1. 이 공간은 무엇인가요?
2. 처음에는 무엇을 하면 되나요?
3. 미션은 어떻게 참여하나요?
4. 포인트는 어떻게 확인하나요?
5. 상점은 어떻게 이용하나요?
6. 궁금한 점은 어디에 물어보나요?
7. 꼭 기억할 것

톤:

- 부드럽게
- 참여자 친화적으로
- 지시보다 안내 중심으로
- 과제나 경쟁처럼 느껴지지 않게

## 작업 10. README 보강

README.md에 아래 내용을 짧게 보강한다.

- `/안내`가 참여자용 메인 허브라는 점
- 참여자는 `/안내`에서 주요 사용법을 확인할 수 있다는 점
- 미션 인증은 채널 업로드 + 운영자 반응 승인 방식이 기본이라는 점
- `/인증` 명령어는 보조 제출 방식이라는 점
- `docs/participant-onboarding-notice.md`, `docs/first-time-participant-guide.md` 문서 링크 추가

- `#처음-안내` 채널에 `docs/participant-onboarding-notice.md` 내용을 고정 공지로 활용할 수 있다.
