# Codex 작업 지시서

## 작업 이름

운영자 미션 인증 검토 버튼 v1

## 목표

현재 리디파인 디스코드 봇은 미션 인증 제출이 들어오면 운영자 채널에 검토 알림이 오지만, 운영자가 제출 ID를 복사해서 `/인증관리 제출id:... 처리:승인` 또는 `/인증관리 제출id:... 처리:반려`를 직접 입력해야 한다.

이 방식은 실제 운영에서 너무 번거롭다.

이번 작업의 목표는 **미션 인증 검토 알림 카드에 [승인하고 포인트 지급] / [반려하기] 버튼을 추가해서, 운영자가 버튼만 눌러 처리할 수 있게 만드는 것**이다.

## 현재 전제

- 현재 main 브랜치의 최신 코드를 기준으로 작업한다.
- 기존 Slash Command 구조는 유지한다.
- 새 Slash Command는 추가하지 않는다.
- `/인증관리` 명령어는 fallback 용도로 유지한다.
- 기존 미션 인증 제출 흐름은 유지한다.
- 기존 사진/영상 인증 반응 처리 흐름도 유지한다.
- data/*.local.json 파일은 수정하거나 커밋하지 않는다.
- 비밀키, 토큰, 채널 ID 실제값은 코드에 넣지 않는다.

## 핵심 요구사항

### 1. 미션 인증 검토 알림 카드에 버튼 추가

`sendMissionSubmissionReviewAlert` 또는 관련 알림 생성 흐름을 수정해서, 운영자 채널에 오는 “미션 인증 검토 요청” 메시지에 아래 버튼을 붙인다.

- 승인하고 포인트 지급
- 반려하기

버튼 customId 예시:

- `operator_submission_approve:<submissionId>`
- `operator_submission_reject:<submissionId>`

버튼 label은 운영자가 바로 이해할 수 있게 한국어로 작성한다.

예시:

- `승인하고 포인트 지급`
- `반려하기`

### 2. 버튼 클릭 처리 추가

`interactionCreate` 핸들러에서 위 customId를 감지해 처리한다.

처리 조건:

- 운영자 권한이 있는 사람만 누를 수 있어야 한다.
- 기존 `isOperator` 또는 동일한 권한 판별 로직을 사용한다.
- 권한이 없으면 ephemeral 응답으로 “운영진만 처리할 수 있어요.” 정도로 안내한다.

승인 처리:

- `pointsRepository.approveSubmissionById(submissionId, reviewer, note)` 또는 기존 repository 메서드를 사용한다.
- 승인되면 해당 참여자에게 포인트가 지급되어야 한다.
- 원본 검토 알림 메시지는 처리 완료 상태가 보이도록 수정한다.
- 버튼은 비활성화하거나 제거한다.
- 운영자에게는 ephemeral로 “승인 완료 / 지급 포인트 / 참여자”를 알려준다.
- 참여자에게 DM 알림을 보내는 기존 방식이 있다면 재사용한다. 없다면 최소한 조용히 실패해도 전체 흐름이 깨지지 않게 처리한다.

반려 처리:

- `pointsRepository.rejectSubmissionById(submissionId, reviewer, note)` 또는 기존 repository 메서드를 사용한다.
- 포인트는 지급하지 않는다.
- 원본 검토 알림 메시지는 반려 완료 상태가 보이도록 수정한다.
- 버튼은 비활성화하거나 제거한다.
- 운영자에게는 ephemeral로 “반려 완료”를 알려준다.
- 참여자 DM 알림은 가능하면 보내되, 실패해도 전체 흐름이 깨지지 않게 처리한다.

중복 처리:

- 이미 승인/반려된 제출을 다시 버튼으로 처리하려고 하면 에러가 나지 않게 한다.
- “이미 처리된 인증 제출이에요.”라고 ephemeral 안내한다.
- 원본 메시지 버튼은 비활성화하거나 상태를 갱신한다.

### 3. 검토 알림 문구 정리

현재 검토 알림에 `/인증관리 제출id:...` 안내가 길게 들어가 있다면, 버튼 방식이 우선임을 안내한다.

권장 문구:

```txt
아래 버튼으로 바로 처리할 수 있어요.
문제가 있으면 /인증관리 명령어로 직접 처리할 수 있어요.
