# Codex 작업 지시서

## 작업 이름

참여자 UX 단순화 v4

## 목표

프로젝트 리디파인 디스코드 봇의 참여자 화면을 더 단순하고 직관적으로 다듬는다.

현재 v3 작업으로 `/상점`, `/미션`, `/인증` 흐름은 좋아졌지만, 실제 테스트 결과 참여자 화면에 여전히 S001, M001 같은 코드와 운영 안내성 문구가 눈에 띄고, 글이 조금 많아 보인다.

이번 작업의 핵심은 아래와 같다.

* 참여자 화면에서는 코드보다 상품명, 미션명, 다음 행동이 먼저 보이게 한다.
* `/상점` 본문에서 S001 같은 신청 코드를 최대한 숨긴다.
* `/미션` 본문에서 M001 같은 미션 코드를 최대한 숨긴다.
* 신청 코드는 직접 입력이 필요한 경우에만 보조 정보로 작게 안내한다.
* `/상점` 항목 설명을 더 짧게 만든다.
* 포인트 부족 화면에서 참여자가 다음에 무엇을 하면 되는지 알려준다.
* `/미션`이 없을 때 문구를 더 부드럽게 바꾼다.
* `/인증` 첨부파일 안내를 더 짧고 자연스럽게 만든다.
* 참여자 화면과 운영자 화면의 정보량을 분리한다.
* 운영자 화면에서는 ID와 코드가 필요하지만, 참여자 화면에서는 가능하면 숨긴다.

이번 작업에서는 웹 관리자 페이지, Google Sheets 연동, PostgreSQL 연동, MEE6 연동은 구현하지 않는다.

## 중요 UX 원칙

### 1. 참여자 화면에서는 코드가 먼저 보이면 안 된다

참여자가 봐야 하는 우선순위는 아래와 같다.

1. 상품명 또는 미션명
2. 필요한 포인트 또는 받을 포인트
3. 내가 할 수 있는 행동
4. 보조 정보로 신청 코드 또는 미션 코드

따라서 `/상점` 본문에서는 아래처럼 보이지 않게 한다.

* S001 · 청년동 포인트 전환권 100P
* M001 · QA 테스트 미션

권장 표시:

🟢 청년동 포인트 전환권 100P
100P로 청년동 포인트 전환을 신청할 수 있어요.

🌱 오늘의 짧은 회고
가볍게 글로 남기면 20P를 받을 수 있어요.

S001, M001 같은 코드는 드롭다운 label이나 상세 하단에만 보조 정보로 표시한다.

### 2. 운영자 화면에서는 ID와 코드가 보여도 된다

운영자는 처리와 확인을 위해 ID가 필요할 수 있다.

따라서 아래 명령어에서는 기존처럼 ID와 코드가 보여도 된다.

* /운영현황
* /교환관리
* /인증관리
* /포인트로그
* /미션관리
* /상점관리
* /운영내보내기

이번 작업은 참여자 화면 중심이다.

### 3. 상점은 짧게, 상세는 선택 후

/상점 본문은 “목록” 역할만 한다.

상세 설명은 상품 선택 후 확인 화면에서 보여준다.

참여자용 /상점 본문 권장 구조:

제목:
리디파인 포인트 상점

설명:
교환 가능한 항목을 골라볼 수 있어요.
선택만으로는 포인트가 차감되지 않습니다.

항목 예시:

🟢 청년동 포인트 전환권 100P
100P로 청년동 포인트 전환을 신청할 수 있어요.

🎁 프로그램 굿즈
수량은 운영진 안내에 따라 달라질 수 있어요.

하단:
아래 선택 메뉴에서 원하는 항목을 골라주세요.

### 4. 포인트 부족 화면은 막다른 길처럼 보이면 안 된다

포인트가 부족할 때는 단순히 신청 불가라고만 하지 않는다.

권장 문구:

아직 포인트가 조금 부족해요.

현재 포인트: 0P
필요 포인트: 100P

체크인이나 미션 참여 후 다시 신청할 수 있어요.

가능하면 하단에 안내를 추가한다.

* `/체크인`으로 오늘의 기록 남기기
* `/미션`에서 참여 가능한 활동 확인하기
* `/포인트`로 내 포인트 다시 확인하기

버튼으로 이동 안내를 제공할 수 있으면 좋지만, Discord에서 Slash Command를 직접 실행할 수는 없으므로 버튼은 “안내 보기” 수준으로만 구현한다.

### 5. 미션 없음 화면은 부드러워야 한다

현재 active 미션이 없을 때 문구가 시스템적으로 보일 수 있다.

권장 문구:

지금 바로 참여할 수 있는 미션은 없어요.

운영진이 새 미션을 열면 이곳에서 확인할 수 있어요.
오늘은 `/체크인`으로 가볍게 기록을 남겨도 괜찮아요.

### 6. 첨부파일 인증 안내는 짧게 한다

/인증 첨부파일 옵션은 유지한다.

단, 참여자 안내는 짧게 한다.

권장 문구:

글로 남기는 미션은 `/미션`에서 선택해 제출할 수 있어요.
사진이나 영상이 필요한 경우에는 `/인증`에서 첨부파일을 함께 올려 주세요.

## 중요 주의사항

* 새 Slash Command는 추가하지 않는다.
* 기존 Slash Command 이름은 변경하지 않는다.
* `/인증` 첨부파일 옵션은 유지한다.
* `.env` 파일은 수정하지 않는다.
* 실제 토큰, 실제 채널 ID, 실제 개인정보는 작성하지 않는다.
* `data/*.local.json`은 커밋하지 않는다.
* package.json, package-lock.json은 수정하지 않는다.
* Railway, GitHub 설정은 변경하지 않는다.
* Google Sheets 연동은 구현하지 않는다.
* PostgreSQL 연동은 구현하지 않는다.
* 웹 관리자 페이지는 구현하지 않는다.
* npm run deploy는 실행하지 않는다.
* git commit, git push는 하지 않는다.

## 작업 1. /상점 본문에서 S001 노출 줄이기

참여자용 `/상점` 본문에서 S001, S002 같은 코드를 크게 보여주지 않는다.

기존 예시:

S001 · 청년동 포인트 전환권 100P
필요 포인트: 100P

변경 권장:

🟢 청년동 포인트 전환권 100P
100P로 청년동 포인트 전환을 신청할 수 있어요.

주의:

* 드롭다운 label에는 S001을 유지해도 된다.
* 직접 입력용 신청 코드는 상세 확인 화면 하단에만 작게 표시한다.
* 본문에는 내부 item.id를 표시하지 않는다.
* “항목 ID”라는 표현은 참여자 화면에서 사용하지 않는다.
* “신청 코드”라는 표현만 사용한다.

## 작업 2. /상점 항목 설명 더 줄이기

/상점 본문에 들어가는 상품 설명은 최대 1문장으로 줄인다.

권장 길이:

* 1줄
* 40자 안팎
* 운영 정책 설명은 생략

예시:

좋음:
100P로 청년동 포인트 전환을 신청할 수 있어요.

나쁨:
청년동 내부에서 정한 사용처를 위한 포인트 지급을 운영진에게 신청하는 예시 항목입니다. 현금 환급 또는 외부 교환 대상이 아닙니다.

자세한 정책 설명은 선택 후 상세 확인 화면 또는 문서에 둔다.

## 작업 3. 교환 신청 확인 화면에서 코드 보조화

교환 신청 전 확인 화면에서도 상품명과 포인트 정보가 먼저 보여야 한다.

권장 구조:

교환 신청 전 확인해 주세요

🟢 청년동 포인트 전환권 100P

필요 포인트: 100P
현재 포인트: 500P
신청 후 포인트: 400P

신청하면 포인트가 차감돼요.
단순 변심에 따른 취소나 환불은 원칙적으로 어렵습니다.

직접 입력용 신청 코드: S001

주의:

* 직접 입력용 신청 코드는 하단에 작게 둔다.
* 내부 item.id는 참여자 화면에 노출하지 않는다.
* 설명이 너무 길면 한두 문장으로 자른다.

## 작업 4. 포인트 부족 화면 개선

포인트가 부족하거나 포인트 기록이 없을 때 문구를 개선한다.

권장 문구:

아직 포인트가 조금 부족해요.

현재 포인트: 0P
필요 포인트: 100P

체크인이나 미션 참여 후 다시 신청할 수 있어요.

하단 안내:

* `/체크인`으로 오늘의 기록 남기기
* `/미션`에서 참여 가능한 활동 확인하기
* `/포인트`로 내 포인트 다시 확인하기

주의:

* “접수할 수 없습니다”, “실패”, “오류” 같은 표현을 줄인다.
* 참여자가 다음 행동을 알 수 있게 한다.
* 포인트가 부족할 때 교환 신청은 생성하지 않는다.
* 포인트는 차감하지 않는다.

## 작업 5. 신청하지 않기 2단계 확인 유지 및 문구 보강

v3에서 신청하지 않기 2단계 확인이 들어갔다면 유지한다.

문구가 아직 딱딱하다면 아래처럼 다듬는다.

1차 버튼:

* 교환 신청하기
* 신청하지 않기

신청하지 않기 클릭 후:

교환 신청을 종료할까요?
아직 포인트는 차감되지 않았어요.

버튼:

* 네, 종료할게요
* 다시 확인할게요

최종 종료 시:

교환 신청을 진행하지 않았어요.
포인트는 차감되지 않았습니다.

주의:

* 접수된 교환 신청의 취소 기능처럼 보이지 않게 한다.
* 참여자용 환불/취소 기능을 만들지 않는다.

## 작업 6. /미션 본문에서 M001 노출 줄이기

참여자용 `/미션` 본문에서 M001, M002 같은 코드를 크게 보여주지 않는다.

기존 예시:

M001 · QA 테스트 미션
지급 포인트: 20P

변경 권장:

🌱 QA 테스트 미션
글로 남기면 20P를 받을 수 있어요.

주의:

* 드롭다운 label에는 M001을 유지해도 된다.
* 직접 입력용 미션 코드는 상세 안내나 하단에만 작게 표시한다.
* 본문에는 내부 mission.id를 표시하지 않는다.
* “미션 ID”라는 표현은 참여자 화면에서 사용하지 않는다.
* “미션 코드”라는 표현만 사용한다.

## 작업 7. /미션 없음 화면 개선

active 미션이 없을 때 문구를 개선한다.

권장 문구:

지금 바로 참여할 수 있는 미션은 없어요.

운영진이 새 미션을 열면 이곳에서 확인할 수 있어요.
오늘은 `/체크인`으로 가볍게 기록을 남겨도 괜찮아요.

* “강제 과제”가 아니라 “선택형 활동”이라는 방향을 유지한다.

## 작업 8. /미션 선택 후 모달 문구 유지 또는 보강

모달 문구는 짧고 부드럽게 유지한다.

권장:

title:
미션 인증하기

input label:
인증 내용

placeholder:
수행 내용을 필요한 만큼만 적어 주세요.

가능하면 미션명은 모달 제목 또는 설명에서 짧게 보여준다.

주의:

* 모달에는 첨부파일을 받을 수 없다.
* 사진/영상은 /인증 명령어의 첨부파일 옵션으로 안내한다.

## 작업 9. /인증 첨부파일 안내 단순화

/인증 명령어 안내 문구를 단순하게 유지한다.

권장 문구:

글로 남기는 미션은 `/미션`에서 선택해 제출할 수 있어요.
사진이나 영상이 필요한 경우에는 `/인증`에서 첨부파일을 함께 올려 주세요.

주의:

* 첨부파일 옵션은 유지한다.
* 첨부파일 metadata 저장 동작은 유지한다.
* 운영자 알림에 첨부파일 정보가 포함되는 기존 동작은 유지한다.

## 작업 10. 참여자 화면과 운영자 화면 분리

참여자 화면에서는 아래 표현을 최대한 줄인다.

* 내부 ID
* 로그
* 상태값
* pending
* active
* repository
* local JSON
* 운영 데이터 저장 방식
* 예시 항목
* 테스트 항목

운영자 화면에서는 필요한 경우 유지한다.

주의:

* `/운영현황`, `/포인트로그`, `/미션관리`, `/상점관리`는 운영자용이므로 ID와 상태값을 유지해도 된다.
* `/상점`, `/미션`, `/교환`, `/인증`, `/포인트`, `/체크인`은 참여자용이므로 문구를 최대한 부드럽게 유지한다.

## 작업 11. 문서 보강

### docs/participant-command-guide.md

보강 내용:

* 참여자는 신청 코드나 미션 코드를 외울 필요가 없다는 점
* `/상점`에서 상품을 고른 뒤 확인하고 신청한다는 점
* 신청하지 않기를 눌러도 포인트가 차감되지 않는다는 점
* `/미션`에서 글 인증은 선택 메뉴와 모달로 할 수 있다는 점
* 사진/영상 인증은 `/인증` 첨부파일을 사용한다는 점

### docs/prelaunch-qa-checklist.md

보강 내용:

* `/상점` 본문에 S001이 크게 노출되지 않는지
* `/미션` 본문에 M001이 크게 노출되지 않는지
* 상품명과 미션명이 먼저 보이는지
* 포인트 부족 화면에서 다음 행동이 안내되는지
* active 미션이 없을 때 문구가 부드러운지
* `/인증` 첨부파일 안내가 자연스러운지

### docs/operation-guide.md

보강 내용:

* 운영자는 상점/미션 제목을 짧고 명확하게 작성한다.
* 참여자 화면에는 코드보다 이름과 행동이 먼저 보이도록 관리한다.
* 사진/영상 인증이 필요한 미션은 운영 전 안내한다.

### README.md

보강 내용:

* 참여자는 `/상점`과 `/미션`에서 항목을 선택해 진행할 수 있으며, 코드를 외울 필요가 없다는 점
* 사진/영상 인증은 `/인증` 첨부파일로 가능하다는 점
