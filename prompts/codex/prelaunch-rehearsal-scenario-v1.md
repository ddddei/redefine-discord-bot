# Codex 작업 지시서

## 작업 이름

운영 전 QA 리허설 시나리오 v1

## 목표

프로젝트 리디파인 디스코드 봇의 실제 운영 전 QA 리허설 문서를 작성한다.

현재 봇은 참여자 안내, 미션, 체크인, 미션 인증 채널 반응 승인, 리디파인 포인트, 상점/교환, 운영자 관리, 운영 데이터 내보내기, 읽기 전용 관리자 웹 대시보드(`/admin`)까지 MVP 구현이 완료된 상태다.

다음 단계에서는 실제 참여자를 받기 전에 운영자와 테스트 참여자 계정으로 전체 흐름을 한 번 끝까지 점검해야 한다.

이번 작업에서는 실제 운영 전 리허설을 위한 문서와 체크리스트를 작성한다.

## 핵심 목표

- 운영 전 QA 리허설 시나리오 문서를 만든다.
- 테스트 계정, 운영자 계정, 채널, 환경변수 확인 항목을 정리한다.
- 운영용 기본 미션/상점 등록 순서를 정리한다.
- 참여자 입장에서 `/안내 → /미션 → 인증 업로드 → 포인트 확인 → /상점 → /교환` 흐름을 점검한다.
- 운영자 입장에서 `✅ 반응 승인 → /운영현황 → /교환관리 → /포인트로그 → /admin → /운영내보내기` 흐름을 점검한다.
- 실패했을 때 확인할 항목을 정리한다.
- 실제 운영 시작 전 최종 체크리스트를 보강한다.

이번 작업은 문서 중심 작업이다. 코드 기능 변경, 새 Slash Command 추가, DB 연동, Google Sheets 연동, 웹 승인/반려 기능은 구현하지 않는다.

## 중요 원칙

### 1. 실제 운영 전 그대로 따라 할 수 있어야 한다

문서는 운영자가 실제로 보면서 순서대로 따라 할 수 있게 작성한다.

문서에는 다음이 포함되어야 한다.

- 리허설 목적
- 준비물
- 계정 준비
- 채널 준비
- Railway 환경변수 확인
- 관리자 대시보드 확인
- 미션/상점 등록
- 참여자 흐름 테스트
- 운영자 흐름 테스트
- 교환 흐름 테스트
- 데이터 내보내기 테스트
- 실패 시 확인할 것
- 최종 운영 가능 판단 기준

### 2. 테스트용 데이터와 실제 운영 데이터를 구분한다

리허설에서 만드는 테스트 데이터는 실제 운영 전 정리해야 한다.

문서에 아래 원칙을 포함한다.

- `data/*.example.json`은 삭제하지 않는다.
- `data/*.local.json`은 커밋하지 않는다.
- 테스트 참여자 데이터가 남아 있으면 실제 운영 전 정리한다.
- 관리자 대시보드에 example 데이터가 보이지 않는지 확인한다.
- 실제 운영용 미션/상점만 active로 둔다.

### 3. 참여자 UX를 기준으로 검토한다

테스트는 운영자 입장이 아니라 참여자 입장에서 먼저 확인한다.

확인할 것:

- `/안내`만 보고 다음 행동을 알 수 있는가
- `/미션`에서 미션명이 자연스럽게 보이는가
- 미션 인증 채널에 글/사진을 올리는 흐름이 어렵지 않은가
- ✅ 승인 후 DM이 자연스럽게 오는가
- `/포인트`에서 포인트가 바로 확인되는가
- `/상점`과 `/교환` 흐름이 이해되는가
- 교환 신청 전 주의 문구가 너무 딱딱하지 않은가

### 4. 운영자 UX도 같이 검토한다

운영자가 실제로 빠르게 확인할 수 있어야 한다.

확인할 것:

- ✅ 반응 승인으로 포인트가 지급되는가
- `/운영현황`에서 상태가 보이는가
- `/포인트로그`에서 지급 기록이 보이는가
- `/admin`에서 요약 카드와 로그가 보이는가
- 교환 신청이 `/교환관리`로 처리되는가
- `/운영내보내기`로 백업 확인이 가능한가

## 작업 8. 실패 시 확인할 것 작성

실패 상황별 확인 항목을 정리한다.

### /안내가 안 뜨는 경우

- 봇이 온라인인지
- Slash Command가 등록되어 있는지
- npm run deploy가 필요한 변경이 있었는지

### 반응 승인으로 포인트가 지급되지 않는 경우

- `MISSION_SUBMISSION_CHANNEL_ID`가 실제 인증 채널 ID와 맞는지
- 운영자에게 권한이 있는지
- `OPERATOR_ROLE_ID` 또는 ManageMessages/Administrator 권한이 있는지
- 참여자 본인이 자기 메시지에 ✅를 누른 것은 아닌지
- 메시지가 봇 또는 자동화 메시지가 아닌지
- Railway 재배포가 완료되었는지

### DM이 오지 않는 경우

- `REACTION_APPROVAL_DM_USER=true`인지
- 참여자가 서버 DM을 차단하지 않았는지
- 포인트 지급 자체는 되었는지

### /admin이 안 열리는 경우

- Railway Public Domain이 생성되었는지
- `ADMIN_DASHBOARD_ENABLED=true`인지
- `ADMIN_DASHBOARD_PASSWORD`가 설정되어 있는지
- `/admin` 경로로 접속했는지
- Basic Auth 비밀번호가 맞는지

### 교환 알림이 안 오는 경우

- `POINT_REDEEM_CHANNEL_ID`가 설정되어 있는지
- 없으면 `LOG_CHANNEL_ID` fallback이 있는지
- 봇이 해당 채널에 메시지를 보낼 수 있는지

### 관리자 대시보드에 데이터가 안 보이는 경우

- example 데이터는 제외되는 것이 정상인지
- 실제 운영용 미션/상점이 active 상태인지
- 테스트 데이터가 local JSON에 저장되었는지
- Railway와 로컬 데이터가 다른 환경인지

## 작업 10. 최종 운영 가능 판단 기준 작성
