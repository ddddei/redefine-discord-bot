# Codex 작업 지시서

## 작업 이름

운영용 기본 미션/상점 데이터 설계 v1

## 목표

프로젝트 리디파인 디스코드 봇의 실제 운영을 준비하기 위해, 운영자가 `/미션관리`, `/상점관리`, `/포인트관리`, `/교환관리`, `/운영현황`, `/admin` 대시보드를 활용할 때 참고할 수 있는 기본 미션/상점/포인트 운영 설계 문서를 작성한다.

현재 관리자 웹 대시보드 MVP는 구현되어 있고, example 데이터는 운영 대시보드에서 제외되도록 정리되었다. 다음 단계에서는 실제 운영 시작 전 등록해야 할 운영용 미션과 상점 항목, 포인트 운영 규칙, 인증/교환 처리 기준을 문서화한다.

이번 작업은 문서 중심 작업이다. 실제 코드 기능 추가, 새 Slash Command 추가, DB 연동, Google Sheets 연동, 웹 승인/반려 기능은 구현하지 않는다.

## 핵심 원칙

### 1. 실제 운영에 바로 참고 가능한 문서로 작성한다

운영자가 문서를 보고 바로 아래 작업을 할 수 있어야 한다.

- 어떤 미션을 등록할지 결정
- 각 미션의 지급 포인트 결정
- 어떤 상점 항목을 등록할지 결정
- 청년동 포인트 전환 항목 구성
- 교환/취소/환불 안내 문구 정리
- 수량 제한 상품 운영 방식 정리
- 미션 인증 채널 운영 방식 정리
- 운영 전 체크리스트 확인

### 2. 코드 구현은 하지 않는다

이번 작업에서 하지 않을 것:

- 새 Slash Command 추가
- 관리자 웹 대시보드 기능 수정
- 웹에서 미션/상점 등록 기능 구현
- 웹 승인/반려 기능 구현
- Google Sheets 연동
- PostgreSQL 연동
- 실제 data/*.local.json 수정
- 실제 운영 데이터 자동 생성

### 3. 운영 문구는 참여자 친화적으로 작성한다

참여자에게 보일 수 있는 문구는 너무 딱딱하지 않게 작성한다.

기준:

- 짧고 이해하기 쉽게
- 신청 전 주의사항은 분명하게
- 환불/취소 불가 안내는 차갑지 않게
- 포인트는 경쟁이나 평가가 아니라 참여 기록이라는 점 강조
- 미션은 강제 과제가 아니라 선택형 활동이라는 점 강조

### 4. 청년동 포인트 전환은 기본 항목으로 포함한다

현재 운영 방향:

- 리디파인 포인트를 청년동 포인트로 전환할 수 있다.
- 청년동 포인트 전환은 기본적으로 한도 없이 가능할 가능성이 높다.
- 다만 30만원 이상 등 비정상적이거나 과도한 신청은 운영자가 별도 확인할 수 있다.
- 밀리의 서재, 왓챠 구독권 등 외부 구독권 상품은 추후 확정되면 수량 제한이 있을 수 있다.

### 5. 교환 취소/환불 안내는 명확히 한다

운영 방향:

- 참여자가 교환 신청 전 내용을 충분히 확인하도록 안내한다.
- 교환 신청 후 단순 변심에 따른 취소/환불 문의는 받지 않는 방향을 기본값으로 둔다.
- 다만 운영 오류, 시스템 오류, 중복 신청, 잘못된 지급 등 예외는 운영자 판단으로 처리할 수 있다.
- 문구는 너무 강압적이지 않게 작성한다.

### 기본 미션 후보

아래 항목을 기반으로 운영용 기본 미션을 설계한다.

#### M001. 첫 인사 남기기

목적:

- 참여자가 서버에 들어와 처음으로 안전하게 말을 걸어볼 수 있게 한다.

권장 포인트:

- 20P

인증 방식:

- 지정 채널에 자기소개 또는 첫 인사 작성
- 운영자 확인 또는 반응 승인

참여자 안내 문구 예시:

```txt
처음 오셨다면 가볍게 인사를 남겨 주세요.
길게 쓰지 않아도 괜찮아요.
지금의 기분, 관심 있는 활동, 기대하는 점 중 하나만 적어도 충분합니다.
```

#### M002. 오늘의 체크인

목적:

- 참여자가 하루 상태를 가볍게 기록한다.

권장 포인트:

- 10P

인증 방식:

- `/체크인`
- 하루 1회 권장

참여자 안내 문구 예시:

```txt
오늘의 상태를 짧게 남겨 주세요.
기분, 컨디션, 오늘 해보고 싶은 것 중 하나만 적어도 괜찮아요.
```

#### M003. 관심 활동 선택하기

목적:

- 참여자가 본인에게 맞는 활동 방향을 고르게 한다.

권장 포인트:

- 20P

인증 방식:

- 지정 채널에 관심 활동 작성
- 또는 추후 선택형 명령/폼으로 확장 가능

관심 활동 예시:

- 대화
- 게임
- 글쓰기
- 산책
- 취미 공유
- 창작
- 진로 탐색
- 가벼운 모임

#### M004. 미션 인증 사진/영상 올리기

목적:

- 참여자가 실제 활동을 기록한다.

권장 포인트:

- 30P

인증 방식:

- 미션 인증 채널에 사진 또는 영상 업로드
- 운영자가 승인 이모지로 확인하면 자동 지급

주의:

- 얼굴, 주소, 연락처 등 민감정보가 포함되지 않도록 안내
- 불편한 인증은 강요하지 않음

#### M005. 프로그램 참여 후기 남기기

목적:

- 참여자가 활동 후 느낀 점을 정리한다.

권장 포인트:

- 50P

인증 방식:

- 후기 채널 또는 지정 채널에 작성
- 운영자 확인 후 지급

참여자 안내 문구 예시:

```txt
참여 후 느낀 점을 짧게 남겨 주세요.
좋았던 점, 아쉬웠던 점, 다음에 해보고 싶은 것 중 하나만 적어도 됩니다.
```

#### M006. 운영진에게 질문 남기기

목적:

- 참여자가 궁금한 점을 안전하게 물어볼 수 있게 한다.

권장 포인트:

- 10P 또는 포인트 없음

주의:

- 포인트를 주면 질문 남발 가능성이 있으므로 운영 판단 필요
- 기본 미션보다는 안내성 활동으로 둘 수 있음

#### M007. 주간 회고 남기기

목적:

- 참여자가 한 주의 변화를 기록한다.

권장 포인트:

- 40P

인증 방식:

- 주 1회
- 지정 채널 작성

#### M008. 함께 응원하기

목적:

- 다른 참여자의 글에 긍정적 반응을 남긴다.

권장 포인트:

- 10P

주의:

- 무의미한 도배 방지 필요
- 운영 초반에는 수동 운영 권장

## 작업 3. 교환/취소/환불 운영 문구 정리

교환 신청 전 안내 문구를 작성한다.

포함할 내용:

- 신청 전 포인트와 상품 내용을 확인해 달라는 안내
- 교환 신청 후 단순 변심으로 인한 취소/환불은 어렵다는 안내
- 운영 오류나 중복 신청은 운영자가 확인 후 조정할 수 있다는 안내
- 상품별 수량 제한이 있을 수 있다는 안내
- 청년동 포인트 전환은 외부 교환 상품이 아니라는 안내

권장 문구 예시:

```txt
교환 신청 전 포인트와 교환 항목을 꼭 확인해 주세요.
신청이 접수된 뒤에는 단순 변심으로 인한 취소나 환불이 어려울 수 있어요.
다만 중복 신청, 시스템 오류, 운영자 확인이 필요한 경우에는 운영진이 확인 후 조정할 수 있습니다.
```

- 운영용 기본 상점 항목을 1개 이상 등록했다.

- `/상점`에서 참여자에게 교환 항목이 자연스럽게 보인다.
- `/교환`에서 신청 전 주의 문구가 확인된다.
- `/admin`에서 활성 미션/상점 수가 정상 표시된다.
- 교환 신청 후 `/admin`의 교환 대기에 표시되는지 확인했다.
- 미션 인증 채널 반응 승인 후 포인트가 지급되는지 확인했다.
- 취소/환불 안내 문구가 너무 딱딱하거나 위협적으로 보이지 않는지 확인했다.
