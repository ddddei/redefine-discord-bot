# Codex 작업 지시서

## 작업 이름

참여자 UX 다듬기 v2

## 목표

프로젝트 리디파인 디스코드 봇의 참여자 UX를 한 번 더 다듬는다.

현재 `/상점`과 `/미션`에는 선택 메뉴, 교환 확인 버튼, 인증 입력 모달, S001/M001 표시 코드가 추가되어 있다. 방향은 좋아졌지만, 실제 테스트 결과 참여자 입장에서는 여전히 읽을 내용이 많고, 일부 문구와 버튼명이 헷갈릴 수 있다.

이번 작업의 목표는 다음과 같다.

* `/상점` 목록의 정보량을 줄인다.
* `/미션` 목록의 정보량을 줄인다.
* “항목 ID”, “미션 ID” 같은 표현을 참여자 화면에서는 줄이고 “신청 코드”, “미션 코드”로 바꾼다.
* 내부 ID는 참여자 화면에서 최대한 숨긴다.
* 교환 신청 전 확인 화면을 더 짧고 명확하게 만든다.
* 취소 버튼 표현을 “취소”가 아니라 “신청하지 않기”처럼 오해가 적게 바꾼다.
* 취소 후에는 “포인트가 차감되지 않았다”는 점을 명확히 안내한다.
* `/인증` 직접 입력 방식에서 사진/영상/이미지 첨부파일 옵션을 지원한다.
* 모달은 텍스트 입력만 가능하다는 점을 고려해, 사진/영상 인증은 `/인증` 명령어의 첨부파일 옵션으로 처리한다.
* 운영자 알림 전송 여부를 로그 또는 운영자 확인용 정보로 더 명확히 남긴다.
* 참여자 문구를 더 부드럽고 덜 시스템스럽게 다듬는다.

이번 작업에서는 웹 관리자 페이지, Google Sheets 연동, PostgreSQL 연동, MEE6 연동은 구현하지 않는다.

## 중요 UX 원칙

### 참여자 화면에서는 내부 ID를 숨긴다

아래와 같은 내부 ID는 참여자에게 어렵다.

* mission_1779947375009_vjcds3
* item_youth_point_100_example
* rd_1779947292182_bsngc0
* submission_1779950613101_9p2fto

참여자 화면에서는 가능하면 아래처럼 보여준다.

* S001 · 청년동 포인트 전환권 100P
* M001 · QA 테스트 미션

내부 ID는 운영자 로그, 운영현황, 운영자 처리 안내에서는 사용할 수 있다.

참여자에게 꼭 보여야 한다면 “신청 코드” 또는 “미션 코드”라고 표현한다.

### /상점은 목록이고, 상세 설명은 선택 후 보여준다

/상점 목록에는 짧은 정보만 보여준다.

권장 표시:

* S001 · 청년동 포인트 전환권 100P

  * 필요 포인트: 100P
  * 사용처: 청년동 내부

* S002 · 프로그램 굿즈

  * 필요 포인트: 300P
  * 수량: 운영진 확인

길고 자세한 설명은 항목을 선택한 뒤 “교환 신청 전 확인” 화면에서 보여준다.

### 취소 버튼은 오해가 없어야 한다

현재 “취소” 버튼은 이미 접수된 교환을 취소하는 것처럼 느껴질 수 있다.

버튼명 변경 권장:

* 기존: 취소
* 변경: 신청하지 않기

취소 후 문구 권장:

교환 신청을 진행하지 않았어요.
포인트는 차감되지 않았습니다.

### 교환 신청 전 확인 화면은 짧게 만든다

필수 정보:

* 선택한 항목
* 필요 포인트
* 현재 보유 포인트
* 신청 후 예상 잔액
* 신청 후 단순 변심 취소/환불은 원칙적으로 어렵다는 안내

불필요하게 긴 설명은 줄인다.

### 사진/영상 인증

Discord 모달은 텍스트 입력만 가능하다.

따라서 `/미션` 선택 메뉴 → 모달 흐름은 텍스트 인증용으로 유지한다.

사진/영상/이미지 인증이 필요한 경우 `/인증` 명령어에 `첨부파일` 옵션을 추가한다.

예시:

* /인증 미션id:M001 내용:인증합니다 첨부파일:이미지

주의:

* 첨부파일은 선택 옵션으로 둔다.
* 첨부파일이 없어도 텍스트 인증은 가능해야 한다.
* 첨부파일 URL 또는 attachment metadata를 submission에 저장한다.
* 첨부파일이 이미지/영상인지 엄격히 검사하지 않아도 되지만, 가능하다면 contentType을 기록한다.
* 운영자 알림에 첨부파일 링크가 보이도록 한다.
* 개인정보가 포함된 사진/영상 업로드 주의 문구를 포함한다.

## 중요 주의사항

* .env 파일은 수정하지 않는다.
* 실제 토큰, API Key, 실제 채널 ID, 실제 참여자 개인정보는 작성하지 않는다.
* package.json, package-lock.json은 수정하지 않는다.
* Railway, GitHub 설정은 변경하지 않는다.
* npm run deploy는 실행하지 않는다.
* git commit, git push는 하지 않는다.
* data/*.local.json은 커밋하지 않는다.
* Google Sheets 연동은 구현하지 않는다.
* PostgreSQL 연동은 구현하지 않는다.
* 웹 관리자 페이지는 구현하지 않는다.
* 기존 Slash Command 이름은 변경하지 않는다.
* 기존 명령어 동작을 깨지 않는다.
* `/인증`에 첨부파일 옵션을 추가하는 경우 src/deploy-commands.js 수정이 필요하며, 작업 후 사용자가 직접 npm run deploy를 실행해야 한다.

## 작업 1. /상점 목록 정보량 축소

/상점 응답의 목록 설명을 줄인다.

현재보다 짧고 읽기 쉬운 형태로 바꾼다.

권장 구조:

제목:
리디파인 포인트 상점

설명:
교환 가능한 항목을 확인하고, 아래 선택 메뉴에서 신청할 항목을 골라주세요.

항목 표시 예시:

필요 포인트: 100P
사용처: 청년동 내부

필요 포인트: 300P
수량: 운영진 확인

하단 안내:
선택만으로는 포인트가 차감되지 않아요.
항목을 선택한 뒤 한 번 더 확인하고 신청할 수 있어요.

주의:

* 참여자용 /상점에서는 내부 item.id를 직접 노출하지 않는다.
* “항목 ID” 대신 “신청 코드”라고 표현한다.
* 너무 긴 설명은 상세 확인 화면으로 넘긴다.
* 선택 메뉴 option description도 짧게 유지한다.

## 작업 2. 교환 신청 전 확인 화면 간소화

상점 항목 선택 후 나오는 확인 화면을 다듬는다.

권장 구조:

제목:
교환 신청 전 확인해 주세요

내용:

신청 항목: S001 · 청년동 포인트 전환권 100P
필요 포인트: 100P
현재 보유 포인트: 500P
신청 후 예상 잔액: 400P

신청이 완료되면 포인트가 차감돼요.
단순 변심에 따른 취소나 환불은 원칙적으로 어렵습니다.

버튼:

* 교환 신청하기
* 신청하지 않기

주의:

* 선택 단계에서는 포인트를 차감하지 않는다.
* “신청하지 않기”를 누르면 포인트 차감 없이 종료한다.
* 포인트 부족 시 “현재 보유 포인트가 조금 부족해요.”처럼 부드럽게 안내한다.

취소 응답 문구:

교환 신청을 진행하지 않았어요.
포인트는 차감되지 않았습니다.

주의:

* 이미 접수된 교환 신청의 취소 기능처럼 보이지 않게 한다.
* 참여자용 취소/환불 기능을 새로 만들지 않는다.

## 작업 10. 운영자 알림 전송 여부 로그 보강

교환 신청 또는 인증 제출 시 운영자 채널 알림이 전송됐는지 확인하기 어렵다.

다음 중 가능한 방식으로 보강한다.

* console.info 또는 console.warn에 알림 전송 성공/실패를 남긴다.
* 운영자 알림 채널 ID가 없으면 명확한 warn을 남긴다.
* 참여자 응답에는 불필요하게 노출하지 않는다.
* 운영자 응답이나 로그에는 “운영자 알림 전송됨 / 채널 미설정으로 생략됨 / 전송 실패” 정도가 남도록 한다.

주의:

* LOG_CHANNEL_ID, POINT_REDEEM_CHANNEL_ID, ACTIVITY_REVIEW_CHANNEL_ID fallback 구조를 유지한다.
* 알림 전송 실패가 참여자 응답 실패로 이어지지 않게 한다.

## 작업 11. 문서 보강

### docs/participant-command-guide.md

보강 내용:

* /상점 목록은 짧게 보고, 선택 후 자세히 확인한다는 점

* /미션 선택 후 글 인증은 모달로 제출한다는 점

### docs/prelaunch-qa-checklist.md

보강 내용:

* 교환 신청 전 확인 화면 확인

* 포인트 차감 없음 확인
* /인증 첨부파일 옵션 테스트

* /인증 미션id:M001 내용:... 첨부파일:... 테스트

### docs/operation-guide.md

보강 내용:

* 운영자는 첨부파일에 개인정보가 포함되어 있을 수 있으므로 외부 공유 주의
* 상점/미션 제목은 선택 메뉴에 표시되므로 짧고 명확하게 작성

### README.md

보강 내용:

* /상점은 목록을 간단히 보고 선택 후 확인하는 방식
* /미션은 선택 후 글 인증 모달로 제출 가능
* 사진/영상 인증은 /인증 첨부파일 옵션으로 가능
