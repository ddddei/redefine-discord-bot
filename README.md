# 프로젝트 리디파인 디스코드 봇

프로젝트 리디파인 참여자 안내, FAQ, 온보딩, 여정 포인트, 상점, 교환, 체크인, 미션, 인증, 운영자 관리 기능을 제공하는 Discord 봇입니다.

MEE6는 환대, 채팅 EXP, 레벨업 보조 용도로만 사용합니다. 리디파인 봇은 실제 운영 안내, 참여 활동 기록, 포인트, 교환, 운영자 처리 흐름을 담당합니다.

## 주요 기능

참여자 기능:

- `/안내` 참여자용 메인 허브에서 처음 안내, 오늘 할 일, 포인트, 상점과 교환, 미션과 인증, 문의 방법 확인
- 채널 안내 확인
- FAQ/지식창고 질문
- 여정 포인트 확인
- 상점 확인
- 교환 신청
- 체크인
- 미션 확인
- 미션 인증 채널 업로드 또는 `/인증` 제출

운영자 기능:

- 공지 템플릿 확인
- 포인트 지급/차감
- 교환 신청 처리
- 포인트 로그 확인
- 인증 제출 승인/반려
- 미션 인증 채널 반응 승인/반려
- 운영 현황 확인
- 미션 관리
- 상점 관리
- 운영 데이터 내보내기

## Slash Command 목록

### 참여자 명령어

| 명령어 | 대상 | 목적 | 공개 범위 또는 비고 |
| --- | --- | --- | --- |
| `/안내` | 참여자 | 처음 온 참여자용 메인 허브 | 본인만 보이는 선택 메뉴로 주요 사용법 확인 |
| `/채널안내` | 참여자 | 주요 채널 용도 확인 | 개인 안내 중심 |
| `/질문` | 참여자 | FAQ와 지식창고에서 답변 검색 | 찾지 못한 질문은 운영 로그로 최소 기록 |
| `/리디` | 참여자 | 도움말, 일정, 규칙, 문의 안내 확인 | 하위 명령어: `도움`, `일정`, `규칙`, `문의` |
| `/포인트` | 참여자 | 본인 여정 포인트 확인 | 본인만 보이는 private 응답 중심 |
| `/상점` | 참여자 | 신청 가능한 리워드 확인 및 선택 | private 응답 중심, 코드를 외우지 않고 선택 메뉴로 진행 |
| `/교환` | 참여자 | 여정 포인트로 리워드 교환 신청 | 코드를 몰라도 선택 메뉴로 진행, 신청 코드 직접 입력 호환 |
| `/체크인` | 참여자 | 당일 체크인 기록과 기본 포인트 적립 | private 응답 중심, 한국 시간 기준 중복 방지 |
| `/미션` | 참여자 | 현재 참여 가능한 미션 확인 및 선택 | private 응답 중심, 코드를 외우지 않고 글 인증 모달로 제출 |
| `/인증` | 참여자 | 미션 수행 내용 제출 | 인증 채널 업로드가 기본이며, 직접 제출이 필요할 때 보조로 사용 |

### 운영자 명령어

운영자 명령어는 `ManageMessages` 또는 `Administrator` 권한이 있는 사용자 기준으로 사용합니다.

| 명령어 | 대상 | 목적 | 공개 범위 또는 비고 |
| --- | --- | --- | --- |
| `/공지` | 운영자 | 복사용 공지 템플릿 확인 | 운영자 전용, 응답은 실행자 중심 |
| `/포인트관리` | 운영자 | 참여자 포인트 지급/차감/정정 | 사유를 운영 로그에 남김 |
| `/교환관리` | 운영자 | 교환 신청 지급완료/취소/환불완료 처리 | 실제 지급 후 완료 처리 |
| `/포인트로그` | 운영자 | 포인트 거래 로그 조회 | 사용자, 종류, 개수 조건으로 확인 |
| `/인증관리` | 운영자 | 미션 인증 승인/반려 | 승인 시 포인트 지급과 연결 |
| `/운영현황` | 운영자 | 교환 대기, 인증 대기, 미션, 상점 현황 확인 | 운영 중 대기열 점검용 |
| `/미션관리` | 운영자 | 미션 목록, 추가, 수정, 활성화, 일시중지, 종료 | 활성화된 미션만 참여자에게 노출 |
| `/상점관리` | 운영자 | 상점 항목 목록, 추가, 수정, 활성화, 일시중지, 품절, 숨김 | 활성 항목만 참여자에게 노출 |
| `/운영내보내기` | 운영자 | 운영 데이터를 요약, JSON, CSV로 내보내기 | 개인정보와 운영 데이터 포함 가능 |

## 여정 포인트 운영 흐름

1. 참여자가 `/체크인`으로 당일 참여를 기록합니다.
2. 참여자가 미션 인증 채널에 글, 사진, 영상 인증 메시지를 올립니다.
3. 운영자가 지급 대상 메시지에 ✅ 반응을 누르면 기본 미션 인증 포인트가 지급되고 거래 로그가 남습니다.
4. 지급 대상이 아니면 운영자가 ❌ 반응으로 반려 처리하며 포인트는 지급되지 않습니다.
5. `/인증` 명령어는 직접 제출이 필요한 경우의 보조 흐름으로 유지하며, 운영자는 기존처럼 `/인증관리`로 제출을 승인할 수 있습니다.
6. 참여자가 `/상점`으로 신청 가능한 항목을 확인하고 선택 메뉴에서 항목을 고릅니다.
7. 참여자가 교환 확인 버튼 또는 `/교환` 선택 메뉴로 신청하면 포인트가 차감되고 신청이 대기 상태로 남습니다. 신청하지 않기를 누른 경우 한 번 더 종료 여부를 확인합니다.
8. 운영자가 실제 청년동 포인트 또는 리워드를 지급합니다.

참여자는 먼저 `/안내`에서 포인트, 상점과 교환, 미션과 인증 방법을 확인할 수 있습니다. 인증 채널에 자유롭게 인증 메시지를 올릴 수 있으며, `/상점`, `/교환`, `/미션`, `/인증`에서 항목이나 미션을 선택해 진행할 수도 있습니다. 기존처럼 `/교환 항목:S001`, `/인증 미션:M001 내용:...` 방식도 계속 사용할 수 있습니다.
9. 운영자가 `/교환관리`로 지급완료 또는 예외 처리를 기록합니다.
10. 운영자는 `/포인트로그`와 `/운영내보내기`로 정산과 백업을 확인합니다.

포인트는 경쟁이나 순위가 아니라 참여 흐름을 돕는 선택형 장치로 안내합니다.

## 데이터 저장 방식

현재 MVP는 local JSON repository 구조를 사용합니다.

- 운영 데이터는 `data/*.local.json` 형태로 저장될 수 있으며 커밋하지 않습니다.
- local JSON은 Railway 장기 운영 저장소로는 한계가 있습니다.
- 실제 운영 전에는 Railway Volume, Google Sheets, PostgreSQL 중 하나를 검토해야 합니다.
- `/운영내보내기`로 포인트, 교환, 인증, 미션, 상점 데이터를 백업할 수 있습니다.
- 내보낸 파일에는 사용자 ID, 표시 이름, 인증 내용, 운영 메모가 포함될 수 있으므로 외부 공유 전 반드시 확인합니다.

## 개발 및 실행 방법

패키지 설치:

```bash
npm install
```

봇 실행:

```bash
npm start
```

Slash Command 등록/갱신:

```bash
npm run deploy
```

`npm run deploy`는 Slash Command 추가, 삭제, 옵션, 선택지 변경이 필요할 때만 실행합니다. 기능 코드를 수정하고 push하면 Railway가 재배포될 수 있지만, Discord Slash Command 목록 변경은 별도 deploy가 필요합니다.

데이터와 릴리즈 검증:

```bash
npm run validate:data
npm run test:questions
npm run check:release
```

## 검증 명령어

## prompts 사용 방식

`prompts/codex`는 Codex CLI 작업 지시서를 보관하는 폴더입니다.

- 재사용 가능한 프롬프트만 보관합니다.
- 실제 토큰, 채널 ID, 참여자 개인정보는 넣지 않습니다.
- 작업 후 결과 문서는 `docs`에 정리합니다.
- 일회성 운영 기록이나 민감 데이터는 프롬프트에 포함하지 않습니다.
