# 프로젝트 리디파인 디스코드 봇

프로젝트 리디파인 참여자 안내, FAQ, 온보딩, 여정 포인트, 상점, 교환, 체크인, 미션, 인증, 운영자 관리 기능을 제공하는 Discord 봇입니다.

MEE6는 환대, 채팅 EXP, 레벨업 보조 용도로만 사용합니다. 리디파인 봇은 실제 운영 안내, 참여 활동 기록, 포인트, 교환, 운영자 처리 흐름을 담당합니다.

## 주요 기능

참여자 기능:

- `/안내` 참여자용 메인 허브에서 처음 왔어요, 오늘 뭐 하면 되나요?, 내 포인트, 상점/교환, 미션/인증, 문의 방법 확인
- 채널 안내 확인
- FAQ/지식창고 질문
- 여정 포인트 확인
- 상점 확인
- 교환 신청
- 체크인
- 미션 확인
- 미션 인증 채널 업로드와 운영자 ✅ 확인 중심 인증, 필요 시 `/인증` 보조 제출

운영자 기능:

- 공지 템플릿 확인
- 포인트 지급/차감
- 교환 신청 처리
- 포인트 로그 확인
- 인증 제출 승인/반려
- 미션 인증 채널 반응 승인/반려
- 운영 현황 확인
- 미션 관리
- 상점 관리
- 운영 데이터 내보내기
- 읽기 전용 관리자 웹 대시보드(`/admin`)

| `/체크인` | 참여자 | 당일 체크인 기록과 기본 포인트 적립 | private 응답 중심, 한국 시간 기준 중복 방지 |
| `/미션` | 참여자 | 현재 참여 가능한 미션 확인 및 선택 | private 응답 중심, 코드를 외우지 않고 글 인증 모달로 제출 |
| `/인증` | 참여자 | 미션 수행 내용 제출 | 글 인증은 모달, 사진/영상 인증은 첨부파일로 보조 제출 |

| `/교환관리` | 운영자 | 교환 신청 지급완료/취소/환불완료 처리 | 실제 지급 후 완료 처리 |
| `/포인트로그` | 운영자 | 포인트 거래 로그 조회 | 사용자, 종류, 개수 조건으로 확인 |
| `/인증관리` | 운영자 | 미션 인증 승인/반려 | 승인 시 포인트 지급과 연결 |
| `/운영현황` | 운영자 | 운영자용 허브에서 요약, 대기 건, 로그, 미션/상점, 반응 승인, 내보내기 안내 확인 | 드롭다운으로 세부 메뉴 선택 |
| `/미션관리` | 운영자 | 미션 목록, 추가, 수정, 활성화, 일시중지, 종료 | 활성화된 미션만 참여자에게 노출 |
| `/상점관리` | 운영자 | 상점 항목 목록, 추가, 수정, 활성화, 일시중지, 품절, 숨김 | 활성 항목만 참여자에게 노출 |
| `/운영내보내기` | 운영자 | 운영 데이터를 요약, JSON, CSV로 내보내기 | 개인정보와 운영 데이터 포함 가능 |

## 여정 포인트 운영 흐름

1. 참여자가 `/체크인`으로 당일 참여를 기록합니다.
2. 참여자가 미션 인증 채널에 글, 사진, 영상 인증 메시지를 올립니다.
3. 운영자가 지급 대상 메시지에 ✅ 반응을 누르면 기본 미션 인증 포인트가 지급되고 거래 로그가 남습니다.
4. 지급 대상이 아니면 운영자가 ❌ 반응으로 반려 처리하며 포인트는 지급되지 않습니다.
5. 반응 승인/반려 후 원본 인증 채널 공개 답글은 기본적으로 남기지 않습니다. 운영자 로그와 포인트 로그는 유지됩니다.
6. 참여자 DM 알림은 `REACTION_APPROVAL_DM_USER`로 제어하며, DM 실패는 포인트 지급이나 반려 기록을 막지 않습니다.
7. `/인증` 명령어는 직접 제출이 필요한 경우의 보조 흐름으로 유지하며, 운영자는 기존처럼 `/인증관리`로 제출을 승인할 수 있습니다.
8. 참여자가 `/상점`으로 신청 가능한 항목을 확인하고 선택 메뉴에서 항목을 고릅니다.
9. 참여자가 교환 확인 버튼 또는 `/교환` 선택 메뉴로 신청하면 포인트가 차감되고 신청이 대기 상태로 남습니다. 신청하지 않기를 누른 경우 한 번 더 종료 여부를 확인합니다.
10. 운영자가 실제 청년동 포인트 또는 리워드를 지급합니다.
11. 운영자가 `/교환관리`로 지급완료 또는 예외 처리를 기록합니다.
12. 운영자는 `/포인트로그`와 `/운영내보내기`로 정산과 백업을 확인합니다.

참여자는 먼저 `/안내`에서 포인트, 상점과 교환, 미션과 인증 방법을 확인할 수 있습니다. `/상점`과 `/미션`은 상품명과 미션명이 먼저 보이는 단순한 선택형 흐름이며, 신청 코드와 미션 코드는 보조 정보로 유지합니다. 기본 미션 인증은 인증 채널에 글, 사진, 영상 메시지를 올리고 운영자가 ✅로 확인하는 방식입니다. `/인증` 명령어는 직접 제출이 필요한 경우의 보조 흐름으로 유지하며, 글 인증은 모달, 사진/영상 인증은 첨부파일 방식으로 제출할 수 있습니다. `/상점`, `/교환`, `/미션`, `/인증`에서 항목이나 미션을 선택해 진행할 수도 있고, 기존처럼 `/교환 항목:S001`, `/인증 미션:M001 내용:...` 방식도 계속 사용할 수 있습니다.

포인트는 경쟁이나 순위가 아니라 참여 흐름을 돕는 선택형 장치로 안내합니다.

## 데이터 저장 방식

현재 MVP는 local JSON repository 구조를 사용합니다.

- 운영 데이터는 `data/*.local.json` 형태로 저장될 수 있으며 커밋하지 않습니다.
- local JSON은 Railway 장기 운영 저장소로는 한계가 있습니다.
- 실제 운영 전에는 Railway Volume, Google Sheets, PostgreSQL 중 하나를 검토해야 합니다.
- Railway Variables에는 미션 반응 승인 알림 정책에 맞게 `REACTION_APPROVAL_PUBLIC_REPLY=false`, `REACTION_APPROVAL_DM_USER=true`를 추가합니다.
- `/운영내보내기`로 포인트, 교환, 인증, 미션, 상점 데이터를 백업할 수 있습니다.
- 내보낸 파일에는 사용자 ID, 표시 이름, 인증 내용, 운영 메모가 포함될 수 있으므로 외부 공유 전 반드시 확인합니다.

## 개발 및 실행 방법

패키지 설치:

```bash
npm install
```

봇 실행:

```bash
npm start
```

Slash Command 등록/갱신:

```bash
npm run deploy
```

`npm run deploy`는 Slash Command 추가, 삭제, 옵션, 선택지 변경이 필요할 때만 실행합니다. 기능 코드를 수정하고 push하면 Railway가 재배포될 수 있지만, Discord Slash Command 목록 변경은 별도 deploy가 필요합니다.

데이터와 릴리즈 검증:

```bash
npm run validate:data
npm run test:questions
npm run check:release
```

## 관리자 웹 대시보드 MVP

읽기 전용 관리자 웹 대시보드가 `/admin` 경로에 추가되어 있습니다. 기본값은 비활성화이며, Railway Variables 또는 로컬 `.env`에 아래 값을 설정했을 때만 같은 봇 프로세스에서 웹 서버가 함께 켜집니다.

```env
ADMIN_DASHBOARD_ENABLED=true
ADMIN_DASHBOARD_PASSWORD=원하는_관리자_비밀번호
ADMIN_DASHBOARD_TITLE=리디파인 운영 대시보드
```

Railway에서 Public Domain을 생성한 뒤 `https://Railway-도메인/admin`으로 접속합니다. Public Domain은 Railway 프로젝트의 서비스 `Settings` -> `Networking` -> `Public Networking`에서 생성합니다.

대시보드는 HTTP Basic Auth로 보호되며 API도 같은 인증을 사용합니다. 운영 요약 카드, 교환 대기, 인증 대기, 최근 포인트 로그, 미션 상태, 상점 상태, 반응 승인 기록, `/운영내보내기` 안내와 운영 체크리스트를 보여줍니다.

운영 로그와 알림 채널은 아래 환경변수를 기준으로 분리합니다.

- `LOG_CHANNEL_ID`: 기본 운영 로그, fallback 질문, 일반 알림
- `ACTIVITY_REVIEW_CHANNEL_ID`: 미션 인증 검토와 반응 승인/반려 처리 로그
- `POINT_REDEEM_CHANNEL_ID`: 교환 신청과 교환 처리 알림

관리자 대시보드와 `/api/admin/*` 응답은 `data/*.example.json`의 example/demo/sample 데이터를 실제 운영 데이터처럼 보이지 않도록 제외합니다. 실제 운영 전에는 `data/*.local.json` 상태를 확인하고, 테스트용 local 데이터가 남아 있으면 정리한 뒤 운영용 미션과 상점 항목을 `/미션관리`, `/상점관리`로 등록합니다.

운영 전 기본 미션과 상점 항목은 자동 생성되지 않습니다. 실제 운영 데이터는 `/미션관리`, `/상점관리`로 직접 등록하고, 기본 후보와 등록 순서는 [운영용 기본 미션/상점 설계](docs/operation-default-items-plan.md)와 [미션/상점 등록 가이드](docs/mission-shop-setup-guide.md)를 기준으로 확인합니다.

초기 MVP 대시보드는 읽기 전용입니다. 승인, 거절, 포인트 지급/차감, 미션/상점 수정은 계속 Discord의 `/교환관리`, `/인증관리`, `/포인트관리`, `/미션관리`, `/상점관리` 명령어에서 처리합니다. Google Sheets는 `GOOGLE_SHEETS_LOGGING_ENABLED=true`일 때 운영 확인용 append-only 보조 로그로만 사용하며, PostgreSQL 연동은 포함하지 않습니다.

## prompts 사용 방식

`prompts/codex`는 Codex CLI 작업 지시서를 보관하는 폴더입니다.

- 재사용 가능한 프롬프트만 보관합니다.
- 실제 토큰, 채널 ID, 참여자 개인정보는 넣지 않습니다.
- 작업 후 결과 문서는 `docs`에 정리합니다.
- 일회성 운영 기록이나 민감 데이터는 프롬프트에 포함하지 않습니다.
