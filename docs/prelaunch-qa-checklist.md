# 실제 운영 전 QA 체크리스트

실제 참여자 입장 전 운영 환경, 권한, 명령어, 포인트 흐름, 백업, 배포 상태를 확인하는 체크리스트입니다. 실제 토큰, API Key, 채널 ID, 참여자 개인정보는 이 문서에 적지 않습니다.

운영 전 전체 흐름 리허설은 [운영 전 QA 리허설 시나리오](prelaunch-rehearsal-scenario.md)를 기준으로 진행합니다. 이 체크리스트는 리허설 전후의 점검 항목을 빠르게 확인하는 용도입니다.

## 0. 운영 전 리허설 완료 확인

- [ ] 테스트 참여자 계정으로 `/안내 -> /미션 -> /체크인 -> 인증 업로드 -> /포인트 -> /상점 -> /교환` 흐름을 1회 이상 완료했습니다.
- [ ] 운영자 계정으로 `✅ 반응 승인 -> /포인트로그 -> /운영현황 -> /admin -> /교환관리 -> /운영내보내기` 흐름을 1회 이상 완료했습니다.
- [ ] `/admin` 대시보드에서 오늘의 운영 큐, 요약 카드, 교환 대기, 최근 포인트 로그, 미션/상점 상태, 반응 승인 기록의 변화를 확인했습니다.
- [ ] 리허설 후 테스트 참여자 포인트, 테스트 교환 신청, 테스트 인증 기록 정리 여부를 결정했습니다.
- [ ] 실제 운영용 미션과 상점만 active 상태로 남겼고 hidden/paused/soldOut 항목 노출 여부를 확인했습니다.
- [ ] `data/*.example.json`은 삭제하지 않았고 `data/*.local.json`은 커밋 대상에 포함하지 않았습니다.

## 1. 환경변수 확인

- [ ] `DISCORD_TOKEN`이 운영 환경에 등록되어 있습니다.
- [ ] Railway Public Domain이 생성되어 있습니다.
- [ ] `CLIENT_ID`가 운영 봇 애플리케이션 기준입니다.
- [ ] `GUILD_ID`가 실제 운영 서버 기준입니다.
- [ ] `LOG_CHANNEL_ID`가 운영진 로그 채널 기준입니다.
- [ ] `POINT_REDEEM_CHANNEL_ID`가 교환 알림 채널 기준입니다.
- [ ] `ACTIVITY_REVIEW_CHANNEL_ID`가 인증 검토 알림 채널 기준입니다.
- [ ] `POINTS_DATA_PATH`를 사용할 경우 운영 데이터 저장 위치가 확인되어 있습니다.
- [ ] `SHOP_ITEMS_DATA_PATH`를 사용할 경우 운영 데이터 저장 위치가 확인되어 있습니다.
- [ ] `REDEMPTIONS_DATA_PATH`를 사용할 경우 운영 데이터 저장 위치가 확인되어 있습니다.
- [ ] `MISSIONS_DATA_PATH`를 사용할 경우 운영 데이터 저장 위치가 확인되어 있습니다.
- [ ] `SUBMISSIONS_DATA_PATH`를 사용할 경우 운영 데이터 저장 위치가 확인되어 있습니다.
- [ ] `MISSION_SUBMISSION_CHANNEL_ID`가 미션 인증 채널 기준입니다.
- [ ] `MISSION_REACTION_REWARD_POINTS`가 기본 지급 포인트 기준입니다.
- [ ] `MISSION_APPROVE_EMOJI`가 승인 반응 기준입니다.
- [ ] `MISSION_REJECT_EMOJI`가 반려 반응 기준입니다.
- [ ] `OPERATOR_ROLE_ID` 사용 여부가 운영자 권한 정책과 맞습니다.
- [ ] `REACTION_APPROVAL_PUBLIC_REPLY=false`일 때 미션 인증 채널에 공개 답글이 남지 않습니다.
- [ ] `REACTION_APPROVAL_DM_USER=true`일 때 참여자 DM 알림이 전송됩니다.
- [ ] `ADMIN_DASHBOARD_ENABLED=true`를 사용할 경우 `ADMIN_DASHBOARD_PASSWORD`가 실제 운영 비밀번호로 설정되어 있습니다.
- [ ] DM 대화 연습을 사용할 경우 `DM_CHAT_ENABLED`, `AI_ENABLED`, `AI_PROVIDER`, `AI_MODEL`, `DM_CHAT_LOG_CHANNEL_ID`, `SAFETY_ALERT_CHANNEL_ID` 설정이 운영 정책과 맞습니다.
- [ ] `DM_CHAT_DAILY_LIMIT`가 KST 당일 사용자별 연습 상한 정책과 맞으며, 제한 해제가 필요한 경우 `0`으로 설정하는 절차를 확인했습니다.
- [ ] `SAFETY_ALERT_THROTTLE_MINUTES`가 반복 안전 알림 운영 정책과 맞으며, 전량 알림이 필요한 경우 `0`으로 설정하는 절차를 확인했습니다.

## 2. Discord 권한 확인

- [ ] 봇이 실제 운영 서버에 초대되어 있습니다.
- [ ] Slash Command가 운영 서버에 등록되어 있습니다.
- [ ] 운영자 역할과 테스트 운영자 계정이 준비되어 있습니다.
- [ ] 운영자는 `ManageMessages` 또는 `Administrator` 권한을 가지고 있습니다.
- [ ] 일반 참여자는 운영자 명령어를 실행할 수 없습니다.
- [ ] 운영자 전용 채널을 일반 참여자가 볼 수 없습니다.
- [ ] 로그/알림 채널에 봇이 메시지를 보낼 수 있습니다.
- [ ] 미션 인증 채널에서 봇 권한 `View Channel`, `Read Message History`, `Add Reactions`, `Send Messages`가 확인되어 있습니다.
- [ ] Discord Developer Portal과 봇 코드에서 reaction intent가 활성화되어 있습니다.

## 3. 참여자 명령어 테스트

- [ ] `/안내`: 참여자용 허브 화면이 본인만 보이는 응답으로 표시됩니다.
- [ ] `/안내`: 선택 메뉴 placeholder가 "궁금한 내용을 선택해 주세요"로 보입니다.
- [ ] `/안내`: 첫 화면이 짧고 읽기 쉬우며 전체 명령어를 길게 나열하지 않습니다.
- [ ] `/안내`: `처음 왔어요`, `오늘 뭐 하면 되나요?`, `내 포인트`, `상점/교환`, `미션/인증`, `문의하기` 선택지가 보입니다.
- [ ] `/안내`: 각 메뉴 선택 시 비어 있지 않은 안내 화면이 표시됩니다.
- [ ] `/안내`: `미션/인증` 안내가 미션 인증 채널 업로드와 운영진 ✅ 확인을 기본 흐름으로 설명합니다.
- [ ] `/안내`: `/인증` 명령어가 기본 방식이 아니라 직접 제출이 필요한 경우의 보조 수단으로 안내됩니다.
- [ ] 신규 참여자 고정 공지문 [participant-onboarding-notice.md](participant-onboarding-notice.md)이 존재하고 실제 채널 ID를 포함하지 않습니다.
- [ ] 처음 참여자 요약 안내문 [first-time-participant-guide.md](first-time-participant-guide.md)이 존재하고 참여자에게 바로 공유할 수 있습니다.
- [ ] `/안내`: 모바일에서 선택 메뉴와 문구가 읽기 편합니다.
- [ ] `/안내`: 명령어를 많이 몰라도 다음 행동이 `/체크인`, `/미션`, `/포인트`, `/상점`, 문의 흐름으로 이해됩니다.
- [ ] `/채널안내`: 주요 채널 설명이 실제 서버 구조와 어긋나지 않습니다.
- [ ] `/질문`: FAQ 또는 지식창고 답변이 정상 표시됩니다.
- [ ] `/리디`: 도움, 일정, 규칙, 문의 안내가 정상 표시됩니다.
- [ ] 브라우저 미니게임 `검은 종 생존전`: 시작, 큰 지도 카메라 이동, 직업별 자동 공격과 시각 차이, 웨이브 전환, 적 행동 차이, 업그레이드 레벨 선택, 보스 등장/처치 승리 조건이 동작하고 포인트/Discord 계정 연동 안내가 보이지 않습니다.
- [ ] `/포인트`: 본인 포인트만 private 응답으로 확인됩니다.
- [ ] `/상점`: 활성 상점 항목만 private 응답으로 짧게 표시되고, 목록 본문에는 신청 코드가 크게 노출되지 않으며 상품명이 먼저 보입니다.
- [ ] `/상점`: 상품 유형 이모지와 짧은 태그가 보이며, 본문에서는 내부 항목 ID가 노출되지 않습니다.
- [ ] `/교환`: 항목 없이 실행하면 상점 선택 메뉴가 private 응답으로 표시됩니다.
- [ ] `/교환 항목:S001`: 신청 코드 직접 입력 방식이 계속 접수됩니다.
- [ ] `/교환`: 기존 내부 항목 입력도 계속 접수됩니다.
- [ ] 활성 상점 항목이 없을 때 부드러운 안내가 보입니다.
- [ ] `/체크인`: 당일 1회 체크인이 기록되고 중복 체크인은 방지됩니다.
- [ ] `/미션`: 활성 미션만 짧게 표시되고, 목록 본문에는 미션 코드가 크게 노출되지 않으며 미션명이 먼저 보입니다.
- [ ] `/미션`: 본문에서는 내부 미션 ID가 노출되지 않고 지급 포인트와 인증 방식이 짧게 보입니다.
- [ ] 활성 미션이 없을 때 시스템 표현 대신 부드러운 안내와 `/체크인` 제안이 보입니다.
- [ ] `/인증`: 미션 없이 실행하면 미션 선택 메뉴가 private 응답으로 표시됩니다.
- [ ] `/인증`: 글 인증은 `/미션` 선택 후 모달, 사진/영상 인증은 `/인증` 첨부파일 방식으로 이해됩니다.
- [ ] `/인증 미션:M001 내용:...`: 미션 코드 직접 입력 방식이 계속 접수됩니다.
- [ ] `/인증 미션:M001 첨부파일:...`: 첨부파일 제출이 접수되고 운영자 검토 채널에 파일 정보가 보입니다.
- [ ] `/인증`: 기존 내부 미션 입력도 계속 접수됩니다.
- [ ] 참여자가 미션 인증 채널에 글, 사진, 영상 인증 메시지를 올릴 수 있습니다.
- [ ] DM 대화 연습을 켠 경우 첫 DM에서 기록/운영진 열람 안내가 1회 표시되고, 일반 대화가 로그 채널과 `/admin`에 읽기 전용으로 남습니다.
- [ ] `DM_CHAT_DAILY_LIMIT` 초과 상태에서 일반 DM을 보내면 "오늘은 연습을 충분히 했어요. 내일 다시 이어서 연습해요. 급한 일이나 어려운 일이 있다면 운영진에게 문의해 주세요." 안내가 전송되고 AI 호출 없이 assistant 로그가 남습니다.
- [ ] `DM_CHAT_DAILY_LIMIT` 초과 상태에서도 민감 표현 DM은 안전 알림과 기존 안내 흐름으로 처리됩니다.
- [ ] 같은 사용자가 민감 표현 DM을 반복하면 `SAFETY_ALERT_THROTTLE_MINUTES` 안에서는 안전 알림 채널 전송만 묶이고, DM 로그 저장과 DM 로그 채널 전송은 모두 유지됩니다.
- [ ] 참여자가 DM에 정확히 `새로 시작`을 보내면 "좋아요, 새 마음으로 다시 시작해요. 편하게 말을 걸어 주세요." 안내가 전송되고 이후 AI history에서 이전 대화가 제외됩니다.
- [ ] AI 응답 출력에 민감 표현이 포함되는 리허설 케이스에서 원문이 참여자에게 전송되지 않고 "지금은 답변을 만들지 못했어요. 잠시 후 다시 말을 걸어 주세요."로 대체되며, 운영진 DM 로그에서 출력 감지로 구분됩니다.

## 4. 운영자 명령어 테스트

- [ ] `/공지`: 선택한 공지 템플릿이 운영자에게 표시됩니다.
- [ ] `/포인트관리`: 지급/차감이 사유와 함께 로그에 남습니다.
- [ ] `/교환관리`: 신청 ID 기준으로 지급완료, 취소, 환불완료 처리가 됩니다.
- [ ] `/포인트로그`: 최근 거래와 필터 결과가 확인됩니다.
- [ ] `/인증관리`: 승인 시 포인트가 지급되고 반려 시 지급되지 않습니다.
- [ ] 미션 인증 채널 메시지에 운영자가 ✅ 반응을 누르면 포인트가 지급됩니다.
- [ ] 같은 메시지에 ✅ 반응을 다시 눌러도 중복 지급되지 않습니다.
- [ ] 미션 인증 채널 메시지에 운영자가 ❌ 반응을 누르면 반려 기록이 남고 포인트가 지급되지 않습니다.
- [ ] 운영자 권한이 없는 사용자의 ✅ 또는 ❌ 반응은 무시됩니다.
- [ ] DM을 막은 사용자도 ✅ 승인 시 포인트 지급과 포인트 로그 기록이 유지됩니다.
- [ ] 운영자 로그 채널에 승인/반려 처리 기록이 남습니다.
- [ ] 운영자 로그 채널의 승인/반려 기록에서 참여자 DM과 공개 답글 상태가 `전송 완료`, `전송 실패`, `비활성` 중 실제 결과로 표시됩니다.
- [ ] `/운영현황`: 첫 화면이 운영 현황 허브로 표시되고 핵심 숫자가 확인됩니다.
- [ ] `/운영현황`: 운영자 드롭다운이 표시되고 `전체 요약`, `오늘의 운영 큐`, `첫날 점검`, `교환 대기`, `인증 대기`, `최근 포인트 로그`, `미션/상점 상태`, `미션 관리 허브`, `반응 승인 기록`, `반응 후속 확인`, `도움 필요 신호`, `FAQ 후보`, `DM 대화`, `내보내기 안내`, `운영 체크리스트`를 선택할 수 있습니다.
- [ ] `/운영현황`: `오늘의 운영 큐` 화면에서 pending 교환, pending 인증, 오늘 반응 승인/반려, 오늘 포인트 거래, 후속 확인, QA 경고가 읽기 전용으로 확인됩니다.
- [ ] `/운영현황`: `첫날 점검` 화면에서 환경변수/채널, active 미션/상점 수, 교환/인증 대기, 예시 데이터 제외, `/운영내보내기` 안내가 읽기 전용으로 확인됩니다.
- [ ] `/운영현황`: `교환 대기` 화면에서 pending 교환 신청과 `/교환관리` 처리 안내가 확인됩니다.
- [ ] `/운영현황`: `인증 대기` 화면에서 pending 인증 제출과 `/인증관리` 처리 안내가 확인됩니다.
- [ ] `/운영현황`: `최근 포인트 로그` 화면에서 최근 거래와 `/포인트로그`, `/운영내보내기` 안내가 확인됩니다.
