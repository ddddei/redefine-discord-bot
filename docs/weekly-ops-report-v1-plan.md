# 주간 운영 리포트 v1 계획서

**상태: 코드·자동 검증 완료, 실환경 QA 대기 (2026-07-11)**

## 1. 목적

운영자가 최근 7일의 참여·포인트·미션 인증·교환·지연 신호를 한 화면에서 확인하고, 같은 요약을 운영진 전용 Discord 채널에 안전하게 공유할 수 있도록 한다. 참여자 평가나 순위가 아니라 누락된 운영 업무를 찾는 내부 보조 도구로만 사용한다.

## 2. v1 범위

- KST 기준 주간 범위와 이전 주 이동을 지원하는 순수 집계 모듈
- 체크인 참여자 수·체크인 수, 인증 상태별 건수, 포인트 지급·차감 합계, 교환 상태별 건수, 지연·마감 신호 집계
- `/api/admin/weekly-report` 읽기 전용 API와 운영 콘솔 카드
- 동일한 최소 집계를 이용한 Discord 미리보기·수동 발송·주간 자동 발송
- 자동 발송 기본 off, 최대 1개 KST 요일·시간, 주차별 원자 선예약으로 중복 방지
- 발송 이력은 공통 운영 데이터 경로·백업·strict 점검에 포함

## 3. 제외 범위

- 참여자별 순위·점수 비교·DM·공개 채널 발송
- 인증 원문, 첨부·URL, DM 내용, 운영 메모, 표시 이름 목록
- 자동 상태 변경, 포인트 지급, 교환 처리
- 월간/분기 보고서와 외부 문서·스프레드시트 전송

## 4. 집계 계약

- 기본 범위는 실행 시각이 포함된 KST 월요일 00:00부터 현재까지이며 `weekOffset`은 `0~-12`만 허용한다.
- example/demo/sample 레코드는 공통 필터로 제외한다.
- 중복 없는 Discord 사용자 ID만 참여자 수로 세되 API와 메시지에는 ID 목록을 노출하지 않는다.
- 포인트는 양수 합계와 음수 절대값 합계를 분리하고 거래 건수만 함께 제공한다.
- 지연 신호는 `opsDelayPolicy`와 동일한 임계값을 사용한다.
- 모든 HTTP 응답은 Basic Auth와 `Cache-Control: no-store`를 유지한다.

## 5. 발송·이력 계약

- `WEEKLY_OPS_REPORT_ENABLED=true`일 때만 자동 스케줄러가 동작하며, 정기 발송은 완료된 직전 주를 집계한다.
- 전용 채널이 없으면 `OPS_REMINDER_CHANNEL_ID`, `ADMIN_CONSOLE_LOG_CHANNEL_ID`, `LOG_CHANNEL_ID` 순으로 fallback하되 채널이 없으면 안전하게 건너뛴다.
- 수동 발송과 자동 발송 모두 `YYYY-MM-DD` 주 시작일을 키로 원자 선예약하며 같은 주차 중복 발송을 막는다.
- 예약 후 실패는 failed 상태로 기록하고 자동 재시도하지 않는다. 운영자가 원인을 확인한 뒤 별도 수동 재시도를 명시적으로 선택하는 기능은 v1에서 제외한다.
- Discord 메시지는 집계 숫자와 HTTPS 콘솔 링크만 포함하고 mention을 금지한다.

## 6. 검증·운영 전 조건

- 경계 시각, 이전 주, example 제외, 민감정보 비노출, 파일 무변경 조회를 테스트한다.
- 중복 예약, 채널 누락, 전송 실패, 성공 이력과 백업 포함을 테스트한다.
- 기존 admin·Phase 3·백업 회귀 테스트와 `npm run check:release`를 통과한다.
- 실제 운영에서는 Railway 단일 인스턴스·Volume·전용 채널·모바일 화면을 확인한 뒤 자동 발송을 활성화한다.
