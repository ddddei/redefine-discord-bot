# 덱빌딩 브라우저 미니게임 v1 계획서 — `간식 수호대` (Codex 실행용)

이 문서는 다른 컨텍스트 없이 단독으로 구현 가능하도록 작성된 계획서입니다. 구현 전 이 저장소의 [AGENTS.md](../AGENTS.md), [src/AGENTS.md](../src/AGENTS.md), [scripts/AGENTS.md](../scripts/AGENTS.md)를 먼저 읽어 주세요.

## 1. 개요와 설계 철학

로그라이크 덱빌더(슬레이 더 스파이어류)의 핵심 재미를 브라우저용으로 압축한 카드 게임 **`간식 수호대`** 를 만듭니다. 한 판 10~15분짜리 단일 런 구조로, 전투에서 이길 때마다 카드를 골라 덱을 키우고 마지막 보스에 도전합니다. 매치3 `간식 맞추기`, 방치형 `간식 공방 키우기`와 같은 밝은 간식 세계관을 공유합니다 — 주인공 견습 제빵사가 공방의 간식을 노리는 침입자들을 물리치는 이야기입니다.

이 장르의 재미 축과 v1 구현:

| 재미 축 | 구현 |
| --- | --- |
| 덱이 성장하는 재미 | 전투 승리마다 3장 중 1장 선택(스킵 가능), 휴식 이벤트에서 카드 제거 |
| 읽고 대응하는 전투 | 적의 다음 행동(의도) 예고 — 공격 예고를 보고 방어할지 밀어붙일지 선택 |
| 한정 자원 퍼즐 | 턴당 에너지 3, 드로우 5장 안에서 최적 조합 찾기 |
| 런의 긴장감 | HP가 전투를 넘어 유지, 회복 기회는 제한적, 패배하면 런 종료 |

**v1에서 의도적으로 뺀 것 (볼륨 통제)**: 갈림길 맵(선형 진행으로 대체), 유물/포션, 다중 적 전투(전투당 적 1명), 카드 강화, 메타 진행(영구 해금). 전부 10절의 v2 후보입니다.

기존 웹게임과 동일한 운영 원칙과 서빙 구조를 따릅니다.

- 브랜치: `feat/deck-web-game-v1`
- 배포 경로: 관리자 서버(`src/adminServer.js`)의 `/game/deck` 라우트 (접속 안내는 트래일링 슬래시 포함 `/game/deck/`)
- 정적 파일 위치: `public/deck/`

## 2. 운영 원칙 (기존 웹게임과 동일 — 반드시 준수)

- Discord 계정 연동 없음. 포인트 지급/차감/베팅/랭킹 저장 없음.
- 진행 상태는 **브라우저 localStorage에만** 저장하며 운영 데이터 JSON에 저장하지 않음. 서버는 정적 파일만 서빙.
- `.env` 수정, `npm run deploy` 불필요. 신규 npm 의존성 금지 (순수 HTML/CSS/JS).
- 기존 버튼형 미니게임의 보상 정책은 변경하지 않음.

## 3. 런 구조

한 런은 선형 11칸입니다. 갈림길 없이 순서대로 진행하되, 어떤 적이 나올지는 시드 셔플로 결정됩니다.

```
일반 → 일반 → 일반 → 휴식 → 정예 → 일반 → 일반 → 휴식 → 일반 → 정예 → 보스
```

- **일반 전투 6회**: 일반 적 풀 6종에서 시드 셔플로 중복 없이 배치.
- **정예 전투 2회**: 정예 적 풀 2종에서 하나씩. 보상 카드 후보의 질이 높음(아래 5.3).
- **휴식 2회**: `회복하기`(최대 HP의 30% 회복) 또는 `덱 정리하기`(카드 1장 영구 제거) 중 택1. 카드 제거는 덱빌더의 핵심 전략 요소라 v1에 포함합니다.
- **보스 1회**: 고정 보스 1종.
- 승리 보상: 전투 후 카드 3장 제시 → 1장 선택 또는 스킵.
- 패배(HP 0) 또는 보스 격파 시 결과 화면: 도달 칸, 최종 덱, 처치 수, 짧은 평가 문구, `새로 시작` 버튼. 보스 격파 기록(클리어 횟수·최고 기록)은 localStorage에 유지.

## 4. 전투 규칙

- **플레이어**: 최대 HP 60(런 내내 유지), 턴당 에너지 3, 턴 시작 시 5장 드로우, 턴 종료 시 손패 전부 버림. 뽑을 덱이 떨어지면 버림 더미를 시드 셔플해 재사용.
- **적**: 전투당 1명. 매 턴 **의도**(다음 행동)를 아이콘+수치로 예고: `공격 N`, `방어 N`, `강화`(힘 +N), `저주`(약화/취약 부여) 중 하나. 행동 패턴은 적별 고정 순환(시드 불필요, 예측 가능해야 재미)입니다.
- **방어도(block)**: 피해를 먼저 흡수하고 자기 턴 시작 시 소멸. 플레이어/적 동일 규칙.
- **상태 효과 3종 (v1 전부)**:
  - `힘`: 공격 피해 +N (영구, 전투 종료 시 소멸)
  - `약화`: 주는 공격 피해 25% 감소 (N턴)
  - `취약`: 받는 공격 피해 50% 증가 (N턴)
- **피해 계산 순서**: (기본 피해 + 힘) × 약화(×0.75, 내림) × 취약(×1.5, 내림) → 방어도 차감 → HP 차감. 내림은 각 곱연산 직후 적용.
- 전투 승리 시 방어도/상태 효과 초기화, HP는 유지.

- 일반 전투 승리: 일반 카드에서 3장 (시드 셔플, 중복 없음).

## 6. 적 설계 (9종)

행동 패턴은 배열 순환입니다. `공N`=공격 N, `방N`=방어도 N, `힘N`=힘 +N, 상태는 플레이어에게 부여.

| 적 | 등급 | HP | 패턴 |
| --- | --- | --- | --- |
| 부스러기 개미 | 일반 | 14 | 공5 → 공5 → 방5 |
| 단내 나방 | 일반 | 18 | 공4 → 약화1턴 → 공7 |
| 욕심쟁이 비둘기 | 일반 | 22 | 공8 → 방6 |
| 설탕 슬라임 | 일반 | 26 | 방8 → 공6 → 공6 |
| 주방 생쥐 | 일반 | 20 | 공3×2회 → 공3×2회 → 힘2 |
| 곰팡이 요정 | 일반 | 24 | 취약2턴 → 공9 (취약은 부여 턴 종료 시 즉시 1 감소하므로 다음 공격 증폭에 2턴 필요) |
| 캐러멜 골렘 | 정예 | 45 | 방10 → 공12 → 공8 |
| 휘핑 하피 | 정예 | 40 | 공6×2회 → 약화2턴 → 공10 |
| 대왕 식탐 드래곤 | 보스 | 80 | 힘2 → 공10 → 방12 → 공14 |

밸런스 목표: 시작 덱만으로 일반 2~3전투는 무난히, 정예는 카드를 안 모았으면 위험하게, 보스는 덱을 잘 짰을 때 이길 수 있게. 구현 후 수동 QA에서 시드 고정 런으로 확인하고, 수치 조정은 `content.js`에서만 합니다.

## 7. 화면 구성·저장·기타 규칙

- 세로 모바일 우선 단일 페이지, PC는 가운데 폭 520px 카드. 상단: 진행 트랙(11칸)·플레이어 HP. 중앙: 적(이모지·HP·방어도·의도). 하단: 손패(가로 스크롤 카드), 에너지, `턴 종료` 버튼.
- 카드는 탭하면 사용(적 1명이라 대상 선택 불필요). 비용 부족/사용 불가 카드는 비활성 표시.
- **시드**: URL `?seed=<숫자>`로 결정적 런(QA용). 없으면 랜덤 시드 생성 후 런 저장 데이터에 기록 — 이어하기 시 같은 셔플 유지.
- **저장**: localStorage 키 `redefine-deck-save-v1`(`version: 1`). 런 진행 중 상태(덱·HP·현재 칸·전투 상태·시드·RNG 카운터)를 행동 단위로 저장 → 브라우저를 닫아도 이어하기. 별도 키 분리 없이 같은 객체에 통산 기록(클리어 수, 최고 도달 칸) 포함. 손상 데이터는 조용히 버리고 새 게임(콘솔 경고만).
- **RNG**: `engine.js`에 시드 기반 결정적 RNG(매치3 `board.js`의 기존 패턴 참고). `Math.random()` 직접 사용 금지 (game.js의 연출용 제외).
- 카피 톤: 한국어, 차분하고 직접적으로. 전투 결과·평가 문구도 과장 없이 가볍게.

## 9. 테스트

순수 Node + `assert`, 마지막에 성공 한 줄 출력 (기존 컨벤션).

### `scripts/test-deck-logic.js`

`vm.runInNewContext`로 `content.js` + `engine.js` 로드 후:

- **RNG/셔플 결정성**: 같은 시드는 같은 셔플·같은 런 배치·같은 카드 보상. 다른 시드는 다른 결과(최소 1개 시드 쌍 확인).
- **드로우/버림 순환**: 5장 드로우, 턴 종료 시 손패 버림, 덱 소진 시 버림 더미 재셔플 후 이어서 드로우.
- **에너지**: 비용 합이 에너지 초과면 사용 불가, 턴 시작 시 3으로 리셋, `계량 정확히`/`마스터 레시피`의 에너지 획득 반영.
- **피해 계산**: 힘/약화/취약/방어도 각각과 조합의 경계값 (예: 힘2+취약 상태 피해 6 → (6+2)×1.5=12). 곱연산 직후 내림 검증. 다단 히트는 히트마다 방어도 차감.
- **상태 효과 지속**: 약화/취약 턴 카운트 감소·만료, 힘의 전투 내 지속, 방어도의 자기 턴 시작 시 소멸.
- **적 행동**: 패턴 순환 인덱스, 의도와 실제 행동 일치, 적 방어도/힘 반영.
- **런 진행**: 11칸 구성이 3절 배치와 일치, 일반 적 중복 없음, 휴식 2회의 회복(30% 상한)·카드 제거 반영, 정예/보스 보상에 정예급 1장 이상 보장.
- **승패**: 적 HP 0 → 전투 승리·상태 초기화·HP 유지, 플레이어 HP 0 → 런 종료, 보스 격파 → 클리어 기록 증가.
- **저장 왕복**: 런 중간 상태 직렬화 → 역직렬화 일치(같은 시드·RNG 카운터로 이후 셔플 동일). 손상 입력(빈 문자열/잘못된 JSON/음수 HP/버전 누락)은 `null`.
- **콘텐츠 안전망**: 모든 카드의 effect 프리미티브가 엔진이 아는 종류인지, 적 패턴이 비어 있지 않은지, 런 구성 배열의 적 참조가 전부 존재하는지 순회 검증.
