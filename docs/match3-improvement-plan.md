# 간식 맞추기 고도화 v1 계획서 — 특수 타일·오늘의 도전 변형·목표 판 (완성 배포판)

`public/match3/`의 고도화 v1 전체 명세입니다. **이 계획서의 전 항목을 구현하면 배포 가능한 완성 상태**이며, QA·피드백 반영은 배포 후 별도 작업입니다. 절대 조건: **시드 결정성 유지** — 같은 시드는 언제나 같은 판·같은 리필(오늘의 도전·리플레이 검증 v2의 전제).

## 0. 완성 정의 (이것이 전부 참이면 완료)

1. 4매치·5매치·T/L매치가 특수 타일을 만들고, 발동이 명세대로 동작한다
2. 오늘의 도전이 요일 변형 규칙으로 돌아간다 (서버가 변형을 결정)
3. 목표 판 모드 12종이 플레이 가능하다 (랭킹 무관)
4. 시드 고정 회귀 테스트가 통과한다 (기존 판 재현 + 특수 타일 결정성)
5. `check:release` 전체 통과, 데스크톱/모바일 QA, 미연결 회귀

## 1. 작업 A — 특수 타일 (board.js 로직 확장)

### 1.1 생성 규칙 (결정적 — RNG 미사용)

| 매치 형태 | 생성 타일 | 생성 위치 |
| --- | --- | --- |
| 4개 일렬 (가로) | 세로줄 제거 타일 | 스왑으로 유발 시 스왑된 셀, 캐스케이드 유발 시 매치 그룹의 최좌상단 셀 |
| 4개 일렬 (세로) | 가로줄 제거 타일 | 위와 동일 규칙 |
| 5개 일렬 | 동종 제거 타일 (컬러) | 위와 동일 규칙 |
| T/L자 (교차 5~6개) | 폭발 타일 (3×3) | 교차점 셀 |

- 생성 위치 규칙이 결정적이므로 RNG를 전혀 소비하지 않는다. **리필은 기존 RNG 경로 그대로** — 기존 시드의 리필 순서가 변하지 않음을 회귀 테스트로 증명한다(단, 특수 타일이 생기면 제거 셀 수가 달라져 리필 개수는 달라진다 — "같은 시드+같은 입력 = 같은 결과"가 불변 조건이지, 구버전과의 판 동일성이 아님을 명시. **배포 시점 주의: 오늘의 도전 도중(하루 중간)에 배포하면 같은 날 신구 클라이언트의 판이 달라진다 — 배포는 KST 자정 직후 권장, 운영 문서에 기록**).
- 특수 타일 자체는 일반 매치의 재료로도 쓰인다(간식 종류를 유지). 매치로 소모되면 그 시점에 발동한다.

### 1.2 발동 규칙

- 스왑 대상이 되면 즉시 발동(스왑 상대가 일반 타일이어도). 특수+특수 스왑 조합 효과는 **v1 제외**(각자 발동) — v2 후보.
- 발동으로 제거된 셀에 다른 특수 타일이 있으면 연쇄 발동(체인). 처리 순서: 좌상단부터 행 우선 — 결정적.
- 컬러 타일: 스왑 상대의 간식 종류를 제거. 캐스케이드로 소모되면 보드에서 가장 많은 간식 종류를 제거(동수면 간식 id 순).

### 1.3 점수 (maxScore 재산정 포함)

- 발동 제거 타일: 일반 매치와 동일한 개당 점수 × 현재 콤보 배율
- 발동 보너스: 줄 100 / 폭발 150 / 컬러 300 (콤보 배율 적용)
- **서버 상한**: 이론 상한 재계산 근거를 계획 대비 실측으로 보고하고 `GAME_DEFINITIONS.match3.maxScore`를 50,000 → **90,000**으로 상향(30수 × 컬러 체인 최대 가정 + 여유 계수). [webgame-rankings-ops.md](webgame-rankings-ops.md) 표 갱신.

### 1.4 표시

- 원화 타일 위 잉크 마크 오버레이(SVG): 줄=화살 쌍, 폭발=방사 점, 컬러=별 문양. `webgame-design-guide.md`의 잉크 톤 준수.
- 발동 연출은 기존 clearing 연출 재사용 + 줄/범위 하이라이트 1프레임 — 신규 애니메이션 최소화(저사양 예산).

## 2. 작업 B — 오늘의 도전 요일 변형

### 2.1 변형 테이블 (서버 결정 — dayKey의 KST 요일)

| 요일 | 변형 id | 규칙 | 카피 |
| --- | --- | --- | --- |
| 월·수·금·일 | `standard` | 기존 30수 | "오늘의 간식판이에요." |
| 화 | `sprint20` | 20수 제한 | "오늘은 20수 스프린트예요. 짧고 굵게!" |
| 목 | `collect` | 30수 + 목표 간식 40개 수집 시 보너스 3,000점 (목표 간식 = 시드로 결정) | "오늘의 목표 간식을 많이 모아 보세요." |
| 토 | `combo` | 30수 + 최고 콤보 × 500 보너스 | "오늘은 콤보가 돈이 돼요." |

### 2.2 서버/API

- `GET /game/api/daily` 응답에 `variant: { id, movesLimit, targetTile?, label }` 추가 — 결정 로직은 `webgameApi.js`(서버가 유일 소스, 클라 요일 계산 금지). targetTile은 `getDailySeed(dayKey)` 기반 결정적 선택.
- 점수 제출은 변경 없음(변형 보너스는 클라 점수에 합산돼 제출, 상한 검증은 1.3의 새 maxScore로 충분 — sprint20은 자연히 낮은 점수라 주간 랭킹에서 불리하지 않음: 주간은 최고 기록 기준임을 문서에 명시).
- 어제 시드 유예 제출은 어제의 variant 기준(서버가 dayKey로 판정하므로 자동).

### 2.3 클라이언트

- 오늘의 도전 시작 시 variant 규칙 적용(수 제한·목표 간식 칩 표시·보너스 계산). variant를 받지 못하면(구버전 서버) `standard`로 폴백.

## 3. 작업 C — 목표 판 모드 (랭킹 무관 완료형)

- 진입: 보드 아래 버튼 "목표 판" → 12종 목록(완료 체크 표시, localStorage `redefine-match3-goals-v1`).
- 판 정의는 `board.js`가 아니라 신규 `goals.js`(콘텐츠 상수): 각 판 = 고정 시드 + 목표 + 수 제한. 예시 12종:

| # | 시드 | 목표 | 수 |
| --- | --- | --- | --- |
| 1 | 1001 | 딸기 20개 | 20 |
| 2 | 1002 | 콤보 ×4 달성 | 25 |
| 3 | 1003 | 쿠키 30개 | 25 |
| 4 | 1004 | 특수 타일 3회 발동 | 20 |
| 5~12 | 1005~1012 | 수집/콤보/특수 혼합, 점진 난도 (구현 시 플레이 테스트로 수치 확정, 확정값 보고) | 18~30 |

- 성공 화면: "해냈어요!" + 다음 판 버튼. 실패: "이번엔 여기까지예요. 같은 판으로 다시 할 수 있어요." (재도전 무제한, 실패 기록 없음 — 배려 원칙)
- **서버 제출 없음** (부담 없는 병행 트랙 — 완료 여부는 로컬만).

## 4. 작업 D — 연출 폴리시

- 드래그 중 타일 따라오기: pointermove 동안 `transform: translate` (주축 방향만, 최대 이동 = 타일 1칸의 60%), pointerup에 스냅. 기존 스와이프 판정 로직(24px·busy 가드) 무변경 — 표시 계층만.
- `prefers-reduced-motion`에서 따라오기 비활성.
