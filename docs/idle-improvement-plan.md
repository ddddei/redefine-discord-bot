# 간식 공방 키우기 고도화 v1 계획서 — 공동 목표 연동·파견 확장·통계·소품 원화 (완성 배포판)

`public/idle/`의 고도화 v1 전체 명세입니다. **전 항목 구현 시 배포 가능한 완성 상태.** 절대 조건: `lifetimeProduced` 단조 증가 불변(공동 목표 집계 전제 — 어떤 신기능도 이 값을 줄이지 않는다), engine(순수 로직)/content(밸런스)/game(DOM) 분리 유지.

## 0. 완성 정의

1. 공동 목표 달성 주간에 공방 화면에서 축하가 보이고, 운영 이벤트 주간(배수)이 서버 값으로 동작한다
2. 파견 목적지 6종·이야기 카드 24종이 동작한다
3. 기록 탭에 주간 생산 추이·환생 히스토리가 보인다
4. 무대 장면의 이모지 소품이 원화로 교체된다 (원화 도착 게이트)
5. 구버전 세이브 로드 정상(신규 필드 관용 초기화), `check:release` 통과, QA 통과

## 1. 작업 A — 공동 목표 연동 콘텐츠

### 1.1 달성 축하 (게임 내 반영)

- 게임 로드 시 + 기록 탭 진입 시 `GameLink.fetchGoal()` 결과를 상태에 캐시(세션당 최대 2회 호출 — 폴링 없음).
- `achieved === true`인 주간: 공방 장면 상단에 현수막 렌더("이번 주 목표 달성! 다 같이 해냈어요 🎉") + 무대에 깃발 소품 1종. 미연결·오프라인이면 조용히 생략(게임 무영향).
- 주가 바뀌면(응답의 weekKey 변화) 자동 제거.

### 1.2 운영 이벤트 주간 (생산 배수)

- 서버: `GET /game/api/goal` 응답에 `event: { multiplier, label } | null` 추가. 값은 env `WEBGAME_IDLE_EVENT_MULTIPLIER`(기본 없음, 허용 1.5/2/3)·`WEBGAME_IDLE_EVENT_LABEL`(기본 "이벤트 주간"). `.env.example`·[railway-env-guide.md](railway-env-guide.md) 추가.
- 클라: multiplier를 engine의 전역 배수에 곱연산(오프라인 수익 포함). **미연결이어도 적용**(goal 엔드포인트는 공개) — 단 서버 미응답이면 1배(조용한 폴백).
- 공동 목표가 빨리 차는 것은 운영 의도(달성률 조절 수단). [webgame-rankings-ops.md](webgame-rankings-ops.md) 공동 목표 절에 이벤트 운영 절차 1단락 추가: 켜는 법·권장 빈도(월 1회 이하)·목표량과의 상호작용.
- **부정 방지 관점**: idle은 랭킹이 없으므로 배수로 인한 제출값 상승은 무해. 이상치 플래그(3배 휴리스틱)와 충돌 가능 → idle의 outlier 판정은 유지하되 flagged여도 공동 목표 집계에서 idle만은 배수 주간 감안이 필요하다는 운영 노트 1줄(코드 변경은 없음 — 소규모 운영 판단 영역).

## 2. 작업 B — 파견 확장

### 2.1 목적지 6종 (content.js `DELIVERY_DESTINATIONS`)

| 목적지 | 소요 | 보상 (1차안 — 기존 파견 보상 스케일에 상대 배율) | 해금 |
| --- | --- | --- | --- |
| 골목 어귀 | 5분 | 생산량 3분치 | 시작 |
| 마을 장터 | 15분 | 생산량 10분치 | 무대 2단계 |
| 강가 찻집 | 30분 | 생산량 22분치 + 낮은 확률(시드 무관 Math.random — 랭킹 무관 장르라 허용, 기존 황금 간식과 동일 원칙) 황금 간식 | 무대 3단계 |
| 숲속 야영지 | 2시간 | 생산량 90분치 | 무대 4단계 |
| 성문 앞 축제 | 8시간 | 생산량 5시간치 + 레시피 조각(환생 포인트 +1) | 무대 5단계 |
| 달빛 기차역 | 24시간 | 생산량 14시간치 + 레시피 조각 2 | 무대 6단계 |

- 동시 파견 1건 유지(기존). 보상 배율은 "방치 대비 약간 이득 + 돌아오는 재미" 원칙 — 구현 중 실측 조정, 확정표 보고.

### 2.2 이야기 카드 24종

- 파견 완료 모달에 목적지별 4종 중 1종(순환 — 방문 횟수 기반 결정, RNG 불필요)의 짧은 이야기(2~3문장, 스토리북 톤)를 표시. 전문은 content.js `DELIVERY_STORIES`에 — **카피 24종 전문을 구현 PR에 포함**하고 톤 리뷰 대상으로 보고.
- 본 카드 수집 여부를 도감 탭에 추가(기존 업적 도감 패턴, localStorage 신규 필드 — 세이브 버전 상향 없이 관용 초기화).

## 3. 작업 C — 통계·회고

- 기록 탭에 **주간 생산 추이**: 로컬에서 주간 스냅샷 저장(`weeklySnapshots: [{ weekKey, produced }]`, 주 변경 감지 시 기록, 최근 8주 보관). CSS 막대 그래프(gk 스타일, 라이브러리 금지).
- **환생 히스토리**: 환생 시점에 `{ at, prestigePoints, lifetimeProduced }` push(최근 10개). 기록 탭에 목록.
- 신규 세이브 필드는 로드 시 없으면 빈 배열 초기화(하위 호환 — 마이그레이션 불필요).

## 4. 작업 D — 무대 이모지 소품 원화 교체 (v3 잔여)

- 대상: 무대 장면(scene) 내 이모지 소품 전수(구현 시 감사 목록을 보고서에 첨부 — 예상 6~10개).
- 원화 형식: v3 정책(webp, `public/shared/art/`, 파일 150KB·총 예산 내, SOURCES.md 기록). 프롬프트는 [webgame-art-prompts.md](webgame-art-prompts.md) 형식으로 이 계획 승인 직후 작성 → **원화 도착이 이 작업의 게이트**(도착 전 다른 작업 A~C 선진행 가능).
- 로드 실패 시 이모지 폴백 유지(기존 패턴).
