# 운영진용 /점검 명령어 설계안

## 1. 문서 목적

이 문서는 운영진이 Discord 안에서 봇과 운영 준비 상태를 빠르게 확인할 수 있도록 하는 `/점검` 명령어의 설계안입니다.

실제 구현을 시작하기 전에 점검 항목, 출력 범위, 권한 기준과 수동 확인이 필요한 항목을 정리하기 위한 문서이며, 이번 단계에서는 명령어를 구현하지 않습니다.

## 2. 명령어 개요

| 항목 | 내용 |
| --- | --- |
| 명령어 이름 | `/점검` |
| 사용 대상 | 운영진 |
| 응답 방식 | `ephemeral` 응답 권장 |
| 목적 | 봇 상태, 주요 명령어, 로그 채널, 민감 질문 알림, 운영 체크리스트를 빠르게 확인 |

## 3. 권한 원칙

- 일반 참여자는 `/점검`을 사용할 수 없도록 해야 합니다.
- 권한 기준은 `ManageMessages` 권한 또는 별도 운영진 역할 기준 중 어떤 방식이 운영에 맞는지 검토합니다.
- 결과는 운영진 전용 응답이어야 하며, `ephemeral` 응답을 기본 방향으로 권장합니다.
- 토큰, API Key, 실제 환경변수 값은 절대 표시하지 않습니다.
- 채널 ID 자체를 출력할지 여부는 운영진 검토 후 결정하며, 기본 방향은 노출하지 않는 것입니다.
- 민감 질문 알림 설정 및 점검 결과는 운영진 전용으로만 표시합니다.

## 4. `/점검`에서 보여줄 수 있는 항목

### 포함 후보

- 봇 온라인 여부
- 현재 명령어 안내
- `/안내` 테스트 안내
- `/채널안내` 테스트 안내
- `/질문` 테스트 안내
- `/공지` 권한 확인 안내
- `LOG_CHANNEL_ID` 설정 여부
- `SAFETY_ALERT_CHANNEL_ID` 설정 여부
- 민감 질문 알림 테스트 안내
- Railway Online 확인 안내
- GitHub Actions CI 확인 안내
- `npm run check:release` 로컬 실행 안내

### 표시 원칙

- 환경변수나 채널 관련 정보는 실제 값 대신 설정 여부만 표시하는 방향을 권장합니다.
- Discord API로 직접 확인하기 어렵거나 명령어가 확인 범위를 보장할 수 없는 항목은 `수동 확인 필요`로 표시합니다.
- Railway 상태, GitHub Actions CI 결과, 실제 채널 권한은 외부 화면이나 테스트 계정으로 확인해야 하므로 자동 확인 완료처럼 표시하지 않습니다.

## 5. 추천 출력 구조

아래 문구는 Embed 또는 운영진 전용 메시지의 구성 예시입니다. 구현 시 실제로 확인 가능한 결과와 수동 확인 안내를 구분해 표시합니다.

### 봇 기본 상태

```text
봇 기본 상태
- 봇 응답 상태: 정상 응답 중
- /점검 결과 공개 범위: 운영진 전용 (ephemeral)
- 실제 서버/호스팅 상태: Railway에서 수동 확인 필요
```

### 주요 명령어 테스트

```text
주요 명령어 테스트
- /안내: Discord에서 응답 내용 확인 필요
- /채널안내: 채널 안내 표시 확인 필요
- /질문: 일반 질문 응답 및 fallback 흐름 확인 필요
- /공지: 운영진 권한으로만 사용할 수 있는지 확인 필요
```

### 로그/알림 채널 확인

```text
로그/알림 채널 확인
- LOG_CHANNEL_ID: 설정 여부만 표시
- SAFETY_ALERT_CHANNEL_ID: 설정 여부만 표시
- 실제 채널 접근 권한 및 봇 전송 권한: 수동 확인 필요
- 채널 ID와 환경변수 실제 값: 표시하지 않음
```

### 민감 질문 알림 확인

```text
민감 질문 알림 확인
- 낮은 위험도 테스트 문구로 /질문 알림 흐름 확인 권장
- 알림 대상 채널: 설정 여부에 따른 경로만 안내
- 알림 채널이 운영진 전용인지: 수동 확인 필요
- 자해/자살 표현 테스트: 운영진 내부에서 신중히 진행
```

### 배포/릴리즈 확인

```text
배포/릴리즈 확인
- Railway Online 상태: 수동 확인 필요
- GitHub Actions CI 상태: 수동 확인 필요
- 로컬 사전 검증: npm run check:release 실행 안내
```

### 운영 전 수동 체크

```text
운영 전 수동 체크
- 테스트 계정으로 운영진 전용 채널 비공개 여부 확인
- Discord에서 주요 명령어 응답 확인
- 민감 질문 알림 채널의 공개 범위 확인
- 공지 및 운영 대응 문구 최신 상태 확인
```

## 6. 민감 질문 알림 점검 기준

- `/질문 내용:DM이 불편해요`와 같은 낮은 위험도 테스트 문구를 사용하는 방향을 권장합니다.
- 자해 또는 자살 표현을 포함한 테스트는 운영진 내부에서 필요성과 노출 범위를 검토한 뒤 신중히 진행합니다.
- `SAFETY_ALERT_CHANNEL_ID`가 설정되어 있으면 해당 채널로 운영진 알림을 보내는 흐름을 확인합니다.
- `SAFETY_ALERT_CHANNEL_ID`가 없으면 `LOG_CHANNEL_ID`로 운영진 알림을 보내는 흐름을 확인합니다.
- 두 값이 모두 없으면 알림이 전송되지 않을 수 있음을 점검 결과에서 안내합니다.
- 민감 질문 알림 채널은 운영진 전용이어야 하며, 실제 공개 범위는 Discord 권한에서 수동 확인해야 합니다.

## 7. 구현 시 수정 예상 파일

향후 실제 구현을 진행한다면 아래 파일 변경을 검토할 수 있습니다. 이번 문서 작성 작업에서는 수정하지 않습니다.

- `src/deploy-commands.js`
- `src/handlers.js`
- `src/embeds.js` 또는 별도 helper
- `scripts/check-release.js`
- `docs/operation-guide.md`
- `docs/release-checklist.md`

## 8. 구현 단계 제안

1. 설계 문서를 확정합니다.
2. `/점검` Slash Command를 추가합니다.
3. 운영진 권한 검사를 구현합니다.
4. 점검 Embed를 생성합니다.
5. `check-release`에 문법 검사를 반영합니다.
6. `npm run check:release`를 실행합니다.
7. `npm run deploy`로 Slash Command를 등록합니다.
8. Discord에서 `/점검`을 테스트합니다.

## 9. 구현 시 주의사항

- `/점검`은 운영진 전용이어야 합니다.
- 응답은 `ephemeral` 방식을 권장합니다.
- 실제 환경변수 값은 출력하지 않습니다.
- 민감 질문 알림 테스트는 노출 범위와 필요성을 검토하며 신중히 진행합니다.
- 일반 대화 메시지 감지는 아직 구현하지 않습니다.
- `/점검`이 실제 서버 상태를 모두 자동으로 확인한다고 오해하지 않도록, 확인이 제한되는 항목에는 `수동 확인 필요`를 함께 표시합니다.

- Discord 권한 변경 없음
- 환경변수 변경 없음
