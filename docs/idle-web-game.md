# 방치형 브라우저 미니게임: 간식 공방 키우기

`간식 공방 키우기`는 참여자들이 가볍게 오래 즐길 수 있도록 만든 브라우저용 방치형(키우기) 게임입니다. 던전월드 세계관과는 무관한 독립 게임이며, 매치3 `간식 맞추기`와 같은 밝은 간식/디저트 테마를 공유하는 자매 게임입니다. `public/idle/` 아래의 정적 HTML/CSS/JS 파일로 동작하며, 기존 `검은 종 생존전`([docs/dungeonworld-survivors-web-game.md](dungeonworld-survivors-web-game.md)), `간식 맞추기`([docs/match3-web-game.md](match3-web-game.md))와 동일한 운영 원칙과 서빙 구조를 따릅니다.

## 운영 원칙

- Discord 계정 연동이 없습니다.
- 권장 기기는 모바일입니다. Discord 앱 내 브라우저와 375px 폭을 1차 QA 기준으로 봅니다.
- 포인트 지급 없음, 포인트 차감 없음, 베팅 없음, 랭킹 저장이 없습니다.
- 기존 버튼형 미니게임의 하루 보상 상한과 중복 지급 정책은 변경하지 않습니다.
- `.env` 수정이나 `npm run deploy`가 필요하지 않습니다.
- 진행 상태는 **참여자 브라우저의 localStorage에만** 저장됩니다. 운영 데이터 JSON에는 저장하지 않으며, 서버는 정적 파일만 서빙합니다.
- 기기나 브라우저를 바꾸면 진행 상태가 이어지지 않고 처음부터 시작합니다. 참여자에게 안내할 때 이 점을 알려주세요.

## 플레이 내용

주인공(견습 제빵사)이 길거리 좌판에서 간식 왕국까지 성장하는 방치형 게임입니다. 화면 하단 탭 4개(공방/시설/배달/기록)로 구성되고, 하단 퀘스트 바가 항상 다음 목표를 한 줄로 안내합니다.

- **무대 승급 (6단계)**: 길거리 좌판 → 포장마차 → 동네 가게 → 간식 공방 → 간식 공장 → 간식 왕국. 승급마다 장면 배경과 직함이 바뀌고 새 시설/기능이 열립니다.
- **생산**: 간식 만들기 버튼(클릭)과 생산 시설 6종(딸기 텃밭 🍓, 오렌지 과수원 🍊, 사탕 기계 🍬, 쿠키 오븐 🍪, 컵케이크 스탠드 🧁, 젤리 공장 🍇)으로 간식을 모읍니다. 시설 비용은 보유 수에 따라 지수적으로 증가합니다.
- **업그레이드**: 클릭 생산력 강화, 전체 생산량 배수, 오프라인 수익 상한 연장 등 일회성 구매 5종.
- **간식 배달**: 무대 2부터 시간제 파견 의뢰(5분/1시간/8시간)를 보내고, 완료되면 수령 버튼으로 보상을 받습니다. 동시 진행은 1건이며 오프라인 중에도 타이머가 흐릅니다.
- **황금 간식**: 무대 3부터 화면이 보이는 동안 가끔 나타나는 보너스 탭 대상입니다. 즉시 보상 또는 일시적 클릭 배수 중 하나를 얻습니다. 백그라운드 탭/오프라인에는 나타나지 않습니다.
- **퀘스트 체인**: 순차 진행 20개. 하단 퀘스트 바에서 항상 다음 목표와 보상을 확인할 수 있고, 튜토리얼 역할을 겸합니다.
- **비법 레시피(환생)**: 무대 6(간식 왕국) 도달 후 환생하면 간식·시설·업그레이드·무대·배달이 초기화되고, 누적 생산량에 비례한 비법 레시피를 얻습니다. 레시피 1개당 전체 생산량이 영구적으로 +10%씩 오릅니다. 업적·통계·레시피는 환생해도 유지됩니다.
- **업적 도감**: 12종, 기록 탭에서 확인합니다.
- **오프라인 수익**: 재접속 시 마지막 접속 이후 경과 시간만큼 생산량을 지급합니다(기본 상한 8시간, 야간 요정 업그레이드 구매 시 24시간). 60초 미만 경과는 조용히 지급하고 모달을 띄우지 않습니다. 기기 시계가 되돌아간 경우 오프라인 수익은 0으로 처리됩니다.

## 파일 구성

- `public/idle/index.html` — 마크업, 헤더, 탭 4개 컨테이너, 퀘스트 바, 탭 바, 모달(오프라인/승급/환생/리셋), 토스트 레이어. 공용 디자인 시스템 `public/shared/game-ui.css`를 `styles.css`보다 먼저 로드합니다.
- `public/idle/styles.css` — 매치3과 같은 밝은 파스텔 팔레트, 무대별 장면 스타일, 모바일(375px) 우선 + PC 480px 카드 레이아웃
- `public/idle/content.js` — 무대/시설/업그레이드/배달/퀘스트/업적/황금 간식 등 정의 데이터와 밸런스 상수. DOM에 접근하지 않으며 `window.IdleContent` 전역과 Node `module.exports` 양쪽에서 로드할 수 있습니다.
- `public/idle/engine.js` — 비용·생산·구매·승급·배달·환생·오프라인 수익·저장 직렬화 등 순수 계산 로직. DOM이나 `Date.now()`를 직접 참조하지 않고 시각은 항상 인자로 받습니다. `window.IdleEngine` 전역과 Node `module.exports` 양쪽에서 로드할 수 있습니다.
- `public/idle/game.js` — DOM 렌더링, 탭 전환, 클릭 입력/애니메이션, `requestAnimationFrame` 루프, 황금 간식 스케줄링, localStorage 저장/복원, `visibilitychange` 처리, 모달 제어. 캐릭터·장면 소품 아이콘은 `public/shared/assets/shared-char-baker.svg`와 `match3-tile-*.svg` 재사용([webgame-design-guide.md](webgame-design-guide.md))에 의존합니다.

## 로컬 실행 및 QA

봇 프로세스의 HTTP 서버가 켜져 있는 환경에서는 `/game/idle` 경로로 정적 파일을 서빙합니다. 이 경로는 대시보드 API와 달리 Basic Auth를 요구하지 않습니다.

`ADMIN_DASHBOARD_ENABLED=true`와 관리자 계정 환경 변수를 설정한 뒤 `npm start`로 봇을 실행하고, 브라우저에서 아래 주소를 엽니다(경로 끝의 슬래시를 포함해야 상대 경로 스크립트/스타일이 올바르게 로드됩니다).

```text
http://localhost:3000/game/idle/
```

확인할 사항:

- 퀘스트 바를 따라가는 것만으로 무대 2 승급까지 자연스럽게 도달하는지.
- 승급 시 장면·직함이 바뀌고 새 시설이 열리는지. 시설 구매 시 장면에 소품이 추가되는지.
- 배달을 보내고 탭을 닫았다가 소요 시간 뒤 재접속하면 수령 대기 상태로 보이는지.
- 황금 간식이 무대 3부터 나타나고 탭 시 보너스가 적용되는지.
- 오프라인 수익: 저장 데이터(`localStorage`의 `redefine-idle-save-v1` 키)의 `lastSeenAt`을 과거로 수정한 뒤 새로고침해 지급량과 상한(8시간/24시간)을 확인.
- 환생: 무대 6 도달 후 확인 모달 → 레시피 획득 → 초기화 후 생산 보너스가 반영되는지.
- 새로고침 후 상태가 유지되는지(localStorage 복원), `처음부터 다시 시작`이 정상 동작하는지.
- 모바일 뷰포트(375px)와 PC 화면 모두에서 탭 4개가 정상적으로 조작 가능한지.

## 배포 메모

정적 파일과 문서만 바뀐 경우에는 Slash Command 구조가 바뀌지 않으므로 `npm run deploy`를 실행하지 않습니다. 운영자가 실제 참여자에게 공개 URL을 안내하려면 먼저 Railway/정적 호스팅 경로에서 `public/idle/`이 접근 가능한지 확인해 주세요. 진행 상태가 참여자 브라우저의 localStorage에만 저장되므로, 기기·브라우저를 바꾸면 처음부터 다시 시작한다는 점을 안내에 포함해 주세요.
