# 운영자 명령어 가이드

운영자 명령어는 `ManageMessages` 또는 `Administrator` 권한이 있는 운영진이 사용하는 것을 기준으로 합니다. 처리 결과에는 참여자 정보, 포인트, 인증 내용, 운영 메모가 포함될 수 있으므로 운영진 전용 채널과 개인 응답 중심으로 확인합니다.

## 전체 목록

| 명령어 | 목적 | 주요 옵션 |
| --- | --- | --- |
| `/공지` | 복사용 공지 템플릿 확인 | `종류` |
| `/포인트관리` | 포인트 지급, 차감, 정정 | `대상`, `증감`, `사유` |
| `/교환관리` | 교환 신청 지급완료, 취소, 환불완료 처리 | `신청id`, `처리`, `메모` |
| `/포인트로그` | 포인트 거래 로그 조회 | `사용자`, `종류`, `개수` |
| `/인증관리` | 미션 인증 승인 또는 반려 | `제출id`, `처리`, `메모` |
| `/운영현황` | 운영 대기열과 현황 요약 | `종류`, `개수` |
| `/미션관리` | 미션 목록, 추가, 수정, 상태 변경 | `작업`, `미션id`, `제목`, `설명`, `포인트`, `인증필요`, `날짜`, `메모` |
| `/상점관리` | 상점 항목 목록, 추가, 수정, 상태 변경 | `작업`, `항목id`, `이름`, `설명`, `비용`, `재고`, `월한도`, `유형`, `메모` |
| `/운영내보내기` | 운영 데이터 요약 또는 파일 백업 | `종류`, `형식`, `개수` |

## `/공지`

언제 사용하나:

- 운영진이 일정, 봇 사용 안내, 미니게임 허브, 입장 안내, 리마인드, 준비물, 결석 안내 같은 공지 초안이나 버튼 허브를 확인할 때 사용합니다.

기본 사용 흐름:

1. `/공지 종류:...`를 실행합니다.
2. 표시된 문구를 실제 날짜, 장소, 링크에 맞게 확인합니다.
3. 참여자 공지 채널에 필요한 내용만 게시합니다.

미니게임 허브:

- `MINIGAME_CHANNEL_ID`로 지정한 미니게임 채널에서 `/공지 종류:미니게임허브`를 실행하면 참여자가 누를 수 있는 미니게임 버튼 허브가 공개 메시지로 게시됩니다.
- 지정 채널이 아닌 곳에서 실행하면 private/ephemeral 채널 안내만 표시됩니다.
- `/공지` 선택지에 `미니게임허브`가 보이지 않으면 운영 환경에서 `npm run deploy`로 Slash Command를 갱신합니다.

확인해야 할 점:

- 확정되지 않은 일정이나 링크가 들어 있지 않은지 확인합니다.
- 공지 대상과 게시 채널이 맞는지 확인합니다.

실수 방지 포인트:

- 템플릿을 그대로 게시하기 전에 날짜, 장소, 링크, 채널명을 다시 봅니다.
- 실제 토큰, 채널 ID, 내부 운영 메모를 공지에 포함하지 않습니다.

## `/포인트관리`

언제 사용하나:

- 운영자가 사유 있는 수동 지급, 차감, 누락 보정, 오류 정정을 처리할 때 사용합니다.

기본 사용 흐름:

1. 대상 참여자를 선택합니다.
2. 지급은 양수, 차감은 음수로 `증감`을 입력합니다.
3. 운영자가 나중에 이해할 수 있는 `사유`를 남깁니다.
4. `/포인트로그`로 거래가 남았는지 확인합니다.

확인해야 할 점:

- 대상 사용자가 맞는지 확인합니다.
- 음수 입력 시 잔액이 부족하지 않은지 확인합니다.
- 사유가 너무 짧거나 모호하지 않은지 확인합니다.

실수 방지 포인트:

- 잘못 지급한 기록은 삭제하지 않고 반대 거래나 정정 사유로 남깁니다.
- 참여자 비교나 순위 운영으로 보이지 않게 포인트를 안내합니다.

## `/교환관리`

언제 사용하나:

- `/교환`으로 접수된 대기 신청을 실제 지급 후 완료하거나, 예외 상황으로 취소/환불 처리할 때 사용합니다.

기본 사용 흐름:

1. `/운영현황 종류:교환대기`로 신청 ID를 확인합니다.
2. 실제 청년동 포인트 또는 리워드를 지급합니다.
3. 지급이 끝난 신청만 `/교환관리 신청id:... 처리:지급완료`로 처리합니다.
4. 지급 불가, 중복 신청, 시스템 오류 등 예외 상황은 취소 또는 환불완료로 처리하고 메모를 남깁니다.

확인해야 할 점:

- `지급완료`는 실제 지급이 끝난 뒤에만 처리합니다.
- `취소`와 `환불완료`는 단순 변심용이 아니라 시스템 오류, 중복 신청, 운영진 사유 등 예외 상황용입니다.
- 환불이 필요한 신청은 반환 거래가 남았는지 확인합니다.

실수 방지 포인트:

- 신청 ID를 복사할 때 앞뒤 공백이나 다른 신청 ID가 섞이지 않았는지 확인합니다.
- 청년동 포인트 전환권은 현금 환급이나 외부 재화 교환처럼 안내하지 않습니다.

## `/포인트로그`

언제 사용하나:

- 지급, 차감, 교환, 환불, 정정 이력을 확인할 때 사용합니다.

기본 사용 흐름:

1. 필요하면 `사용자`나 `종류`를 지정합니다.
2. 최근 몇 건을 볼지 `개수`를 정합니다.
3. 거래 ID, 사유, 관련 신청/제출 ID를 확인합니다.

확인해야 할 점:

- 교환 차감과 환불이 같은 신청 ID에 연결되어 있는지 확인합니다.
- 수동 정정에는 운영 사유가 남아 있어야 합니다.

실수 방지 포인트:

- 로그 내용을 공개 채널에 옮기지 않습니다.
- 운영 확인에 필요한 최소 정보만 공유합니다.

## `/인증관리`

언제 사용하나:

- 참여자가 `/인증`으로 제출한 미션 수행 내용을 승인하거나 반려할 때 사용합니다.

기본 사용 흐름:

1. `/운영현황 종류:인증대기`로 제출 ID를 확인합니다.
2. 제출 내용이 미션 기준에 맞는지 확인합니다.
3. 승인 또는 반려를 선택하고 필요한 경우 메모를 남깁니다.
4. 승인 후 `/포인트로그` 또는 `/운영현황`으로 지급 결과를 확인합니다.

확인해야 할 점:

- `/인증관리` 승인은 포인트 지급과 연결됩니다.
- 반려 메모는 참여자를 평가하거나 낙인찍는 표현이 아니라 확인이 필요한 내용을 중심으로 씁니다.
- 과도한 개인정보가 제출된 경우 운영진 내부 기준에 따라 보관과 삭제 필요성을 확인합니다.

실수 방지 포인트:

- 이미 처리된 제출을 다시 승인하지 않습니다.
- 미션 ID와 제출 ID를 혼동하지 않습니다.

## `/운영현황`

언제 사용하나:

- 운영 중 대기 중인 교환, 인증, 활성 미션, 상점 항목, 최근 로그를 빠르게 확인할 때 사용합니다.

기본 사용 흐름:

1. 운영 시작 전 `종류:요약`으로 전체 상태를 확인합니다.
2. 대기 건이 있으면 `교환대기` 또는 `인증대기`로 상세 ID를 확인합니다.
3. 필요한 후속 명령어로 처리합니다.

확인해야 할 점:

- 장기 `pending` 상태가 쌓이지 않는지 확인합니다.
- 활성 미션과 상점 항목이 실제 공지와 맞는지 확인합니다.

실수 방지 포인트:

- 현황 확인만으로 실제 지급이나 승인 처리가 완료된 것으로 보지 않습니다.

## `/미션관리`

언제 사용하나:

- 미션을 만들고 참여자에게 노출하거나, 기간 종료 후 숨길 때 사용합니다.

기본 사용 흐름:

1. `작업:추가`로 제목, 설명, 포인트, 인증 필요 여부를 입력합니다.
2. 운영 기준을 확인한 뒤 `작업:활성화`로 참여자에게 노출합니다.
3. 운영 중 수정이 필요하면 `작업:수정`을 사용합니다.
4. 일시 중단은 `작업:일시중지`, 종료는 `작업:종료`로 처리합니다.

확인해야 할 점:

- 미션 설명에 기간, 인증 기준, 보상 포인트가 충분히 적혀 있는지 확인합니다.
- 인증에 필요한 개인정보를 과도하게 요구하지 않습니다.

실수 방지 포인트:

- 초안 미션을 바로 활성화하지 않습니다.
- 포인트 수량을 잘못 입력하면 승인 시 지급에 직접 영향을 줍니다.

## `/상점관리`

언제 사용하나:

- 교환 가능한 리워드나 청년동 포인트 전환권을 만들고 운영 상태를 바꿀 때 사용합니다.

기본 사용 흐름:

1. `작업:추가`로 이름, 설명, 비용, 재고, 월한도, 유형을 입력합니다.
2. 운영 기준과 재고를 확인한 뒤 `작업:활성화`합니다.
3. 지급 불가 상태가 되면 `일시중지`, `품절`, `숨김` 중 맞는 상태로 변경합니다.

확인해야 할 점:

- 비용, 재고, 월한도, 지급 소요 시간을 실제 운영 기준과 맞춥니다.
- 청년동 포인트 항목은 청년동 내부 사용처용임을 설명합니다.

실수 방지 포인트:

- 비용을 낮게 잘못 입력하면 신청 즉시 포인트가 차감될 수 있습니다.
- 비활성 항목이 참여자에게 노출되지 않는지 확인합니다.

## `/운영내보내기`

언제 사용하나:

- 운영 데이터 백업, 정산 확인, 문제 발생 전후 상태 보존이 필요할 때 사용합니다.

기본 사용 흐름:

1. 빠른 확인은 `종류:요약 형식:요약`으로 봅니다.
2. 백업은 `종류:전체 형식:JSON`을 기본으로 받습니다.
3. 스프레드시트 검토가 필요하면 필요한 종류만 `형식:CSV`로 받습니다.
4. 파일을 내부 저장소에 날짜가 드러나는 이름으로 보관합니다.

확인해야 할 점:

- `/운영내보내기` 결과에는 개인정보나 운영 데이터가 포함될 수 있으므로 외부 공유에 주의합니다.
- 공유 전 사용자 ID, 표시 이름, 인증 내용, 운영 메모 포함 여부를 확인합니다.

실수 방지 포인트:

- 공개 채널이나 접근 권한이 불명확한 드라이브에 백업 파일을 올리지 않습니다.
- 전체 JSON이 필요하지 않은 상황에서는 범위를 줄인 CSV를 공유합니다.
