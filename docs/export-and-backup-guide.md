# 운영 데이터 내보내기 및 백업 가이드

이 문서는 `/운영내보내기`로 여정 포인트 운영 데이터를 확인하고 백업하는 방법을 정리합니다.

## 목적

`/운영내보내기`는 local JSON 기반 MVP 운영 중 데이터 유실 위험을 줄이기 위한 운영자 전용 명령어입니다. 운영자는 디스코드 안에서 포인트 거래, 교환 신청, 인증 제출, 미션 설정, 상점 설정, 운영 요약을 확인하거나 파일로 내려받을 수 있습니다.

## 내보낼 수 있는 데이터

- 전체: 포인트, 교환, 인증, 미션, 상점 데이터를 한 번에 JSON 중심으로 백업합니다.
- 포인트: 포인트 거래 로그와 운영 확인에 필요한 사용자 정보를 포함합니다.
- 교환: 교환 신청, 처리 상태, 연결 거래 ID를 포함합니다.
- 인증: 인증 제출, 상태, 검토자, 지급 거래 ID를 포함합니다.
- 미션: 미션 설정, 상태, 지급 포인트를 포함합니다.
- 상점: 상점 항목, 비용, 재고, 상태를 포함합니다.
- 요약: 전체 건수와 대기 건수를 빠르게 확인합니다.

## 형식

- 요약: Discord ephemeral 메시지로 핵심 수량과 주의사항을 확인합니다.
- JSON: 백업과 복구 참고에 적합한 구조화 파일입니다. 사용자 ID와 제출 내용이 포함될 수 있습니다.
- CSV: 스프레드시트에서 빠르게 검토하기 쉬운 표 형식입니다. 객체나 배열은 짧은 JSON 문자열로 들어갈 수 있습니다.

## 개인정보 및 보관 주의사항

내보낸 파일에는 사용자 ID, 표시 이름, 인증 내용, 포인트 기록, 운영 메모가 포함될 수 있습니다. 파일은 운영진 내부 저장소에만 보관하고, 외부 공유 전에는 개인정보와 제출 원문 포함 여부를 반드시 확인합니다.

백업 파일을 공개 채널, 개인 메신저, 접근 권한이 불명확한 드라이브에 올리지 않습니다. 행사 종료 후 보관 기간과 삭제 기준은 운영진 정책에 맞춰 별도로 정합니다.

## local JSON 저장소 주의

`data/*.local.json`은 MVP 운영 데이터 파일이며 커밋하지 않습니다. Railway 재배포, 재시작, 환경 변경 시 데이터가 유지되는 방식은 운영 전에 반드시 확인해야 합니다.

이번 단계는 장기 저장소 전환 전 임시 백업과 출력 형식 정리입니다. 실제 운영 전 또는 운영 규모가 커지는 시점에는 Google Sheets 보조 정산이나 PostgreSQL 같은 영속 저장소를 별도 단계로 검토합니다.

## 추천 운영 루틴

- 행사 전 백업: 운영 시작 직전 `/운영내보내기 종류:전체 형식:JSON`을 실행합니다.
- 행사 후 백업: 당일 운영 종료 후 전체 JSON과 필요한 CSV를 저장합니다.
- 주 1회 백업: 장기 운영 중에는 정해진 요일에 전체 JSON을 보관합니다.
- 교환 처리 전후 백업: 대량 교환 처리 전과 후에 교환 CSV 또는 전체 JSON을 저장합니다.
- 이슈 발생 시 백업: 포인트 정정, 환불, 누락 지급을 처리하기 전 현재 상태를 남깁니다.

## 파일 공유 시 주의사항

정산 담당자에게 전달할 때도 최소한의 범위만 공유합니다. CSV가 충분하면 전체 JSON 대신 해당 종류 CSV를 공유합니다. 파일명과 저장 위치에 날짜를 남겨 중복 백업을 구분합니다.

## 다음 단계

`/운영내보내기`는 Google Sheets 또는 PostgreSQL 연동 전 중간 단계입니다. 운영진이 반복적으로 스프레드시트 확인을 해야 하거나 local JSON 보관이 불안정해지면 외부 저장소 연동을 별도 작업으로 검토합니다.
