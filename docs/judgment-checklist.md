# 판단 기준 체크리스트 (redefine-discord-bot)

세션 기록에서 반복적으로 내려진 판단들을 정리한 참조 문서 (단일 원본).
plan-doc / codex-brief / sandwich-review 스킬이 이 문서를 인용한다.

## 착수 판단

- [ ] 이 작업의 계획서가 승인됐는가? 미승인이면 구현하지 말고 계획서부터.
- [ ] 착수 게이트가 있는가? (예: "종반 도달 참여자가 실제로 있는가") 데이터로 확인 후 착수.
- [ ] 금기(CLAUDE.md 안티패턴)를 깨는 작업인가? → 계획서에 별도 절로 명시하고 사용자 승인 + 안전장치 3종(env 게이트 기본 off · 감사 로그 · 확인 절차/중복 방지) 동반.
- [ ] 구조(스키마·로그 형식)를 바꾸는 부수 작업이 끼어 있는가? → 분리해서 보류 목록에 명시.

## 구현 방식 선택

- 분석·계획·리뷰 = 상위 모델(Fable), 구현 = 코덱스 또는 하위 모델 (샌드위치).
- 코드 로직 0줄로 데이터/콘텐츠만 추가해서 되는 일인지 먼저 확인 (기존 확장 지점 주석 탐색).
- 새로 만들기 전에 미러링할 기존 패턴을 찾는다 (예: local/example 저장 패턴, 정적 서빙 패턴).

## PR vs 직접 푸시

- 기능 작업 → feature 브랜치 + PR (트렁크 기반 관례).
- 이미 로컬 main에 있는 문서 커밋 + 리뷰 완료된 fix → 직접 푸시 가능 (사용자 확인 후).
- 계획서 단계에서 열린 PR이 있으면 새 PR 만들지 말고 그 PR 갱신.

## 리베이스·충돌 해소 (사이에 다른 PR이 머지됐을 때)

1. 새 main 기준선에서 `check:release` 통과 확인 (클린 베이스 확보)
2. 리베이스 → 충돌은 "양쪽 다 살리기"가 기본, 로직 삭제·덮어쓰기 금지
3. 해소 후: 충돌 마커 grep → 양쪽 함수/export 존재 grep → 문법 검사 → 전체 게이트
4. diff 범위를 main 대비로 확인 — 다른 PR의 파일·연동을 건드리지 않았는지
5. 머지 후 main에서 게이트 재실행 + **다른 PR들의 전용 스모크 테스트를 명시적으로 직접 실행**

## 머지 후 후속 조치 판정

- `deploy-commands.js` 변경 → `npm run deploy` 필요. 보고에 "실행 전까지의 증상"까지 적는다.
- env 변수 추가 → `.env.example` + 관련 문서 갱신 + Railway 변수 등록 안내.
- 정적 파일·라우트만 → 후속 조치 없음 (그것도 명시).

## Railway/배포 변경

- 적용 직전 "N changes to apply" 스테이징 화면에서 **의도한 변경만 있는지** 확인 후 적용.
- 적용 후: 유지돼야 할 항목(볼륨 연결, 핵심 env, replica 수) 무변경 확인 + 배포 ACTIVE 확인.
- 배포 후 Discord에서 `/운영전점검` 실행 권고.

## 보고 형식 (모든 작업 공통)

- 한국어. 결론 먼저. 변경 전/후는 표로.
- 검증은 "실행한 명령 + 출력에서 확인한 사실"만 적는다.
- 커밋/푸시/PR 상태를 항상 명시 ("커밋은 하지 않았습니다").
- 롤백 방법 한 줄 + 다음 단계 제안으로 끝맺음.
- 사용자 결정이 필요한 값은 기본값을 제안하며 목록으로.

## 잘 작동하는지 확인하는 테스트

- 최근 머지된 PR 3개를 골라, 이 체크리스트를 하위 모델에게 주고 각 PR에서
  "머지 후 후속 조치"와 "PR vs 직접 푸시" 판정을 재현시킨다. 실제 세션의 판단과
  일치하면 통과. 불일치 항목은 기준 문구가 모호한 것이므로 해당 줄을 구체화한다.
