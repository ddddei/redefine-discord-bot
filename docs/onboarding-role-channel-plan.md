# 프로젝트 리디파인 72시간 온보딩 역할/채널 구조 설계안

## 문서 목적

사전 설문 및 선발 이후, 참여자의 고립·은둔 척도와 참여 가능성에 따라 디스코드 온보딩 밀도를 다르게 설계하기 위한 내부 운영 문서입니다.

이 문서는 역할과 채널 공개 구조를 정리하기 위한 설계안이며, 실제 Discord 권한 설정이나 봇 코드 변경을 포함하지 않습니다.

## 실제 반영 v1 메모

이번 v1 반영은 실제 Discord 역할, 채널, 권한 설정을 변경하지 않고 봇 안내 문구와 데이터, FAQ, Knowledge, 테스트 질문, 운영 문서에만 먼저 반영합니다.

따라서 이 문서의 역할/채널 구조는 운영 설계 기준으로 유지하되, 실제 서버 권한 변경은 별도 검토와 운영진 확인 이후 진행합니다.

## 1. 운영 전제

- 사전 설문 작성자가 100명을 넘을 수 있습니다.
- 사전 설문과 척도 결과를 바탕으로 최종 참여자 60명을 선발합니다.
- 선발된 60명만 디스코드에 초대하는 구조를 기준으로 합니다.
- 72시간 온보딩은 디스코드 입장 이후 OT 전 적응과 이탈 방지를 위한 과정입니다.
- 세부 선발 기준과 척도 해석은 운영진 내부 기준을 따릅니다.

## 2. 설계 원칙

- 참여자에게 고립·은둔 척도나 위험도를 직접 드러내지 않습니다.
- 역할명은 낙인 없는 중립적 표현을 사용합니다.
- 참여를 강요하지 않고 진입 깊이를 다르게 열어줍니다.
- 척도가 높은 참여자에게는 챗봇보다 운영진 연결과 밀착 확인을 우선합니다.
- 처음부터 모든 채널을 노출하지 않습니다.
- 읽기, 이모지 반응, 짧은 질문도 참여 방식으로 인정합니다.

## 3. 내부 분류와 공개 역할명

### 내부 운영 분류

- A. 밀착 온보딩 필요
- B. 기본 온보딩
- C. 활동형 온보딩

### 디스코드 공개 역할명 예시

- @온보딩-천천히
- @온보딩-기본
- @온보딩-활동
- @참여자
- @운영진

위 역할명은 운영진 검토를 거쳐 필요 시 더 부드러운 이름으로 바꿀 수 있습니다.

## 4. 역할별 목적

### @온보딩-천천히

- 척도가 높거나 진입 부담이 큰 참여자를 위한 역할입니다.
- 읽기, 문의, 익명 질문, 운영진 연결을 중심으로 안내합니다.
- 자유채팅, 포인트, 미션을 초반부터 강하게 노출하지 않습니다.

### @온보딩-기본

- 중간 정도의 참여자를 위한 역할입니다.
- 공지 확인, 가벼운 채팅, 질문, 미션 확인까지 가능하게 합니다.
- 활동을 강요하지 않습니다.

### @온보딩-활동

- 비교적 활동 가능성이 높은 참여자를 위한 역할입니다.
- 자유채팅, 챌린지, 출석, 포인트 등 활동 채널까지 점진적으로 노출합니다.
- 단, 경쟁이나 과한 친목은 방지합니다.

## 5. 역할별 채널 공개 예시

### 공통 채널

- #환영-인사와-규칙
- #참여동의-확인
- #이름표-색상-고르기
- #프로젝트공지_일정및안내
- #공지_관리자-공지

- #처음-안내

- #운영진-문의 또는 #문의하기
- 봇 사용 가능
- 필요 시 자유채팅방은 숨기거나 읽기 전용으로 검토합니다.

### @온보딩-기본

- #환영해주세요
- #자유채팅방
- #익명고민채널
- #오늘의-미션
- #매일출석체크

### @온보딩-활동

- #자유채팅방
- #매일-챌린지

- #매일출석체크
- #포인트-상점

- #랭킹확인
- 음성채널은 필요 시 단계적으로 공개합니다.

- #봇-질문로그
- #운영진-문의대응
- 익명고민 관리 채널
- 일반 참여자에게 보이지 않아야 합니다.

## 6. 72시간 온보딩 흐름

### 0~24시간

- 서버 적응
- 공지 확인
- 참여동의 확인
- 이름표/색상 선택
- /안내 사용
- 모든 채널을 다 보지 않아도 된다는 메시지 안내

### 24~48시간

- /채널안내 확인
- /질문 사용해보기
- 필요 시 익명고민채널 또는 문의 채널 사용
- 온보딩 역할별로 자유채팅, 미션, 출석 노출 범위 조절

### 48~72시간

- OT 전 확인사항 안내
- 참여 부담 확인
- 운영진 문의 유도
- 온보딩 이후 역할 전환 여부 판단
- 척도가 높은 참여자는 온보딩 연장 또는 운영진 확인 검토

## 7. 챗봇의 역할

- 기본 안내
- FAQ/Knowledge 기반 질문 응답
- 채널 안내
- 커뮤니티 약속 안내
- 미응답 질문 로그 기록
- 척도가 높은 참여자에게는 판단이나 상담이 아니라 운영진 문의로 연결
- 위기 표현, 개인정보, 민감한 내용은 자동 답변보다 운영진 확인 우선

## 8. 안내 문구 수정 방향

향후 실제 운영 구조를 반영할 때 수정이 필요한 봇/데이터 항목은 다음과 같습니다.

- /안내 문구
- /채널안내 문구
- data/channels.json
- data/faq.json
- data/knowledge.json
- participant-notice-pack.md
- operator-response-templates.md
- release-checklist.md

## 9. 추후 구현 단계

1. 역할/채널 구조 문서 확정
2. 실제 Discord 역할 생성
3. 채널 권한 설정
4. data/channels.json 수정
5. /안내, /채널안내 문구 수정
6. FAQ/Knowledge 온보딩 관련 문구 수정
7. 운영진 테스트
8. 참여자 입장 전 릴리즈 체크

## 10. 주의사항

- 역할명이 참여자에게 낙인처럼 보이지 않게 합니다.
- 척도 결과를 공개하지 않습니다.
- 고척도 참여자에게 활동 채널을 무리하게 열지 않습니다.
- 챗봇이 상담이나 위기 판단을 대신하지 않습니다.
- 운영진 내부 기록은 최소화하고 안전하게 관리합니다.
- 실제 권한 설정 전 반드시 운영진과 검토합니다.
