# 웹게임 디자인 고도화 v2 계획서 — 무드 결정 → 가이드 → SVG 에셋 → 적용

이 문서는 디자인 리프레시 v1([webgame-design-refresh-plan.md](webgame-design-refresh-plan.md), PR #57)의 후속 계획입니다. v1이 "정리·통일"이었다면 v2는 **아이덴티티** — 이모지를 벗어난 고유 비주얼을 만듭니다. 구현 전 [webgame-design-audit.md](webgame-design-audit.md)와 저장소 [AGENTS.md](../AGENTS.md), [src/AGENTS.md](../src/AGENTS.md), [scripts/AGENTS.md](../scripts/AGENTS.md)를 먼저 읽어 주세요.

## 0. 선행 조건과 운영 원칙

- PR #57(디자인 리프레시 v1)이 `main`에 머지된 뒤 진행. 브랜치: `feat/webgame-design-v2`
- 순수 정적 파일 원칙 유지: 빌드 도구·npm 의존성 금지. **에셋은 SVG(텍스트 파일)만** — 래스터 이미지(png/jpg)·웹폰트 파일은 v2 범위 밖.
- 게임 로직 무변경: `board.js`/`engine.js`/`content.js`의 로직은 수정 금지. 단, **표시용 데이터 필드 추가**(예: 적 정의에 `asset` 파일명)는 허용 — 로직 스모크 테스트가 무수정 통과해야 한다는 조건은 동일.
- `.env`·`npm run deploy` 불필요. 생존전(`public/dungeonworld-survivors/`)은 범위 밖.
- 카피·연출 톤: 차분하고 직접적 (기존 원칙).

## 1. 진행 구조 — 4단계, 중간 승인 지점 1회

```
1단계: 무드/방향 시안 (Fable 직접) ──▶ [사용자 선택] ──▶ 2~4단계: 가이드·에셋·적용 (샌드위치)
```

스타일 방향은 취향 결정이라 코드 리뷰로 대체할 수 없습니다. 1단계에서 시안을 보고 방향을 고른 뒤에 본작업에 들어갑니다.

## 2. 1단계 — 무드/방향 시안 (사용자 선택 지점)

같은 샘플 3종(매치3 딸기 타일, 덱 적 `부스러기 개미`, 공용 주인공 `견습 제빵사`)을 **스타일 방향 3안**으로 각각 그려 한 화면에서 비교합니다.

| 방향 | 컨셉 | 특징 |
| --- | --- | --- |
| A. 소프트 플랫 | 쿠키런 킹덤 UI에 가까운 말랑한 플랫 | 외곽선 없음, 넓은 면, 부드러운 하이라이트. 파스텔과 가장 잘 어울림 |
| B. 라인 캐릭터 | 두꺼운 초콜릿색 외곽선 + 플랫 채색 | 스티커/이모티콘 느낌, 표정 강조. 작게 그려도 또렷함 |
| C. 젤리 글로시 | 반투명 그라디언트 + 광택 하이라이트 | 사탕/젤리 질감, 통통 튀는 느낌. 그리기 난이도 높음 |

- 산출물: `scratch` 성격의 비교 페이지 1장(브랜치 내 임시 파일, 최종 PR에서 제거) 또는 스크린샷 보고. 각 안은 동일 크기·동일 배경에서 비교.
- 사용자가 1안을 선택(혼합 지시 가능: "A 기반 + B의 표정")하면 그 결정을 3단계 가이드에 명문화.
- 이 단계는 Fable이 직접 수행 (SVG 시안 품질 편차를 줄이기 위해).

## 3. 2단계 — 디자인 가이드 문서 + 토큰 확장

### `docs/webgame-design-guide.md` (신규)

선택된 방향을 규칙으로 명문화. 이후 모든 에셋·신규 게임이 따르는 기준 문서.

- **일러스트 스타일 규칙**: 외곽선 유무/두께·색, 팔레트(면당 색 수 제한, 하이라이트/섀도 규칙), 모서리 곡률, 표정 규칙(눈·볼터치 등), viewBox 표준(예: 64×64), 최소 표시 크기에서의 가독성 기준
- **게임별 서브 팔레트**: 공통 파스텔 기반 위에 게임별 강조색 1~2개 (매치3=현행 타일 팔레트 정리, 방치형=골드/웜톤, 덱=전투용 쿨톤 소량)
- **모션 원칙**: 무엇을 움직이는가(피드백·보상 순간만), 지속시간 상한, 이징 표준, reduced-motion 정책 — v1 구현을 원칙으로 승격
- **에셋 파일 규칙**: 파일명(`{게임|shared}-{종류}-{이름}.svg`), 저장 위치, `currentColor`/CSS 변수 활용 여부, 접근성(role/aria 처리)

### `public/shared/game-ui.css` 토큰 확장

- 게임별 서브 팔레트 변수(`--m3-*`, `--idle-*`, `--deck-*` 또는 게임 CSS로 위임 — 가이드에서 결정)
- 에셋 표시 크기 스케일(`--asset-sm/md/lg`)

## 4. 3단계 — SVG 에셋 제작 (`public/shared/assets/`)

기존 `/game/shared` 라우트로 서빙되므로 서버 변경 불필요. 각 게임에서 `../shared/assets/*.svg` 상대 경로 `<img>` 참조 (색을 CSS로 제어해야 하는 경우에만 인라인 SVG).

### 에셋 인벤토리 (총 20종 — 이 수량을 넘기지 않는다)

| 대상 | 수량 | 내용 |
| --- | --- | --- |
| 공용 주인공 | 1 | 견습 제빵사 캐릭터 (방치형 클릭 버튼·덱 플레이어 영역 공용) |
| 매치3 타일 | 6 | 딸기·오렌지·사탕·쿠키·컵케이크·젤리 (기존 타일 배경색과 세트) |
| 덱 적 | 9 | 부스러기 개미 ~ 대왕 식탐 드래곤 (등급별 크기 차등: 일반<정예<보스) |
| 덱 카드 타입 아이콘 | 3 | 공격/방어/스킬 (카드 우상단 소형 아이콘) |
| 방치형 시설 소품 | 재사용 | 매치3 타일 6종을 장면 소품으로 재사용 (신규 제작 없음 — 세계관 통일 효과) |

- 무대 배경(방치형)은 SVG 일러스트가 아니라 **CSS 그라디언트 + 타일 소품 배치**로 유지 (배경 일러스트 6종은 볼륨 폭발 지점이라 v3 후보).
- 모든 에셋은 가이드의 스타일 규칙 준수. 리뷰 시 스타일 이탈(선 두께·팔레트 위반)을 확인.

## 5. 4단계 — 게임별 적용

- **매치3**: 타일 이모지 → SVG 교체. 타일 크기·매치 판정에 영향 없어야 함(`board.js` 무변경, `game.js` 렌더링만). `?seed=42` 결정성 유지.
- **방치형**: 클릭 버튼 캐릭터·장면 소품 이모지 → SVG. 이모지 폴백 불필요(SVG는 정적 파일이라 로드 실패 시나리오는 404뿐).
- **덱**: 적 이모지 → SVG (content.js의 `emoji` 필드 옆에 `asset` 필드 추가 — 표시용 데이터라 로직 테스트 영향 없음), 카드에 타입 아이콘 추가. 피격 흔들림 등 v1 연출은 SVG에도 동일 적용.
- 교체 후 이모지 잔존 여부 점검 (의도적으로 남기는 곳: 런 트랙 노드 아이콘·황금 간식 등 소형 장식은 유지 가능 — 가이드에서 결정).

## 6. 테스트

- **신규 `scripts/test-design-assets-static.js`**: `public/shared/assets/`에 인벤토리 19개(재사용 제외) 전부 존재, 각 SVG가 `<svg`로 시작하고 `viewBox` 보유, 파일명 규칙 준수, 각 게임 HTML/JS가 참조하는 에셋 경로가 실재하는지 순회 검증. `check-release.js` 등록.
- 기존 로직 테스트 3본 무수정 통과 (deck `content.js`에 `asset` 필드를 추가해도 통과해야 함 — 실패 시 필드 추가 방식 재검토).
- 수동 QA: 3종 데스크톱·모바일에서 에셋 렌더링(선명도·크기), 매치3 시드 결정성, 덱 연출 유지, 콘솔 404 없음.

## 7. 커밋/PR 구성

- 1단계 시안은 커밋하지 않음 (선택 후 폐기, 결정 사항만 가이드에 기록).
- 권장 커밋 5개: ① 디자인 가이드 문서 + 토큰 확장 ② SVG 에셋 전량 + 에셋 정적 테스트/게이트 ③ 매치3 적용 ④ 방치형 적용 ⑤ 덱 적용 + 문서 갱신. PR 하나, 본문 한국어.
- 2~4단계는 샌드위치 방식(Sonnet 구현 → Fable 리뷰). 단 **에셋 제작(커밋 ②)의 스타일 준수 여부는 Fable이 렌더링 스크린샷으로 전수 확인**하고, 이탈 에셋은 Fable이 직접 수정.

## 8. 영향 범위 / 롤백 / v3 후보

- **영향 범위**: 시각 전용. 서버 라우트 변경 없음(기존 `/game/shared` 사용). 저장 스키마·로직 무변경.
- **롤백**: PR 머지 커밋 revert 한 번.
- **v3 후보**: 방치형 무대 배경 일러스트 6종, 덱 카드 일러스트(카드별 개별 아트 — 21종이라 대형), 웹폰트(Pretendard 번들 — 용량 정책 결정 필요), 사운드, 생존전 리디자인.
