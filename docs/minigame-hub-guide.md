# 미니게임 허브 운영 가이드

## 1. 미니게임 허브 개요

미니게임 허브는 참여자가 Discord 안에서 버튼만 눌러 가볍게 즐길 수 있는 MVP 기능입니다. 새 Slash Command는 추가하지 않았고, 기존 `/안내` 참여자 메뉴의 `미니게임` 버튼에서 진입합니다.

이번 MVP의 목적은 참여를 돕는 가벼운 놀이 흐름을 만드는 것입니다. 포인트 베팅, 포인트 차감, 반복 파밍 구조는 넣지 않았습니다.

운영 채널명은 기존 `#포인트로게임하기` 대신 앞으로 `#미니게임-놀이터` 기준으로 안내합니다. 봇 기능 자체는 채널 ID에 묶여 있지 않으며, 참여자는 `/안내`에서 본인에게만 보이는 메뉴로 접근합니다.

## 2. 참여자 사용 방법

1. Discord에서 `/안내`를 입력합니다.
2. 참여자 메뉴에서 `미니게임` 버튼을 누릅니다.
3. `오늘의 보물상자`, `가위바위보`, `주사위 대결` 중 하나를 선택합니다.
4. 결과와 포인트 지급 여부는 private/ephemeral 응답으로 확인합니다.
5. 같은 날짜에 같은 게임 보상은 다시 지급되지 않습니다.

## 3. 게임별 규칙

### 오늘의 보물상자

- 하루 1회 열 수 있습니다.
- 결과는 0P, 3P, 5P, 10P 중 하나입니다.
- 이미 같은 날짜에 열었다면 결과를 다시 처리하지 않고 중복 지급 차단 안내를 보여줍니다.

### 가위바위보

- 참여자는 `가위`, `바위`, `보` 버튼 중 하나를 누릅니다.
- 봇 선택과 승패를 표시합니다.
- 승리하면 5P까지 받을 수 있습니다.
- 무승부나 패배는 0P로 기록됩니다.
- 같은 날짜의 가위바위보 보상은 1회만 확인됩니다.

### 주사위 대결

- 참여자 주사위와 봇 주사위를 각각 1회 굴립니다.
- 참여자 숫자가 더 크면 5P, 비기면 3P, 지면 0P입니다.
- 같은 날짜의 주사위 보상은 1회만 확인됩니다.

## 4. 포인트 보상 원칙

- 포인트 베팅은 없습니다.
- 참여자 포인트 차감은 없습니다.
- 보상은 0P, 3P, 5P, 10P 수준으로 작게 시작합니다.
- 하루 미니게임 보상 합계는 최대 10P입니다.
- 보상 지급과 0P 결과 기록은 기존 포인트 거래 로그 구조를 사용합니다.
- Google Sheets 포인트 append 설정이 켜져 있으면 기존 포인트 거래 append 경로를 그대로 사용합니다.

## 5. 하루 제한/중복 지급 기준

미니게임 거래는 `pointTransactions`에 아래 기준으로 기록됩니다.

- `relatedType`: `minigameReward`
- `relatedId`: `YYYY-MM-DD:gameId`
- `createdBy`: 참여자 Discord user ID

같은 사용자의 같은 `relatedId` 거래가 이미 있으면 해당 게임은 중복 지급되지 않습니다. 0P 결과도 거래로 남겨 같은 날짜에 같은 게임을 반복해서 보상 확인하지 못하게 합니다.

하루 최대치 판단은 같은 사용자, 같은 날짜, `relatedType=minigameReward` 거래의 양수 포인트 합계로 계산합니다. 이미 10P를 받았다면 이후 게임은 0P로 결과만 기록됩니다.

## 6. 운영자가 Discord에서 확인할 QA 항목

- `/안내` 응답이 private/ephemeral로 보이는지 확인합니다.
- 기존 `오늘의 미션 보기`, `내 포인트 확인`, `랭킹 확인`, `이용 방법 보기` 버튼이 그대로 동작하는지 확인합니다.
- `미니게임` 버튼을 눌렀을 때 세 게임 버튼이 보이는지 확인합니다.
- 오늘의 보물상자를 두 번 눌러 두 번째 응답에서 중복 지급 차단 안내가 보이는지 확인합니다.
- 가위바위보 버튼을 눌렀을 때 내 선택, 봇 선택, 승패가 표시되는지 확인합니다.
- 주사위 대결 버튼을 눌렀을 때 내 주사위, 봇 주사위, 승패가 표시되는지 확인합니다.
- `/포인트`에서 미니게임 보상 기록이 과도하게 늘어나지 않는지 확인합니다.
- 하루 미니게임 보상 합계가 10P를 넘지 않는지 운영 데이터나 `/포인트로그`로 확인합니다.

## 7. 향후 웹 미니게임 확장 방향

공피하기나 갤러그 같은 실시간 웹 미니게임은 Discord 버튼만으로 구현하기 어렵습니다. 다음 단계에서는 별도 웹 화면에서 게임을 실행하고, Discord user ID와 안전한 세션 토큰을 연결한 뒤 결과만 봇으로 기록하는 방식을 검토할 수 있습니다.

확장 시에도 유지해야 할 원칙은 같습니다.

- 포인트 베팅과 차감 금지
- 하루 보상 상한 유지
- 동일 사용자/날짜/게임 중복 지급 차단
- 결과 조작 방지를 위한 서버 검증
- 실제 Discord ID, 토큰, URL 같은 민감 정보 문서화 금지
