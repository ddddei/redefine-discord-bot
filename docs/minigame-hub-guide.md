# 미니게임 허브 운영 가이드

## 1. 미니게임 허브 개요

미니게임 허브는 참여자가 Discord 안에서 버튼만 눌러 가볍게 즐길 수 있는 MVP 기능입니다. 포인트 베팅, 포인트 차감, 반복 파밍 구조는 넣지 않습니다.

운영 기준은 `#포인트로게임하기`처럼 운영진이 지정한 미니게임 채널에서만 플레이하는 방식입니다. 봇에는 실제 채널명을 하드코딩하지 않고, Railway Variables 또는 로컬 `.env`의 `MINIGAME_CHANNEL_ID`로 채널을 지정합니다.

`/안내`의 `미니게임` 버튼은 지정된 미니게임 채널 안에서는 미니게임 허브를 바로 보여줍니다. 다른 채널에서 누르면 지정 채널로 이동하라는 private/ephemeral 안내만 보여줍니다.

## 2. 채널 제한

- `MINIGAME_CHANNEL_ID`가 설정되어 있으면 해당 채널에서만 미니게임 버튼이 실행됩니다.
- 다른 채널에서 미니게임 버튼을 누르면 private/ephemeral 응답으로 `미니게임은 지정된 미니게임 채널에서 이용해 주세요`라고 안내합니다.
- `MINIGAME_CHANNEL_ID`가 비어 있으면 기존 테스트/임시 운영처럼 채널 제한 없이 버튼 처리가 가능합니다.
- 실제 운영에서는 `MINIGAME_CHANNEL_ID` 설정을 권장합니다.

## 3. 참여자 사용 방법

1. 운영진이 지정한 미니게임 채널로 이동합니다.
2. `/안내`를 실행하고 `🎮 미니게임` 버튼을 누릅니다.
3. 미니게임 허브 첫 화면에서 원하는 게임을 고릅니다.
4. 게임별 상세 화면에서 카드, 숫자, 주사위 굴리기 같은 선택지를 누릅니다.
5. 결과와 포인트 지급 여부는 private/ephemeral 응답으로 확인합니다.
6. 하루에 확정 결과는 사용자별 최대 4회까지 기록됩니다.
7. 같은 날짜의 미니게임 보상 합계는 사용자별 최대 40P입니다.

## 4. 화면 구조

허브 첫 화면에는 게임 목록만 표시합니다. 카드 번호, 숫자, 주사위 굴리기 같은 세부 선택지는 첫 화면에 한꺼번에 노출하지 않습니다.

첫 화면 버튼은 아래 8개입니다.

- `🎴 행운 카드 뒤집기`
- `✊ 가위바위보`
- `🎲 주사위 대결`
- `🔢 숫자 맞히기`
- `🚪 문 하나 고르기`
- `🧠 이모지 기억력`
- `🧩 초성 퀴즈`
- `🧭 리디파인 탐험`

각 게임 버튼을 누르면 해당 게임의 상세 선택지 화면이 private/ephemeral로 열립니다.

## 5. 게임별 규칙

### 🎴 행운 카드 뒤집기

- 상세 화면에서 1번 카드, 2번 카드, 3번 카드 중 하나를 고릅니다.
- 결과는 0P, 3P, 5P, 10P 중 하나입니다.
- 출석 보상이 아니라 가벼운 운 게임으로 운영합니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

### ✊ 가위바위보

- 허브에는 `✊ 가위바위보` 게임 선택 버튼만 보입니다.
- 게임을 선택하면 `✌️ 가위`, `✊ 바위`, `✋ 보` 선택 버튼을 보여줍니다.
- 승리하면 5P까지 받을 수 있습니다.
- 패배는 0P로 기록됩니다.
- 비기면 보상/실패 처리 없이 다시 선택할 수 있고, 하루 참여 횟수에도 포함되지 않습니다.
- 승패가 확정되면 0P 패배도 하루 참여 횟수에 포함됩니다.

### 🎲 주사위 대결

- 상세 화면의 `🎲 주사위 굴리기` 버튼으로 참여자 주사위와 봇 주사위를 각각 1회 굴립니다.
- 결과에는 내 주사위, 봇 주사위, 승패, 지급 포인트를 표시합니다.
- 참여자 숫자가 더 크면 5P입니다.
- 비기거나 지면 0P로 기록합니다. 비김도 다시 굴리기 없이 보상 없음 처리합니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

### 🔢 숫자 맞히기

- 상세 화면에서 1~5 중 하나를 고릅니다.
- 봇 숫자와 같으면 5P를 받을 수 있습니다.
- 틀리면 0P로 기록합니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

### 🚪 문 하나 고르기

- 상세 화면에서 1번 문, 2번 문, 3번 문 중 하나를 고릅니다.
- 결과는 0P, 3P, 5P 중 하나입니다.
- 재미 문구 중심으로 운영하며 포인트 차감은 없습니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

### 🧠 이모지 기억력

- 상세 화면에서 짧은 이모지 패턴을 보여줍니다.
- 참여자는 3개 보기 중 같은 패턴을 고릅니다.
- 정답이면 5P, 오답이면 0P로 기록합니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

### 🧩 초성 퀴즈

- 상세 화면에서 쉬운 초성을 보여줍니다.
- 참여자는 3개 보기 중 정답을 고릅니다.
- 정답이면 5P, 오답이면 0P로 기록합니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

### 🧭 리디파인 탐험

- 상세 화면에서 숲길, 도서관, 광장 중 하나를 고릅니다.
- 짧은 스토리 결과와 0P, 3P, 5P 수준의 작은 보상을 확인합니다.
- 복잡한 상태 저장 없이 당일 선택 결과만 포인트 로그에 남깁니다.
- 결과가 확정되면 0P도 하루 참여 횟수에 포함됩니다.

## 6. 포인트 보상 원칙

- 포인트 베팅은 없습니다.
- 참여자 포인트 차감은 없습니다.
- 보상은 0P, 3P, 5P, 10P 수준으로 작게 유지합니다.
- 하루 미니게임 확정 결과는 사용자별 최대 4회입니다.
- 하루 미니게임 보상 합계는 사용자별 최대 40P입니다.
- 40P 상한에 가까운 상태에서 결과 보상이 남은 한도를 넘으면 남은 한도까지만 지급합니다.
- 40P를 이미 받은 사용자는 이후 확정 결과가 0P로 기록되며 추가 지급은 없습니다.
- 0P 결과도 확정 결과로 기록되며 하루 참여 횟수에 포함됩니다.
- 가위바위보 무승부는 확정 결과가 아니므로 포인트 거래와 하루 참여 횟수에 포함하지 않습니다.
- 보상 지급, 상한으로 잘린 지급, 0P 결과 기록은 기존 포인트 거래 로그 구조를 사용합니다.
- Google Sheets 포인트 append 설정이 켜져 있으면 기존 포인트 거래 append 경로를 그대로 사용합니다.

## 7. 하루 제한/중복 지급 기준

미니게임 확정 결과는 `pointTransactions`에 아래 기준으로 기록됩니다.

- `relatedType`: `minigameReward`
- `relatedId`: `YYYY-MM-DD:gameId`
- `createdBy`: 참여자 Discord user ID

같은 사용자의 같은 `relatedId` 거래가 이미 있으면 해당 게임은 중복 지급되지 않습니다. 0P 결과도 거래로 남겨 같은 날짜에 같은 게임을 반복해서 보상 확인하지 못하게 합니다.

가위바위보 무승부는 거래로 기록하지 않습니다. 승리 또는 패배가 확정된 경우에만 `minigameReward` 거래를 남깁니다.

하루 참여 횟수 판단은 같은 사용자, 같은 날짜, `relatedType=minigameReward` 거래 개수로 계산합니다. 0P 거래도 확정 결과이므로 참여 횟수에 포함합니다. 하루 4회가 이미 기록된 사용자는 추가 미니게임 결과를 확정하지 않습니다.

하루 보상 상한 판단은 같은 사용자, 같은 날짜, `relatedType=minigameReward` 거래의 양수 포인트 합계로 계산합니다. 이미 40P를 받았다면 이후 확정 결과는 0P로 기록됩니다. 남은 한도가 결과 보상보다 작으면 남은 한도까지만 지급하고, 잘린 금액을 추가로 지급하지 않습니다.

## 8. 운영자가 Discord에서 확인할 QA 항목

- `/안내` 응답이 private/ephemeral로 보이는지 확인합니다.
- `/안내`의 `오늘의 미션 보기`, `내 포인트 확인`, `랭킹 확인`, `이용 방법 보기` 버튼이 그대로 동작하는지 확인합니다.
- 지정 미니게임 채널에서 `/안내`의 `미니게임` 버튼을 눌렀을 때 미니게임 허브가 보이는지 확인합니다.
- 지정 채널이 아닌 곳에서 `/안내`의 `미니게임` 버튼을 눌렀을 때 채널 안내만 보이는지 확인합니다.
- 지정 채널이 아닌 곳에서 미니게임 버튼을 눌렀을 때 채널 안내가 보이고 포인트 거래가 생기지 않는지 확인합니다.
- `MINIGAME_CHANNEL_ID`가 설정된 상태에서 지정 채널과 다른 채널의 동작이 위 기준과 맞는지 확인합니다.
- 미니게임 허브 첫 화면에 게임 선택 버튼만 보이고 카드 번호, 숫자, 주사위 굴리기 같은 세부 선택지가 보이지 않는지 확인합니다.
- 각 게임 선택 버튼을 눌렀을 때 세부 선택지가 private/ephemeral 상세 화면으로 열리고, 결과 응답도 private/ephemeral로 보이는지 확인합니다.
- 행운 카드 뒤집기를 두 번 눌러 두 번째 응답에서 중복 지급 차단 안내가 보이는지 확인합니다.
- 가위바위보 시작 후 선택 버튼이 보이고, 무승부일 때 다시 선택 버튼이 보이는지 확인합니다.
- 가위바위보 무승부 뒤에는 포인트 거래가 생기지 않고 하루 참여 횟수도 늘지 않는지 확인합니다.
- 주사위 대결 결과에 🎲 내 주사위, 🎲 봇 주사위, 승패, 지급 포인트가 표시되는지 확인합니다.
- 숫자 맞히기에서 내 숫자와 봇 숫자, 지급 포인트가 표시되는지 확인합니다.
- 문 하나 고르기, 이모지 기억력, 초성 퀴즈, 리디파인 탐험 상세 화면과 결과 응답이 private/ephemeral로 보이는지 확인합니다.
- 0P 결과가 포인트 거래로 남고 하루 참여 횟수에 포함되는지 확인합니다.
- 같은 사용자가 하루 확정 결과 4회를 채운 뒤 추가 결과를 확정할 수 없는지 확인합니다.
- 하루 보상 합계가 40P를 넘지 않는지 운영 데이터나 `/포인트로그`로 확인합니다.
- 남은 하루 보상 한도보다 큰 결과가 나왔을 때 남은 한도까지만 지급되고 초과분이 추가 지급되지 않는지 확인합니다.
- `/포인트`에서 미니게임 보상 기록이 과도하게 늘어나지 않는지 확인합니다.
- 포인트 베팅, 포인트 차감, 실패 시 차감 안내가 어디에도 보이지 않는지 확인합니다.


## 9. 향후 웹 미니게임 확장 방향

공피하기나 갤러그 같은 실시간 웹 미니게임은 Discord 버튼만으로 구현하기 어렵습니다. 다음 단계에서는 별도 웹 화면에서 게임을 실행하고, Discord user ID와 안전한 세션 토큰을 연결한 뒤 결과만 봇으로 기록하는 방식을 검토할 수 있습니다.

확장 시에도 유지해야 할 원칙은 같습니다.

- 포인트 베팅과 차감 금지
- 하루 보상 상한 유지
- 동일 사용자/날짜/게임 중복 지급 차단
- 결과 조작 방지를 위한 서버 검증
- 실제 Discord ID, 토큰, URL 같은 민감 정보 문서화 금지
