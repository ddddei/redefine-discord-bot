# 미션/상점 등록 가이드

실제 운영 전 Discord 명령어로 운영용 미션과 상점 항목을 등록하고 확인하는 순서입니다. 이 문서는 등록 절차를 설명하며, `data/*.local.json`을 직접 수정하거나 운영 데이터를 자동 생성하지 않습니다.

## 1. 문서 목적

- `/미션관리`로 운영용 기본 미션을 등록하는 순서를 정리합니다.
- `/상점관리`로 청년동 포인트 전환과 리워드 항목을 등록하는 순서를 정리합니다.
- 등록 후 `/미션`, `/상점`, `/운영현황`, `/admin`에서 확인할 항목을 정리합니다.
- 운영 중 수정, 일시중지, 숨김, 품절 처리 기준을 정리합니다.

기본 항목의 세부 설계는 [operation-default-items-plan.md](operation-default-items-plan.md)를 함께 확인합니다.

## 2. 운영 전 준비

- 운영자 계정이 `ManageMessages` 또는 `Administrator` 권한을 가지고 있는지 확인합니다.
- 운영자 전용 채널과 로그 채널을 일반 참여자가 볼 수 없는지 확인합니다.
- 미션 인증 채널과 `MISSION_SUBMISSION_CHANNEL_ID` 설정을 확인합니다.
- `/운영현황`이 운영자에게만 보이는지 확인합니다.
- 관리자 웹 대시보드를 사용할 경우 `/admin` 접속과 Basic Auth를 확인합니다.
- 운영용 미션/상점 등록 전 테스트용 `data/*.local.json`이 남아 있는지 확인하고, 필요한 경우 [production-data-reset-guide.md](production-data-reset-guide.md)에 따라 정리합니다.
- 이번 등록은 Slash Command 구조를 바꾸지 않으므로 `npm run deploy`를 실행하지 않습니다.

## 3. 미션 등록 순서

1. `/미션관리 작업:추가`를 실행합니다.
2. 제목에는 참여자가 바로 이해할 수 있는 짧은 이름을 입력합니다.
3. 설명에는 다음 행동과 인증 방식을 한두 문장으로 적습니다.
4. 지급 포인트를 입력합니다.
5. 인증 필요 여부를 정합니다.
6. 반복 가능 여부를 운영 기준에 맞게 정합니다.
7. 상태는 참여자에게 바로 보여도 되는 미션만 active로 둡니다.
8. 등록 후 `/미션관리 작업:목록`으로 미션 ID와 상태를 확인합니다.
9. active가 아닌 미션은 `/미션관리 작업:활성화 미션id:...`로 노출 시점을 조정합니다.
10. 참여자 화면에서 `/미션`을 실행해 이름, 설명, 선택 메뉴가 자연스럽게 보이는지 확인합니다.

### 기본 미션 등록 예시

| 등록 순서 | 미션명 | 권장 포인트 | 인증 필요 | 반복 기준 | 권장 상태 |
| ---: | --- | ---: | --- | --- | --- |
| 1 | 첫 인사 남기기 | 20P | 필요 | 1회 | active |
| 2 | 오늘의 체크인 | 10P | 체크인 명령어 | 하루 1회 | active |
| 3 | 관심 활동 선택하기 | 20P | 필요 | 1회 | active |
| 4 | 미션 인증 사진/영상 올리기 | 30P | 필요 | 활동별 1회 | active |
| 5 | 프로그램 참여 후기 남기기 | 50P | 필요 | 회차별 1회 | active 또는 paused |
| 6 | 주간 회고 남기기 | 40P | 필요 | 주 1회 | active 또는 paused |

초기 운영에서는 참여자가 바로 이해할 수 있는 3-4개 미션만 active로 열고, 후기나 주간 회고는 실제 운영 일정에 맞춰 활성화해도 됩니다.

### 미션 필드 작성 기준

- 제목: `첫 인사 남기기`처럼 행동이 바로 보이게 씁니다.
- 설명: "지정 채널에 첫 인사를 남겨 주세요. 길게 쓰지 않아도 괜찮아요."처럼 짧게 씁니다.
- 지급 포인트: 기본 설계의 권장 포인트를 사용하되 운영 상황에 맞게 조정합니다.
- 인증 필요 여부: `/체크인`처럼 자동 기록되는 활동 외에는 운영자 확인을 기본으로 둡니다.
- 상태: 참여자에게 보여도 되는 항목만 active로 둡니다.
- 반복 가능 여부: 하루 1회, 주 1회, 1회처럼 설명 가능한 기준만 사용합니다.
- 시작일/종료일: 시스템 필드가 부족하면 운영자가 별도 공지와 메모로 관리합니다.

## 4. 상점 항목 등록 순서

1. `/상점관리 작업:추가`를 실행합니다.
2. 항목명에는 참여자가 바로 이해할 수 있는 이름을 입력합니다.
3. 설명에는 교환 내용, 신청 전 확인할 점, 지급 방식을 짧게 적습니다.
4. 필요 포인트를 입력합니다.
5. 유형을 정합니다.
6. 재고를 정합니다.
7. 상태는 실제 지급 가능한 항목만 active로 둡니다.
8. 등록 후 `/상점관리 작업:목록`으로 항목 ID와 상태를 확인합니다.
9. active가 아닌 항목은 실제 제공이 확정된 뒤 `/상점관리 작업:활성화 항목id:...`로 노출합니다.
10. 참여자 화면에서 `/상점`과 `/교환`을 실행해 안내 문구와 선택 흐름을 확인합니다.

### 기본 상점 등록 예시

| 등록 순서 | 항목명 | 필요 포인트 | 유형 | 재고 | 권장 상태 |
| ---: | --- | ---: | --- | --- | --- |
| 1 | 청년동 포인트 전환 100P | 100P | youthCenterPoint | 제한 없음 | active |
| 2 | 청년동 포인트 전환 300P | 300P | youthCenterPoint | 제한 없음 | active 또는 hidden |
| 3 | 프린트 카드 충전권 | 150P 또는 추후 확정 | reward | 제한 가능 | paused 또는 hidden |
| 4 | 밀리의 서재 구독권 | 추후 확정 | reward | 수량 제한 | hidden |
| 5 | 왓챠 구독권 | 추후 확정 | reward | 수량 제한 | hidden |

### 상점 필드 작성 기준

- 항목명: `청년동 포인트 전환 100P`처럼 교환 내용을 직접 씁니다.
- 설명: 신청 전 확인, 단순 변심 취소/환불 어려움, 예외 처리 가능성을 짧게 안내합니다.
- 필요 포인트: 실제 차감될 포인트와 일치해야 합니다.
- 유형: 청년동 포인트 전환은 `youthCenterPoint`, 외부 리워드는 `reward`로 구분합니다.
- 재고: 청년동 포인트 전환은 제한 없음 권장, 외부 구독권은 수량 확정 후 제한합니다.
- 확인 기준: 30만원 이상처럼 과도하게 큰 청년동 포인트 전환 신청은 운영자가 별도 확인할 수 있습니다.
- 상태: 지급 가능성이 확정되지 않은 항목은 hidden 또는 paused로 둡니다.

## 5. 등록 후 확인 방법

- `/미션`: active 미션만 참여자에게 자연스럽게 보이는지 확인합니다.
- `/상점`: active 상점 항목만 참여자에게 자연스럽게 보이는지 확인합니다.
- `/교환`: 신청 전 주의 문구가 차갑거나 위협적으로 보이지 않는지 확인합니다.
- `/운영현황`: 활성 미션 수와 활성 상점 항목 수를 확인합니다.
- `/포인트로그`: 테스트 지급, 차감, 환불 기록이 의도대로 남는지 확인합니다.
- `/운영내보내기`: 운영 전 백업이 필요한 경우 전체 JSON을 저장합니다.

## 6. 관리자 대시보드 확인 방법

`/admin`은 읽기 전용 확인 화면입니다.

- 미션/상점 상태가 0이면 운영용 항목이 아직 등록되지 않았거나 active 상태가 아닐 수 있습니다.
- 운영용 미션 등록 후 활성 미션 수가 증가하는지 확인합니다.
- 운영용 상점 등록 후 활성 상점 항목 수가 증가하는지 확인합니다.
- 교환 대기와 인증 대기는 실제 참여자 신청이나 제출이 생긴 뒤 표시됩니다.
- example 데이터가 운영 데이터처럼 보이지 않는지 확인합니다.
- 수정, 승인, 반려, 지급 처리는 `/admin`이 아니라 Discord 명령어에서 진행합니다.

## 7. 참여자 화면 확인 방법

- 일반 참여자 테스트 계정으로 `/안내`를 실행합니다.
- `/미션`에서 미션명이 먼저 보이고, 코드가 중심이 되지 않는지 확인합니다.
- `/상점`에서 교환 항목명이 먼저 보이고, 신청 전 확인 문구가 이해하기 쉬운지 확인합니다.
- `/교환`에서 항목 선택과 신청 확인 흐름이 자연스러운지 확인합니다.
- 미션 인증 채널에 테스트 메시지를 올리고 운영자 승인 반응 후 포인트가 지급되는지 확인합니다.
- `/포인트`로 참여자 잔액이 반영됐는지 확인합니다.

## 8. 운영 중 수정 기준

- 포인트가 너무 빠르게 쌓이면 반복 가능 미션의 주기를 늘리거나 지급 포인트를 낮춥니다.
- 참여자가 특정 미션을 어려워하면 설명을 더 짧게 쓰고 선택지를 줄입니다.
- 개인정보가 포함된 인증이 자주 올라오면 사진/영상 미션 설명에 주의 문구를 더 앞에 둡니다.
- 청년동 포인트 전환 신청이 과도하게 커지면 운영자가 별도 확인 기준을 공지합니다.
- 수량 제한 상품은 제공 가능 수량과 지급 일정이 확정되기 전까지 hidden 또는 paused로 둡니다.
- 이미 참여자가 신청한 상점 항목은 임의 삭제보다 일시중지, 품절, 운영 메모 기록을 우선합니다.

## 9. 운영 전 체크리스트

- [ ] 운영용 기본 미션을 1개 이상 등록했습니다.
- [ ] 운영용 기본 상점 항목을 1개 이상 등록했습니다.
- [ ] `/미션`에서 참여자에게 미션이 자연스럽게 보입니다.
- [ ] `/상점`에서 참여자에게 교환 항목이 자연스럽게 보입니다.
- [ ] `/교환`에서 신청 전 주의 문구가 확인됩니다.
- [ ] `/admin`에서 활성 미션/상점 수가 정상 표시됩니다.
- [ ] 교환 신청 후 `/admin`의 교환 대기에 표시되는지 확인했습니다.
- [ ] 미션 인증 채널 반응 승인 후 포인트가 지급되는지 확인했습니다.
- [ ] 취소/환불 안내 문구가 너무 딱딱하거나 위협적으로 보이지 않습니다.
- [ ] 문서만 수정한 작업에서는 `npm run deploy`를 실행하지 않았습니다.
