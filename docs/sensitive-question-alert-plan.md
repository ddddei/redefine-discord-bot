# 민감 질문 운영진 연결 및 자동 알림 설계안

## 1. 문서 목적

이 문서는 민감 질문이 들어왔을 때 봇이 상담자나 판단자 역할을 하지 않고, 운영진 확인으로 안전하게 연결하기 위한 설계 문서입니다.

봇은 참여자의 상황을 상담, 진단, 치료하거나 위기 여부를 판정하지 않습니다. 민감한 표현이 포함된 질문을 발견했을 때 운영진이 확인할 수 있도록 돕는 보조 도구로만 설계합니다.

## 2. 민감 질문 범위

아래 유형은 FAQ 자동 답변보다 운영진 확인을 우선해야 하는 민감 질문 범위입니다.

- 자해 표현
- 자살 표현
- 죽고 싶다, 사라지고 싶다 등 위기 표현
- 병원에 가야 하는지 묻는 질문
- 상담기관이나 전문기관 안내 요청
- 불편한 DM
- 반복 연락
- 지인과 같은 서버에 있어 불편한 경우
- 개인정보 노출
- 타인을 특정할 수 있는 신고성 내용
- 폭력, 위협, 성폭력, 괴롭힘 관련 표현

## 3. 봇의 역할 한계

- 봇은 상담, 진단, 치료, 위기 판단을 하지 않습니다.
- 봇은 운영진에게 연결하는 보조 도구입니다.
- 민감 질문은 FAQ 자동 답변보다 운영진 확인을 우선합니다.
- 긴급하거나 안전이 우려되는 경우 주변의 신뢰할 수 있는 사람, 운영진, 전문 도움을 요청하도록 안내해야 합니다.
- 단, 봇과 운영진 안내는 구체적인 의료·법률 판단을 대신하지 않습니다.

## 4. `/질문` 민감 표현 감지 설계

- `/질문` 입력값을 FAQ/Knowledge 검색 전에 먼저 검사합니다.
- 민감 표현이 있으면 일반 답변보다 운영진 확인 안내를 우선합니다.
- 사용자에게는 차분한 안내를 ephemeral로 표시합니다.
- 운영진 로그 채널에는 최소 정보만 알립니다.
- 사용자 ID, 실명, 불필요한 개인정보는 기록하지 않는 방향으로 설계합니다.
- 단, 운영상 필요한 경우 Discord 메시지 링크 또는 채널 정보 포함 여부는 운영진이 별도 검토합니다.

## 5. 운영진 알림 메시지 설계

운영진 알림 메시지에는 아래 정보를 최소 범위로 포함하는 방향을 검토합니다.

- 감지 유형
- 감지 시간
- 입력 경로: `/질문`
- 질문 일부 또는 요약
- 운영진 확인 필요 안내
- 자동 판단이 아니라 키워드 기반 감지라는 설명

주의사항:

- 원문 전체 저장은 최소화합니다.
- 민감한 사연을 공용 운영진 채널에 과도하게 노출하지 않습니다.
- 운영진 전용 채널 권한 확인이 필요합니다.

## 6. 일반 대화 메시지 감지 설계

일반 대화 메시지 감지는 기술적으로 가능할 수 있지만, 이번 단계에서는 바로 도입하지 않고 별도 검토가 필요합니다.

- Message Content Intent가 필요할 수 있습니다.
- 참여자에게 사전 안내와 동의/공지 범위를 명확히 해야 합니다.
- 감지 대상 채널을 제한하는 것이 좋습니다.
- 모든 메시지를 저장하지 않습니다.
- 감지된 경우에만 최소 정보로 운영진에게 알립니다.
- 오탐 가능성이 있으므로 운영진 확인 절차가 필요합니다.
- 민감한 주제를 과도하게 감시하는 느낌을 주지 않도록 주의합니다.

## 7. 권장 구현 단계

1. 문서와 운영진 응대 기준 확정
2. `/질문` 민감 표현 감지 및 운영진 알림 구현
3. 테스트 질문 추가
4. 운영진 로그 채널 권한 확인
5. 참여자 공지문에 안전 안내 추가
6. 일반 대화 메시지 감지는 운영진 검토 후 선택 도입

## 8. 감지 키워드 초안

아래 키워드는 확정 목록이 아니라 초안입니다. 키워드만으로 위기 여부를 판단하지 않으며, 운영진 확인이 필요한 신호를 찾기 위한 보조 기준으로만 사용합니다.

### 자해/자살

- 죽고 싶다
- 자살
- 자해
- 사라지고 싶다
- 없어지고 싶다
- 끝내고 싶다

### 위기/위험

- 위험해요
- 무서워요
- 위협받고 있어요
- 폭력
- 협박

### 상담/병원

- 상담기관
- 병원 가야 하나요
- 정신과
- 약 먹어야 하나요

### 관계/DM

- DM이 불편해요
- 계속 연락이 와요
- 원치 않는 연락
- 같은 서버에 있어서 불편해요

### 개인정보/신고

- 개인정보
- 실명
- 전화번호
- 주소
- 신고하고 싶어요

## 9. 사용자에게 보여줄 안내 문구 초안

```text
남겨주신 내용은 봇이 바로 답변하기보다 운영진 확인이 필요한 내용으로 보입니다.

혼자 감당하지 않아도 괜찮습니다. 운영진이 조심스럽게 확인할 수 있도록 연결하겠습니다.

지금 긴급하거나 안전이 걱정되는 상황이라면 디스코드 답변을 기다리지 말고 주변의 신뢰할 수 있는 사람, 운영진, 전문 도움을 요청해 주세요.
```

## 10. 운영진 응대 원칙

- 빠르게 확인합니다.
- 공개 채널에서 자세히 묻지 않습니다.
- 필요한 경우 DM 또는 운영진 안내 연락 방법을 사용합니다.
- 긴급성 판단은 운영진 내부 기준에 따라 진행합니다.
- 참여자를 평가하거나 책임 묻는 표현을 피합니다.
- 기록은 최소화합니다.
- 개인정보와 민감정보 공유 범위를 제한합니다.

## 11. 구현 전 확인사항

- 운영진 전용 로그 채널이 있는지 확인
- `LOG_CHANNEL_ID`를 그대로 쓸지, 별도 `SAFETY_ALERT_CHANNEL_ID`를 만들지 결정
- 참여자 공지에 안전 안내와 모니터링 범위를 어떻게 적을지 결정
- 일반 대화 감지 기능을 켤지 말지 결정
- Discord Developer Portal에서 Message Content Intent가 필요한지 확인
- Railway 환경변수 추가 여부 확인
- 테스트 계정으로 알림 확인

## 12. 이번 문서에서 하지 않은 것

- 실제 코드 구현 없음
- `data/*.json` 수정 없음
- Discord 권한 변경 없음
- Message Content Intent 활성화 없음
- 민감 질문 자동 판단 없음
