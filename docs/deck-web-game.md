# 덱빌딩 브라우저 미니게임: 간식 수호대

`간식 수호대`는 참여자들이 한 판 10~15분 정도로 가볍게 즐길 수 있는 브라우저용 덱빌딩(로그라이크 카드) 게임입니다. 던전월드 세계관과는 무관한 독립 게임이며, 매치3 `간식 맞추기`, 방치형 `간식 공방 키우기`와 같은 밝은 간식/디저트 테마를 공유하는 자매 게임입니다. `public/deck/` 아래의 정적 HTML/CSS/JS 파일로 동작하며, 기존 `검은 종 생존전`([docs/dungeonworld-survivors-web-game.md](dungeonworld-survivors-web-game.md)), `간식 맞추기`([docs/match3-web-game.md](match3-web-game.md)), `간식 공방 키우기`([docs/idle-web-game.md](idle-web-game.md))와 동일한 운영 원칙과 서빙 구조를 따릅니다.

## 운영 원칙

- Discord 계정 연동이 없습니다.
- 포인트 지급 없음, 포인트 차감 없음, 베팅 없음, 랭킹 저장이 없습니다.
- 기존 버튼형 미니게임의 보상 정책은 변경하지 않습니다.
- `.env` 수정이나 `npm run deploy`가 필요하지 않습니다.
- 진행 상태는 **참여자 브라우저의 localStorage에만** 저장됩니다. 운영 데이터 JSON에는 저장하지 않으며, 서버는 정적 파일만 서빙합니다.
- 기기나 브라우저를 바꾸면 진행 상태가 이어지지 않고 처음부터 시작합니다. 참여자에게 안내할 때 이 점을 알려주세요.

## 플레이 내용

견습 제빵사가 공방의 간식을 노리는 침입자들을 물리치는 한 판짜리 런(run) 구조 게임입니다. 승리마다 카드를 골라 덱을 키우고, 마지막 보스에게 도전합니다.

- **런 구조**: 선형 11칸(일반 전투 6, 정예 전투 2, 휴식 2, 보스 1). 어떤 적이 나올지는 시드 셔플로 정해지며, 갈림길은 없습니다.
- **전투**: 적은 전투당 1명이며, 매 턴 다음 행동(의도)을 미리 보여줍니다. 방어할지 밀어붙일지는 참여자의 선택입니다. 턴당 에너지 3, 드로우 5장 안에서 카드 조합을 짭니다.
- **카드**: 시작 덱 10장 + 획득 카드 18종(일반 12·정예급 6). 피해/방어도/드로우/에너지 획득/힘/약화/취약/회복/다단 히트/자해 피해 등의 효과를 조합해 사용합니다.
- **상태 효과**: 힘(공격 피해 증가, 전투 중 유지), 약화(주는 피해 25% 감소, N턴), 취약(받는 피해 50% 증가, N턴).
- **휴식**: 회복하기(최대 HP의 30% 회복) 또는 덱 정리하기(카드 1장 영구 제거) 중 하나를 선택합니다.
- **보상**: 전투 승리 후 카드 3장 중 1장을 고르거나 건너뜁니다. 정예/보스 전투는 정예급 카드를 1장 이상 보장합니다.
- **결과**: 보스를 물리치거나 HP가 0이 되면 런이 종료되고, 도달한 칸·처치 수·최종 덱 크기와 함께 `새로 시작` 버튼을 보여줍니다. 클리어 횟수와 최고 도달 칸은 통산 기록으로 유지됩니다.

## 파일 구성

- `public/deck/index.html` — 마크업. 진행 트랙, 전투/보상/휴식/결과 화면. `content.js` → `engine.js` → `game.js` 순서로 로드합니다. 공용 디자인 시스템 `public/shared/game-ui.css`를 `styles.css`보다 먼저 로드합니다.
- `public/deck/styles.css` — 매치3·간식 공방 키우기와 같은 밝은 파스텔 팔레트, 모바일(375px) 우선 + PC 520px 카드 레이아웃.
- `public/deck/content.js` — 카드 21종(시작 3 + 일반 12 + 정예급 6), 적 9종, 런 구성 배열, 휴식/보상 상수, 카피 등 정의 데이터만 담습니다. DOM에 접근하지 않으며 `window.DeckContent` 전역과 Node `module.exports` 양쪽에서 로드할 수 있습니다.
- `public/deck/engine.js` — 시드 RNG, 덱 셔플/드로우/버림, 카드 효과 해석, 피해 계산(힘/약화/취약/방어도 순서), 적 의도 순환·행동 실행, 턴/런 진행, 승패 판정, 저장 직렬화·역직렬화 등 순수 계산 로직. DOM이나 `Date.now()`, `Math.random()`을 직접 참조하지 않고 난수는 항상 시드 기반 트래커를 인자로 받습니다. `window.DeckEngine` 전역과 Node `module.exports` 양쪽에서 로드할 수 있습니다.
- `public/deck/game.js` — DOM 렌더링, 카드 탭 입력, 화면 전환, localStorage 저장/복원, `beforeunload` 처리. 적·플레이어·카드 타입 아이콘은 `public/shared/assets/deck-enemy-*.svg`, `shared-char-baker.svg`, `deck-icon-*.svg`(`content.js`의 `asset` 필드로 참조, [webgame-design-guide.md](webgame-design-guide.md))에 의존합니다.

## 로컬 실행 및 QA

봇 프로세스의 HTTP 서버가 켜져 있는 환경에서는 `/game/deck` 경로로 정적 파일을 서빙합니다. 이 경로는 대시보드 API와 달리 Basic Auth를 요구하지 않습니다.

`ADMIN_DASHBOARD_ENABLED=true`와 관리자 계정 환경 변수를 설정한 뒤 `npm start`로 봇을 실행하고, 브라우저에서 아래 주소를 엽니다(경로 끝의 슬래시를 포함해야 상대 경로 스크립트/스타일이 올바르게 로드됩니다).

```text
http://localhost:3000/game/deck/
```

확인할 사항:

- `?seed=42`처럼 시드를 고정해 한 런 전체를 플레이: 카드 사용/방어/의도 대응/보상 선택/휴식/보스까지 흐름을 확인합니다. 같은 시드로 재접속하면 같은 배치가 나와야 합니다.
- 전투 중간에 탭을 닫았다가 시드 없이 재접속 → 같은 상태로 이어하기 되는지(시드·RNG 카운터 복원 포함, 이후 셔플도 동일해야 함).
- 패배 시 결과 화면과 `새로 시작` 버튼, 클리어/최고 도달 칸 기록이 유지되는지.
- 시작 덱만으로 첫 2전투가 무난한지, 정예 전투에서 긴장감이 있는지(밸런스 목표, 필요시 `content.js` 수치 조정).
- 모바일 뷰포트(375px)에서 손패 가로 스크롤과 카드 탭 조작이 가능한지, PC 화면(520px 폭)에서도 정상 표시되는지.

## 배포 메모

정적 파일과 문서만 바뀐 경우에는 Slash Command 구조가 바뀌지 않으므로 `npm run deploy`를 실행하지 않습니다. 운영자가 실제 참여자에게 공개 URL을 안내하려면 먼저 Railway/정적 호스팅 경로에서 `public/deck/`이 접근 가능한지 확인해 주세요. 진행 상태가 참여자 브라우저의 localStorage에만 저장되므로, 기기·브라우저를 바꾸면 처음부터 다시 시작한다는 점을 안내에 포함해 주세요.
