# 운영진 데일리 퀵스타트

프로젝트 리디파인 디스코드를 함께 운영하는 동료를 위한 하루 운영 순서표입니다. 상세한 명령어 옵션은 [운영자 명령어 가이드](operator-command-guide.md), 운영 정책은 [운영 가이드](operation-guide.md)를 참고하고, 이 문서는 "지금 뭘 하면 되는지"만 빠르게 찾는 용도로 사용해 주세요.

## 0. 시작 전 딱 한 번 확인할 것

- 운영자 권한: 서버에서 관리자 역할이 있어야 운영 명령어가 보입니다. `/운영현황`을 입력했을 때 자동완성에 뜨면 준비된 것입니다.
- 운영 명령어는 어느 채널에서 실행해도 응답이 본인에게만 보이지만, 습관적으로 `#운영-로그`에서 실행하는 것을 권장합니다.
- 봇 응답의 "처리자"에 내 이름이 기록됩니다. 처리 이력은 나중에 함께 확인할 수 있어요.

## 1. 아침에 하는 일 (5분)

1. `#오늘의-미션`에 오전 8시 자동 안내가 올라왔는지 확인합니다.
2. `/운영현황` → `전체 요약`으로 어제 놓친 대기 건이 없는지 봅니다.
   - `교환 대기`, `인증 대기`, `오늘 반응 승인`이 0건이면 밀린 일이 없는 것입니다.
3. 필요하면 `오늘의 운영 큐` 메뉴로 오늘 먼저 처리할 항목을 확인합니다.

## 2. 미션 인증이 올라오면 (수시)

참여자가 `#오늘의-미션`에 글/사진을 올리면 자동으로 접수되어 `#미션-인증-검토` 채널에 **검토 카드**가 올라옵니다.

1. 카드 내용(제출자, 텍스트 요약, 첨부파일 개수)을 확인합니다.
2. **승인하고 지급** 버튼 → 포인트가 자동 지급되고, 참여자에게 DM 알림이 갑니다.
3. 인증으로 보기 어려우면 **반려하기** 버튼 → 포인트 미지급, 참여자에게 다시 제출 안내 DM이 갑니다.
4. 같은 참여자의 오늘의 미션 포인트는 하루 1회만 지급되므로 중복 걱정은 하지 않아도 됩니다.

처리 결과는 `#미션-인증-검토`와 `#운영-로그`에 자동 기록됩니다.

## 3. 교환 신청이 오면 (수시)

참여자가 `/교환`으로 신청하면 `#교환-신청-알림` 채널에 알림이 옵니다. 신청 시점에 포인트는 이미 차감된 상태입니다.

1. 알림 카드에서 **신청 ID**(`rd_...`)를 복사합니다.
2. 실물 지급(예: 청년동 포인트 전환 처리)을 완료합니다.
3. `/교환관리 신청id:(붙여넣기) 처리:지급완료`를 실행합니다.
4. 착오나 예외 상황이면 `처리:취소` 또는 `처리:환불완료`를 사용합니다 (사유는 `메모`에 남기기).

신청 ID는 알림 카드에서 복사하는 것이 가장 정확합니다. 눈으로 옮겨 적으면 틀리기 쉬워요.

## 4. 포인트를 직접 지급/차감해야 할 때

이벤트 보상, 정정 등이 필요하면:

```
/포인트관리 대상:@참여자 증감:20 사유:이벤트 보상
```

- 차감은 증감에 음수를 입력합니다 (예: `-10`).
- 사유는 로그에 남으니 나중에 봐도 알 수 있게 적어 주세요.
- 지급 내역은 `/포인트로그`로 확인할 수 있습니다.

## 5. 미션/상점 항목을 바꾸고 싶을 때

- 새 미션: `/미션관리 작업:추가 제목:... 설명:... 포인트:... 인증필요:True` → 생성 직후에는 draft 상태이므로, 응답에 나온 미션 ID로 `/미션관리 작업:활성화 미션id:...`까지 해야 참여자에게 보입니다.
- 새 상점 항목: `/상점관리 작업:추가 이름:... 설명:... 비용:... 유형:...` → 마찬가지로 `작업:활성화`까지 필요합니다.
- 잠시 내리기: `작업:일시중지`, 완전히 종료: `작업:종료`(미션) / `작업:숨김`(상점).

**추가 → 활성화 2단계**라는 것만 기억하면 됩니다.

## 6. 하루 마감 (5분)

1. `/운영현황` → `전체 요약`으로 대기 0건인지 확인합니다.
2. 처리 못 한 건이 있으면 내일 아침 큐에 남으니 무리해서 밤에 처리하지 않아도 됩니다.
3. 주 1회 정도 `/운영내보내기 종류:전체 형식:JSON`으로 백업 파일을 받아 정해진 보관 위치에 저장합니다.
   - 내보낸 파일에는 참여자 ID와 인증 내용이 포함되므로 공개 채널이나 외부에 공유하지 않습니다.

## 7. 이런 건 바로 다른 운영진과 상의해요

- `#안전-확인` 채널에 민감 질문 알림이 왔을 때 (자동 감지된 위기 표현 등) — 봇이 아니라 사람이 응답해야 하는 상황입니다.
- 참여자가 개인적인 어려움을 문의했을 때 — [온보딩 운영 런북](onboarding-operation-runbook.md)의 응대 문구를 참고하되, 판단이 어려우면 혼자 결정하지 않습니다.
- 포인트 대량 정정, 교환 환불 등 되돌리기 어려운 처리 — 실행 전에 한 번 공유합니다.

## 8. 자주 쓰는 명령어 치트시트

| 상황 | 명령어 |
| --- | --- |
| 운영 상태 한눈에 | `/운영현황` |
| 인증 승인/반려 | `#미션-인증-검토` 카드 버튼 (명령어 필요 없음) |
| 교환 처리 | `/교환관리 신청id:... 처리:지급완료` |
| 포인트 지급/차감 | `/포인트관리 대상:... 증감:... 사유:...` |
| 포인트 내역 확인 | `/포인트로그` (사용자·종류 필터 가능) |
| 미션 등록 | `/미션관리 작업:추가` → `작업:활성화` |
| 상점 등록 | `/상점관리 작업:추가` → `작업:활성화` |
| 데이터 백업 | `/운영내보내기 종류:전체 형식:JSON` |
| 공지 문구 꺼내기 | `/공지` |
