# 운영자 허브 가이드

## 관리자 웹 대시보드와의 역할 구분

`/운영현황`은 Discord 안에서 빠르게 확인하고 일부 운영 작업을 시작하는 운영자 허브입니다. `/admin` 관리자 웹 대시보드는 브라우저에서 운영 요약, 대기 목록, 최근 로그, 미션/상점 상태, 반응 승인 기록을 한 화면에 보는 읽기 전용 보조 화면입니다.

교환 지급완료/취소/환불, 인증 승인/반려, 포인트 지급/차감, 미션/상점 수정은 계속 Discord 안에서 처리합니다. 미션 생성과 수정은 `/운영현황`의 `미션 관리 허브` 또는 기존 `/미션관리`에서 진행합니다. `/admin`에는 처리 버튼이나 수정 기능을 두지 않습니다.

실제 운영 전 `/admin`에서 활성 미션 수 또는 활성 상점 항목 수가 0이면 운영용 항목이 아직 등록되지 않았거나 active 상태가 아닌 상태입니다. 기본 미션과 상점 항목을 `/미션관리`, `/상점관리`로 등록한 뒤 `/admin`에서 활성 수가 증가하는지 확인합니다. 교환 대기와 인증 대기는 실제 참여자의 신청 또는 제출이 생긴 뒤 표시됩니다.

## 1. 운영자 허브란?

`/운영현황`은 운영자가 현재 운영 상태를 먼저 확인하는 메인 허브입니다. 새 명령어를 외우기보다 `/운영현황`을 실행한 뒤 드롭다운에서 필요한 메뉴를 선택합니다.

## 2. `/운영현황`에서 확인할 수 있는 것

- 전체 사용자 수
- 총 포인트 거래 수
- 교환 대기 수
- 인증 대기 수
- 활성 미션 수
- 활성 상점 항목 수
- 오늘 체크인 수
- 오늘 반응 승인 수
- 오늘 포인트 거래 수
- 미션 관리 허브
- 참여자 초대 안내문
- 초대 전 점검
- 환경 설정 점검

처리가 필요한 항목은 기존 운영자 명령어로 이어서 처리합니다.

## 3. 교환 대기 확인 방법

`/운영현황` 실행 후 `교환 대기`를 선택합니다.

대기 중인 신청 ID, 신청자, 항목명, 필요 포인트, 신청 시각, 상태를 확인합니다. 실제 지급 완료, 취소, 환불 완료 처리는 `/교환관리`에서 진행합니다.

예시:

```text
/교환관리 신청id:신청ID 처리:지급완료
```

## 4. 인증 대기 확인 방법

`/운영현황` 실행 후 `인증 대기`를 선택합니다.

`/인증` 명령어로 접수된 pending 제출을 확인합니다. 미션 인증 채널에서 ✅/❌ 반응으로 처리한 기록은 `반응 승인 기록` 메뉴에서 따로 확인합니다.

예시:

```text
/인증관리 제출id:제출ID 처리:승인
/인증관리 제출id:제출ID 처리:반려 메모:확인 필요
```

## 5. 포인트 로그 확인 방법

`/운영현황` 실행 후 `최근 포인트 로그`를 선택합니다.

최근 거래의 날짜, 사용자, 타입, 포인트 변화량, 사유, 잔액을 확인합니다. 더 자세한 조회는 `/포인트로그`를 사용합니다.

예시:

```text
/포인트로그
/포인트로그 종류:earn
```

## 6. 미션/상점 상태 확인 방법

`/운영현황` 실행 후 `미션/상점 상태`를 선택합니다.

활성 수, 상태별 수, 최근 등록 항목을 확인합니다. 상태 변경이나 내용 수정은 기존 관리 명령어에서 처리합니다.

운영용 미션 등록 후에는 활성 미션 수가 1개 이상인지 확인합니다. 운영용 상점 등록 후에는 활성 상점 항목 수가 1개 이상인지 확인합니다. 0으로 보이면 아직 등록하지 않았거나 `paused`, `soldOut`, `hidden` 상태일 수 있으므로 `/미션관리 작업:목록`, `/상점관리 작업:목록`에서 상태를 다시 확인합니다.

```text
/미션관리 작업:목록
/상점관리 작업:목록
```

## 7. 반응 승인 기록 확인 방법

`/운영현황` 실행 후 `반응 승인 기록`을 선택합니다.

미션 인증 채널에서 운영자가 ✅ 또는 ❌ 반응으로 처리한 최근 기록을 확인합니다. 전체 기록 백업은 `/운영내보내기`를 사용합니다.

## 8. 미션 관리 허브 사용 방법

`/운영현황` 실행 후 `미션 관리 허브`를 선택합니다.

허브에서는 현재 등록된 미션 목록, 선택 미션의 상태, 참여자 안내문 미리보기를 확인합니다. `새 미션`, `수정`, `활성화`, `비활성화`, `종료`, `새로고침` 버튼으로 Discord 안에서 기본 미션 관리를 진행할 수 있습니다.

미션을 참여자에게 보이게 하려면 상태가 `active`여야 합니다. 오늘의 미션 채널 사진 제출, 검토 채널 승인/반려, 하루 1회 중복 지급 차단은 별도 흐름이므로 허브에서 바꾸지 않습니다.

### 템플릿/요일별 오늘의 미션 사용

미션 관리 허브에는 반복해서 쓸 수 있는 미션 템플릿 목록과 요일별 추천 미션이 함께 표시됩니다.

1. `/운영현황`에서 `미션 관리 허브`를 선택합니다.
2. `미션 템플릿` 영역에서 월요일 체크인, 화요일 사진 기록, 수요일 대화, 목요일 회고, 금요일 주간 정리 같은 추천 흐름을 확인합니다.
3. `오늘의 추천` 영역에서 현재 KST 요일에 맞는 추천 템플릿을 확인합니다.
4. 필요하면 템플릿 select 메뉴에서 다른 템플릿을 고릅니다.
5. `템플릿을 오늘의 미션으로 적용` 버튼을 누릅니다.
6. local 파일이 없어 예시 템플릿이 보이는 경우에도 운영자가 선택하면 오늘의 active 미션으로 복사 생성할 수 있습니다.
7. 이미 오늘 날짜의 active 미션이 있으면 새로 만들지 않고 기존 미션을 종료하거나 비활성화한 뒤 다시 시도하라고 안내합니다.
8. 적용 후 생성된 active 미션을 확인합니다.
9. `공지 미리보기`로 참여자에게 보일 제목, 설명, 포인트, 인증 방법, 하루 1회 지급 안내를 확인합니다.
10. 문제가 없으면 `오늘의 미션 게시`를 눌러 `TODAY_MISSION_CHANNEL_ID`로 설정된 #오늘의-미션 채널에 게시합니다.
11. 인증 업로드, 승인/반려, 포인트 지급, 중복 지급 차단, Google Sheets 기록은 기존 흐름대로 확인합니다.
12. 이미 오늘 게시된 기록이 있으면 중복 게시하지 않고 운영자에게만 안내합니다.

이번 MVP는 자동 게시를 하지 않습니다. 자동 게시, 예약 게시, 공지 문구 세부 편집은 후속 작업입니다.

자세한 템플릿 필드와 복사 생성 기준은 [미션 템플릿 운영 가이드](mission-template-guide.md)와 [관리자 미션 관리 허브 MVP](admin-mission-management-hub.md)를 함께 확인합니다.

## 9. 참여자 초대 안내문 확인 방법

`/운영현황` 실행 후 `참여자 초대 안내문` 버튼을 누르거나, 드롭다운에서 같은 항목을 선택합니다.

운영자에게만 보이는 private/ephemeral 응답으로 두 가지 복사용 문구가 표시됩니다.

- 짧은 초대 공지 버전
- 자세한 첫 입장 안내 버전

안내문에는 환영 문구, 참여동의 확인, 이름표/색상 고르기, `/안내`와 `🌱 처음 왔다면 여기부터` 버튼, 오늘의 미션 참여, 포인트/미니게임/상점은 선택 활동이라는 안내, 운영진 문의 안내가 포함됩니다.

초대 전에는 실제 서버에서 쓰는 채널명과 운영 방식에 맞게 문구를 확인한 뒤 공지 채널에 직접 복사해 게시합니다. 실제 Discord 채널 ID, 비공개 링크, 토큰, Google Sheets URL은 문구에 넣지 않습니다.

이번 MVP는 자동 게시를 하지 않습니다. 자동 게시, 예약 게시, 채널 선택, 게시 이력 저장은 후속 작업입니다.

## 10. 초대 전 점검 모드 사용 방법

`/운영현황` 실행 후 `초대 전 점검` 버튼을 누르거나, 드롭다운에서 `초대 전 점검`을 선택합니다.

운영자에게만 보이는 private/ephemeral 응답으로 실제 참여자를 초대하기 전 확인할 체크리스트가 표시됩니다. 이 기능은 상태 확인 전용입니다. 자동 수정, 자동 게시, 미션 생성, 포인트 지급은 하지 않습니다.

점검 결과는 아래 기준으로 읽습니다.

- `✅ 준비됨`: 지금 운영에 사용할 수 있는 상태입니다.
- `⚠️ 확인 필요`: 초대 전 운영자가 설정, 권한, active 데이터 중 하나를 확인해야 합니다.
- `ℹ️ 선택 항목`: 별도 채널이나 보조 연동을 쓰는 운영이면 확인하고, 현재 운영 방식에서 쓰지 않으면 넘어갈 수 있습니다.

초대 전에는 특히 아래 항목을 확인합니다.

- 참여자 안내/온보딩: `/안내`, `🌱 처음 왔다면 여기부터`, 참여자 초대 안내문이 보이는지 확인합니다.
- 필수 채널: `LOG_CHANNEL_ID`, `TODAY_MISSION_CHANNEL_ID`, `ACTIVITY_REVIEW_CHANNEL_ID`, `MINIGAME_CHANNEL_ID`, `POINT_REDEEM_CHANNEL_ID`가 설정되어 있고 봇이 채널 접근과 메시지 전송을 할 수 있는지 확인합니다.
- 오늘의 미션: active 상태의 오늘의 미션이 있는지, 오늘의 미션 채널에 게시 가능한지, 오늘 이미 게시된 기록이 있거나 중복 게시 방지 기록을 만들 수 있는지 확인합니다.
- 미션 인증/검토: 검토 알림 채널과 승인/반려 반응 흐름에 필요한 채널 접근 권한을 확인합니다.
- 포인트/교환: `/포인트` 확인 흐름, active 상점 항목, 교환 신청 알림 채널을 확인합니다.
- 미니게임: `MINIGAME_CHANNEL_ID`와 채널 권한을 확인합니다. 미니게임은 하루 4회, 하루 최대 40P 제한으로 안내됩니다.
- Google Sheets 기록: `GOOGLE_SHEETS_LOGGING_ENABLED`와 `GOOGLE_SHEETS_WEB_APP_URL` 설정 여부만 확인합니다. 실제 URL이나 검증 값은 화면에 표시하지 않습니다.

문제가 표시되면 먼저 Railway Variables, Discord 채널 권한, active 미션 상태, Google Sheets 설정을 확인합니다. active 미션이 없으면 미션 관리 허브에서 템플릿을 오늘의 미션으로 적용하거나 새 미션을 active로 만든 뒤 다시 점검합니다. `POINT_REDEEM_CHANNEL_ID`가 없으면 교환 신청 알림을 받을 운영진 채널을 정한 뒤 변수와 권한을 확인합니다.

## 11. 환경 설정 점검 방법

`/운영현황` 실행 후 `환경 설정 점검`을 선택합니다.

운영자에게만 보이는 응답에서 주요 채널 환경변수와 Google Sheets 보조 로그 설정 상태를 확인합니다. 새 Slash Command가 아니라 기존 운영자 허브의 드롭다운 항목입니다.

채널 환경변수는 아래 항목을 확인합니다.

- 환경변수 설정 여부
- 설정된 채널 ID
- Discord에서 채널을 찾을 수 있는지
- 봇이 해당 채널에 접근 가능한지
- 메시지 전송 권한이 있는지
- 권장 항목인지 선택 항목인지

권장 항목이 미설정이거나 채널을 찾지 못하면 운영 중 알림, 검토, 미니게임 제한 흐름이 기대대로 보이지 않을 수 있습니다. 선택 항목은 별도 채널을 운영할 때만 설정합니다. 선택 항목이 미설정으로 표시되는 것은 오류가 아니라 현재 운영 방식 안내입니다.

Google Sheets 보조 로그는 `GOOGLE_SHEETS_LOGGING_ENABLED`가 `true`인지와 `GOOGLE_SHEETS_WEB_APP_URL`이 설정됐는지만 표시합니다. Web App URL 전체값, secret, token 같은 민감한 값은 표시하지 않습니다.

## 12. 데이터 내보내기 방법

운영 데이터는 정기적으로 백업합니다.

```text
/운영내보내기 종류:요약 형식:요약
/운영내보내기 종류:포인트 형식:CSV
/운영내보내기 종류:교환 형식:JSON
/운영내보내기 종류:인증 형식:JSON
/운영내보내기 종류:전체 형식:JSON
```

내보낸 파일에는 사용자 ID, 표시 이름, 인증 내용, 운영 메모가 포함될 수 있습니다. 외부 공유 전 포함 내용을 확인합니다.

## 13. 운영 전 체크리스트

- `/안내`가 정상 작동하는지 확인합니다.
- 테스트 참여자 계정으로 `/안내`의 `🌱 처음 왔다면 여기부터` 버튼을 눌러 참여동의 확인, 이름표/색상, 오늘의 미션, 포인트, 미니게임, 상점 안내가 private/ephemeral로 보이는지 확인합니다.
- 참여자 초대 전 [처음 참여자 안내](first-time-participant-guide.md)의 복사용 안내 문구가 실제 채널명과 맞는지 확인합니다.
- `/운영현황`의 `초대 전 점검`에서 준비됨, 확인 필요, 선택 항목을 확인합니다.
- `/운영현황`의 `참여자 초대 안내문`에서 짧은 공지와 자세한 첫 입장 안내를 확인하고, 운영자가 직접 복사/게시할 문구를 확정합니다.
- 운영자 계정이 `ManageMessages` 또는 `Administrator` 권한을 가지고 있는지 확인합니다.
- `/운영현황`의 `환경 설정 점검`에서 권장 채널 환경변수와 메시지 전송 권한을 확인합니다.
- `/미션관리`로 운영용 기본 미션을 1개 이상 등록하고 active 상태로 둡니다.
- `/운영현황`의 `미션 관리 허브`에서 운영용 기본 미션, 미션 템플릿, 요일별 추천 미션이 보이는지 확인합니다.
- 템플릿을 오늘의 미션으로 적용한 뒤 active 미션이 1개만 생성되는지 확인합니다.
- `공지 미리보기`와 `오늘의 미션 게시`가 운영자에게만 결과를 알려주는지 확인합니다.
- `TODAY_MISSION_CHANNEL_ID` 채널에 봇이 메시지를 보낼 수 있는지 확인합니다.
- `/상점관리`로 운영용 기본 상점 항목을 1개 이상 등록하고 active 상태로 둡니다.
- `/admin`에서 활성 미션 수와 활성 상점 항목 수가 0이 아닌지 확인합니다.
- ✅/❌ 반응 승인 흐름이 테스트 계정에서 정상 작동하는지 확인합니다.
- `/운영현황` 첫 화면과 드롭다운이 운영자에게만 보이는지 확인합니다.

## 14. 운영 중 체크리스트

- `/운영현황`에서 교환 대기 건을 확인합니다.
- `/운영현황`에서 인증 대기 건을 확인합니다.
- 최근 포인트 로그에서 이상 지급이나 중복 지급이 없는지 확인합니다.
- 미션/상점 상태가 실제 운영 기준과 맞는지 확인합니다.
- 미션 수정이 필요하면 `/운영현황`의 `미션 관리 허브` 또는 `/미션관리`에서 처리합니다.
- 매일 운영 시작 전 미션 관리 허브에서 오늘의 추천 템플릿을 확인하고, 적용 후 미리보기와 게시 버튼으로 #오늘의-미션 채널에 공지합니다.
- 반응 승인 기록이 정상적으로 남는지 확인합니다.

## 15. 운영 후 백업 체크리스트

- `/운영내보내기 종류:요약 형식:요약`으로 수량을 확인합니다.
- `/운영내보내기 종류:전체 형식:JSON`으로 전체 백업을 저장합니다.
- 필요한 경우 포인트, 교환, 인증 데이터를 CSV 또는 JSON으로 별도 저장합니다.
- 외부 공유 전 개인정보와 운영 메모 포함 여부를 확인합니다.
