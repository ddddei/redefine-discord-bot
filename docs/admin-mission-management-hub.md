# 관리자 미션 관리 허브 MVP

이 문서는 Discord 안에서 운영자가 미션을 확인, 생성, 수정, 상태 변경하는 관리자용 허브의 현재 구현 범위와 운영 방법을 정리합니다.

## 현재 구조 요약

- 참여자 미션 목록은 `data/missions.local.json`을 기준으로 동작합니다.
- 미션 템플릿은 `data/mission-templates.local.json`이 있으면 그 파일을, 없으면 `data/mission-templates.example.json`을 읽어 허브에 표시합니다. fallback 예시 템플릿도 운영자가 직접 선택하면 오늘의 미션으로 복사 생성할 수 있습니다.
- 저장과 조회는 `src/pointsRepository.js`의 미션 repository 함수가 담당합니다.
- `status`가 `active`인 미션만 참여자 `/미션` 목록에 노출됩니다.
- 템플릿을 오늘의 미션으로 적용하면 기존 `missions` 구조의 active 미션이 생성됩니다.
- 기존 `/미션관리` 명령은 목록, 추가, 수정, 활성화, 일시중지, 종료 작업을 계속 지원합니다.
- 오늘의 미션 채널에 사진이나 글을 올려 접수되는 흐름은 `src/todayMission.js`와 `TODAY_MISSION_CHANNEL_ID` 기반 흐름입니다. 이번 허브는 이 제출, 승인/반려, 중복 지급 차단, Google Sheets append 흐름을 변경하지 않습니다.

## 구현한 기능

- `/운영현황`의 운영자 허브 select 메뉴에 `미션 관리 허브` 항목을 추가했습니다.
- 허브 화면에서 현재 등록된 미션 목록과 선택 미션 상태를 확인할 수 있습니다.
- 선택 미션의 참여자 안내문 미리보기를 표시합니다.
- 허브 화면에서 반복 사용 가능한 미션 템플릿 목록을 확인할 수 있습니다.
- 월요일부터 금요일 중심의 요일별 추천 미션과 오늘 요일의 추천 미션을 확인할 수 있습니다.
- 템플릿을 선택한 뒤 `템플릿을 오늘의 미션으로 적용` 버튼으로 오늘 날짜의 active 미션을 만들 수 있습니다.
- 예시 템플릿을 선택해도 적용은 막지 않고, 운영자에게만 예시 템플릿 안내를 보여줍니다.
- 이미 오늘 날짜의 active 미션이 있으면 새 미션을 중복 생성하지 않고 기존 미션을 종료하거나 비활성화한 뒤 다시 시도하라고 안내합니다.
- 오늘 날짜 active 미션을 기준으로 `공지 미리보기`를 운영자에게만 보여줄 수 있습니다.
- `오늘의 미션 게시` 버튼으로 `TODAY_MISSION_CHANNEL_ID` 채널에 참여자용 안내 메시지를 게시할 수 있습니다.
- 같은 날짜에 이미 게시 기록이 있으면 중복 게시하지 않고 운영자에게만 안내합니다.
- 버튼으로 다음 작업을 할 수 있습니다.
  - 새 미션 생성
  - 선택 미션 수정
  - 선택 미션 활성화 또는 비활성화
  - 선택 미션 종료
  - 선택 미션 인증 필요 여부 켜기/끄기
  - 선택 템플릿을 오늘의 미션으로 적용
  - 오늘의 미션 공지 미리보기
  - 오늘의 미션 채널 게시
  - 허브 새로고침
- 생성/수정은 Discord modal로 입력합니다.
  - 미션 제목
  - 미션 설명/안내 문구
  - 지급 포인트
  - 상태
  - 미션 날짜 (YYYY-MM-DD, 비우면 오늘 날짜 또는 기존 날짜 유지)
- 인증 필요 여부(`requiresSubmission`)는 modal이 아니라 허브의 `인증 필요 켜기`/`인증 필요 끄기` 버튼으로 바로 전환합니다.
- 저장 후 결과는 운영자에게만 보이는 응답으로 안내합니다.

## 아직 보류한 기능

- 정해진 시간에 자동 게시하는 기능은 이번 MVP 범위에서 제외했습니다. 운영자가 미리보기 후 직접 `오늘의 미션 게시` 버튼을 누르는 흐름입니다.
- 자동 게시 시간, 예약 게시, 게시 문구 세부 편집은 후속 작업으로 남깁니다.
- `startAt`, `endAt`은 repository에 아직 쓰는 곳이 없는 자리표시 필드라 허브에서도 편집을 추가하지 않았습니다. 실제로 신청 가능 기간 제한이 필요해지면 그때 repository 동작과 함께 추가합니다.
- 운영 메모(`note`)는 modal에서 분리했습니다. Discord modal은 최대 5개 입력 필드만 제공하므로 날짜/인증 필요 전환 기능을 추가하며 메모 입력란을 빼고, 메모 수정은 기존 `/미션관리`로 진행합니다.
- 실제 Discord slash command 정의는 바꾸지 않았습니다. 새 명령어를 추가하지 않고 기존 `/운영현황` 허브에 붙였습니다.

## 운영자가 사용하는 방법

1. Discord에서 `/운영현황`을 실행합니다.
2. select 메뉴에서 `미션 관리 허브`를 선택합니다.
3. 기존 미션이 있으면 미션 select 메뉴에서 관리할 미션을 선택합니다.
4. 새 미션을 만들 때는 `새 미션` 버튼을 누르고 modal을 작성합니다.
5. 기존 미션을 고칠 때는 `수정` 버튼을 누르고 modal을 작성합니다.
6. 참여자에게 보이게 하려면 상태를 `active`로 저장하거나 `활성화` 버튼을 누릅니다.
7. 잠시 숨기려면 `비활성화` 버튼을 누릅니다. 이때 상태는 `paused`가 됩니다.
8. 더 이상 쓰지 않을 미션은 `종료` 버튼으로 `closed` 상태로 바꿉니다.
9. 템플릿을 쓰려면 템플릿 select 메뉴에서 항목을 고른 뒤 `템플릿을 오늘의 미션으로 적용`을 누릅니다.
10. 예시 템플릿을 고른 경우에도 적용은 진행되며, 운영자에게만 예시 템플릿 안내가 보입니다.
11. 이미 오늘 날짜의 active 미션이 있으면 기존 미션을 종료하거나 비활성화한 뒤 다시 시도합니다. MVP에서는 강제 덮어쓰기를 지원하지 않습니다.
12. 적용이 끝나면 허브에서 생성된 active 미션을 확인합니다.
13. `공지 미리보기`로 참여자에게 보일 안내 문구를 확인합니다.
14. 문제가 없으면 `오늘의 미션 게시`를 눌러 `TODAY_MISSION_CHANNEL_ID`로 설정된 #오늘의-미션 채널에 게시합니다.
15. 참여자 인증, 승인/반려, 포인트 지급, 중복 지급 차단, Google Sheets 기록이 기존 흐름대로 남는지 확인합니다.
16. 이미 오늘 게시된 기록이 있으면 봇이 중복 게시를 막고 운영자에게만 안내합니다.

상태 입력값은 `draft`, `active`, `paused`, `closed`, `archived`를 사용할 수 있습니다. 한국어로 `활성`, `비활성`, `일시중지`, `종료`, `초안`을 입력해도 각각 대응되는 상태로 저장됩니다.

## QA 체크리스트

- `/운영현황`에서 `미션 관리 허브`가 운영자에게만 열리는지 확인합니다.
- 템플릿 목록과 요일별 추천 미션이 허브에 표시되는지 확인합니다.
- 오늘의 추천 미션 미리보기가 현재 KST 요일 기준으로 표시되는지 확인합니다.
- 템플릿 적용 후 오늘 날짜의 active 미션이 1개 생성되는지 확인합니다.
- 이미 오늘 날짜의 active 미션이 있을 때 템플릿을 다시 적용해도 중복 생성하지 않는지 확인합니다.
- active 미션이 없을 때 `공지 미리보기`가 자연스럽게 안내하는지 확인합니다.
- active 미션이 있을 때 `공지 미리보기`에 제목, 설명, 포인트, 인증 방법, 하루 1회 지급 안내가 보이는지 확인합니다.
- `TODAY_MISSION_CHANNEL_ID`가 없거나 채널 전송이 불가능할 때 운영자에게만 오류가 보이는지 확인합니다.
- `오늘의 미션 게시` 후 #오늘의-미션 채널에 안내 메시지가 올라가고, 같은 날짜 재게시가 차단되는지 확인합니다.
- `새 미션` modal로 제목, 설명, 포인트, 상태를 저장하고 허브에 다시 표시되는지 확인합니다.
- 상태가 `active`인 미션만 참여자 `/미션`에 보이는지 확인합니다.
- `수정` modal로 제목, 설명, 포인트, 상태를 변경한 뒤 저장 결과가 운영자에게만 보이는지 확인합니다.
- `활성화`, `비활성화`, `종료`, `새로고침` 버튼이 선택 미션 기준으로 동작하는지 확인합니다.
- 운영자 권한이 없는 계정이 허브 버튼이나 modal 저장을 시도했을 때 거부되는지 확인합니다.
- 오늘의 미션 채널 사진 제출, 검토 채널 버튼 승인/반려, 하루 1회 중복 지급 차단, Google Sheets append가 기존처럼 동작하는지 확인합니다.
- 템플릿으로 만든 active 미션이 기존 `/미션` 또는 `/인증` 제출 구조에서 `missionId`, `rewardPoints`, `requiresSubmission`, `status`를 유지하는지 확인합니다.

## 다음 단계 제안

- 오늘의 미션 안내 문구 편집과 날짜별 활성화 이력을 더 세분화한 별도 구조를 설계합니다.
- 날짜별 활성 미션과 반복 템플릿을 분리해 `dailyMissionActivations` 형태로 관리합니다.
- 운영자가 승인한 경우에만 지정 채널로 자동 게시하는 후속 기능을 검토합니다.
- modal 5필드 제한을 넘는 편집 항목은 단계형 modal 또는 select 기반 보조 버튼으로 분리합니다.
