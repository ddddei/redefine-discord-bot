## 3. 다음 개발 우선순위

### 완료·머지 대기 — `handlers.js` 분할 v1

**구현 완료 / 동작 변경 없음 / PR·머지 대기**

기존 export와 테스트 진입점을 유지하면서 라우팅과 도메인 구현을 분리합니다. PR #76의 미니게임 랭킹과 PR #77의 웹게임 지급 경로까지 보존해야 합니다. 기준 문서는 [handlers 모듈 분할 v1 계획서](handlers-modularization-v1-plan.md)입니다.

완료 결과:

- `handlers.js`를 조립·호환 export 중심의 얇은 진입점으로 축소
- interaction 라우팅 우선순위, command, customId, 응답 문구, 권한 유지
- 참여자, 활동/포인트, 미션·상점 관리, 운영 허브, 웹게임 지급을 독립 모듈로 분리
- `pointsRepository`와 웹게임 repository의 중복 생성 방지
- 기존 테스트 무수정 통과 우선, 신규 router 계약 테스트 추가

### 1순위 — 운영 콘솔 쓰기 Phase 1 재검토

**우선순위 상 / 크기 중 / handlers 분할 권장 선행**

`ADMIN_WRITE_ENABLED`, 별도 쓰기 토큰, 감사 로그, 서버 상태 재검증을 전제로 교환·인증·포인트·미션/상점 처리를 웹 콘솔에서 제공하는 계획입니다. 실제 운영 데이터를 변경하므로 Railway 영속 경로 검증 전 기본 활성화하지 않습니다.

[운영 콘솔 마스터 플랜](ops-console-master-plan.md)과 `prompts/codex/admin-console-write-v1.md`는 실행 직전 PR #74~#77을 기준으로 다시 감사해야 합니다. `/admin`은 현재 계속 읽기 전용입니다.

### 2순위 — 운영 지연 리마인더 v1

**우선순위 중~상 / 크기 중 / 현재 지시서상 콘솔 Phase 1 선행**

`prompts/codex/ops-reminder-v1.md`는 운영 콘솔 Phase 1 완료를 선행조건으로 둡니다. 리마인더를 Discord 읽기 전용 요약으로 먼저 독립시킬지, 콘솔 Phase 1 이후 진행할지 재결정하기 전에는 그대로 실행하지 않습니다.

## 8. 표준 작업 방식

1. 최신 `main`과 이 로드맵 대조
2. 주 에이전트가 계획서·구현 지시서 작성 및 검토
3. 구현은 전용 브랜치와 격리된 작업공간에서 서브 에이전트 수행
4. 주 에이전트가 diff·보안·운영 안전성 최종 검수
5. 표적 테스트와 `npm run check:release` 통과
6. PR CI 성공 후 머지
7. Discord·Railway 실환경 항목은 수행하지 못했으면 `운영자 확인 대기` 유지

기능 무변경 리팩터링은 기존 테스트 수정 없이 통과하는 것을 우선합니다. 테스트가 구현 세부에 과도하게 결합돼 불가피하게 수정해야 하면 변경 이유와 이전 계약 유지 근거를 별도로 보고합니다.
