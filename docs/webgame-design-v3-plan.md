# 웹게임 디자인 고도화 v3 계획서 — 톤 성숙화 (탈캐주얼)

디자인 v2([webgame-design-v2-plan.md](webgame-design-v2-plan.md), PR #58)의 후속 계획입니다. v2가 "고유 아트(아이덴티티)"를 만들었다면, v3는 **톤 성숙화** — "귀엽지만 장난감 같지는 않은", 프리미엄 모바일 게임의 마감을 목표로 합니다. 구현 전 [webgame-design-guide.md](webgame-design-guide.md)와 저장소 [AGENTS.md](../AGENTS.md), [src/AGENTS.md](../src/AGENTS.md), [scripts/AGENTS.md](../scripts/AGENTS.md)를 먼저 읽어 주세요.

## 0. 선행 조건과 운영 원칙

- PR #58(디자인 v2)이 `main`에 머지된 뒤 진행. 브랜치: `feat/webgame-design-v3`
- 순수 정적 파일 원칙 유지: 빌드·npm 의존성 금지, 래스터 이미지 금지. **웹폰트만 예외 후보** (4절에서 정책 결정).
- 게임 로직 무변경 (로직 스모크 테스트 3본 무수정 통과). 생존전은 범위 밖.
- v2 에셋 19종은 **유지가 기본** — 캐릭터가 아니라 프레임을 바꾼다. 필요 시 채도 보정 수준만 허용(형태·외곽선 불변).

## 1. 진단 — "캐주얼틱함"은 어디서 오는가

현 화면에서 유치한 인상을 만드는 요소를 분해하면 (에셋 자체가 아니라 프레임):

| 요소 | 현재 | 문제 |
| --- | --- | --- |
| 배경 | 크림 단색(`#fff7ec`) 전면 | 깊이 없음 — "웹 문서" 느낌의 최대 원인 |
| 팔레트 | 고채도 파스텔 + 주황 강조 | 유아 앱 연상. 성숙한 톤은 채도를 낮추고 명도 대비로 위계를 만듦 |
| 버튼/칩 | 알약형 + 밝은 주황 솔리드 | 장난감 버튼. 프리미엄 게임 UI는 각진 라운드 + 절제된 강조 |
| 타이포 | 시스템 고딕 단일, 위계 약함 | 게임 타이틀·수치·본문이 같은 표정 |
| 그림자 | 부드러운 단층 그림자 | 마감 디테일(엣지 하이라이트·이중 보더) 부재 |

→ v3는 이 다섯 축을 재설계합니다. 캐릭터 에셋은 성숙한 프레임 위에 놓이면 "프리미엄 캐주얼"(쿠키런 킹덤 방향)로 읽힙니다.

## 2. 진행 구조 — v2와 동일하게 중간 승인 1회

```
1단계: 무드 시안 3안 (Fable 직접, 화면 단위) ──▶ [사용자 선택] ──▶ 2~4단계: 가이드 개정·프레임·적용 (샌드위치)
```

v2 시안이 "캐릭터 1개"였다면 v3 시안은 **같은 화면(덱 전투 화면 기준) 전체를 무드 3안으로** 보여줍니다. 톤은 화면 단위로만 판단 가능하기 때문입니다.

## 3. 1단계 — 무드 시안 3안

| 방향 | 컨셉 | 배경 | 팔레트 경향 |
| --- | --- | --- | --- |
| A. 디저트 부티크 | 고급 디저트 카페의 낮 | 웜 뉴트럴(라떼·베이지) 다층 그라디언트 + 은은한 비네트 | 채도 낮춘 웜톤, 딥브라운 위계, 강조색은 카라멜·버건디 소량 |
| B. 이브닝 라운지 | 해 진 뒤의 공방, 조명 아래 | 딥브라운·플럼 다크 배경 + 크림 카드가 떠 있는 구조 | 다크 프레임 + 웜 라이트. 성숙함 최대, 대비 커서 에셋이 보석처럼 보임 |
| C. 스토리북 | 그림책의 한 페이지 | 종이 느낌의 오프화이트 + 잉크 라인 장식(테두리 플러리시) | 뮤트 파스텔(채도 -30%), 잉크색 위계, 클래식한 프레임 |

- 각 안은 덱 전투 화면 1장을 CSS 목업으로 구성(실제 에셋 사용), 브라우저 스크린샷으로 비교 제시. 혼합 지시 가능.
- 이 단계는 Fable이 직접 수행.

## 4. 2단계 — 디자인 가이드 개정 + 정책 결정

[webgame-design-guide.md](webgame-design-guide.md)에 "톤" 층을 추가 개정:

- **팔레트 v3**: 선택된 무드의 서페이스 스케일(배경 다층·패널·엣지), 채도 낮춘 강조색 체계, 상태색. 기존 에셋 서브 팔레트와의 공존 규칙(에셋은 고채도 유지 — 뮤트된 프레임 위의 포인트가 됨).
- **타이포 정책 (결정 필요)**: ① 시스템 폰트 유지 + 웨이트·자간·크기 스케일로 위계 강화 (용량 0) ② 제목 전용 경량 웹폰트 1종 번들 (예: 한글 디스플레이 서브셋 woff2, 관리자 서버 정적 서빙 — 용량 상한 300KB, 라이선스 명시 필수). **기본 권장은 ①로 시작해 아쉬우면 ②** — 시안에서 두 버전을 함께 보여 판단.
- **마감 규칙**: 패널 이중 보더(외곽 1px 딥 + 내측 1px 하이라이트), 버튼 pressed 상태(눌린 오프셋), 라운드 스케일 하향(알약 → 12~16px), 그림자 2층(접지+확산).
- **배경 규칙**: 게임별 배경 구성(다층 그라디언트 + 대형 장식 SVG 소품의 심도 배치 + 비네트), reduced-motion·저사양 고려(패럴랙스 금지).

## 5. 3단계 — 공통 프레임 개편 (`game-ui.css` v3)

- 서페이스/팔레트 토큰 교체, `gk-` 컴포넌트(버튼·칩·패널·헤더·모달) 마감 규칙 적용.
- 배경 시스템: `gk-stage`(게임 공통 배경 컨테이너 — 그라디언트 층 + 비네트 + 장식 슬롯) 신설.
- 기존 게임별 CSS의 v2 시대 값(크림 전면 배경 등)을 v3 토큰 소비로 정리.

## 6. 4단계 — 게임별 적용

- **매치3**: 보드 프레임 마감(트레이 느낌의 이중 보더), 배경 심도, 타일 배경 톤을 새 팔레트에 맞춰 재조정.
- **방치형**: 무대 6단계 배경을 `gk-stage` 위에 단계별 분위기(그라디언트+기존 타일 소품 심도 배치)로 — v2에서 미룬 "무대 배경"의 저비용 구현. 승급할수록 화면 톤이 풍부해지게.
- **덱**: 전투 화면을 시안 무드로 (적 스포트라이트, 손패 트레이 마감), 카드 프레임 고급화(등급별 테두리 — 정예급 골드 라인).
- 카피 톤 불변. 연출은 v1·v2 원칙 유지(추가 연출은 범위 밖 — 이번엔 정적 마감에 집중).

## 7. 테스트 / QA / 커밋

- 기존 테스트 체계 유지: 로직 3본 무수정 통과, 정적 테스트들(shared-ui·design-assets) 필요 시 갱신. 웹폰트 채택 시 에셋 정적 테스트에 폰트 파일·라이선스 문구 검증 추가.
- 수동 QA: 3종 데스크톱·모바일, 다크한 무드 선택 시 명도 대비(WCAG AA 텍스트 대비) 확인, reduced-motion, 기존 세이브 이어짐. **QA는 반드시 adminServer 경유** (v2 교훈).
