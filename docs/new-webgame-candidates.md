# 신규 웹게임 후보 검토

다섯 번째 이후 웹게임 후보를 평가 기준과 함께 정리한 문서입니다. 선정 시 해당 후보의 상세 계획서를 따로 만듭니다 (기존 4종의 계획서 형식).

## 1. 평가 기준 (기존 4종에서 확립된 제약·자산)

| 기준 | 내용 |
| --- | --- |
| 아키텍처 | 정적 파일, 로직(`engine.js`류)/표시(`game.js`) 분리, Node 로드 가능한 순수 로직(리플레이 검증 대비), 신규 의존성 금지 |
| 시드 결정성 | 같은 시드 = 같은 판. **오늘의 도전·랭킹·리플레이 검증에 편입되는 조건** |
| 모바일 퍼스트 | 인앱 브라우저, 엄지 존, 첫 화면 ≤ 400KB, 저사양, 무음·무진동 |
| 참여자 맥락 | 세션 5~15분(또는 방치), 실패 부담 낮음, 조급함 유발 요소(타이머·생명) 금지 |
| 소셜 인프라 재사용 | GameLink(연결·제출·랭킹·응원)와 오늘의 도전 서버가 이미 있음 — **신규 게임의 소셜 기능은 gameId 등록 수준의 비용** |
| 세계관 | 간식 스토리북 톤(3종) 또는 던전월드 다크 판타지(생존전). 신규는 간식 톤 권장 |

## 2. 추천 후보 (우선순위순)

### 후보 1 — 오늘의 간식 단어 (한글 단어 데일리, 워들류) ★ 최우선 추천

- **왜**: 오늘의 도전 인프라와 궁합이 가장 좋은 장르 — 원래가 "하루 한 단어" 문화라서 일일 시드 챌린지의 대표 사례가 됨. "오늘 N명이 함께 도전했어요"가 자연스럽고, 정답 공유 문화가 가벼운 대화 소재(참여자 목적 ①)를 만든다.
- **형태**: 받침 포함 한글 2~3글자 간식/일상 단어, 자모 분해 기반 힌트(자리·포함 여부). 6회 시도.
- **점수/랭킹**: 시도 횟수 기반 — 다만 이 장르는 랭킹보다 "성공/참여"가 어울림. **랭킹 없이 참여 수 + 분포("3번 만에 맞춘 사람 12명")만 노출**하는 첫 사례로 설계 권장(경쟁 부담 최소 게임).
- **비용**: 소(로직 단순, 콘텐츠는 단어 목록 큐레이션). **주의**: 단어 목록이 서버가 아닌 클라이언트에 있으면 정답이 노출됨 — 정답만 서버 `/daily` 응답으로 내려주는 설계 필요(기존 daily 엔드포인트 확장).
- **리스크**: 단어 풀 고갈·난이도 편차 — 운영 큐레이션 절차 문서 동반.

### 후보 2 — 간식 합치기 (2048류 스와이프 퍼즐) ★ 차순위 추천

- **왜**: 매치3의 스와이프 입력 자산 재사용, 점수 랭킹에 자연스럽게 맞음, 세션 5~10분, 구현 소형. "쿠키 2개 → 파이 → 케이크" 승급이 간식 세계관·v3 원화와 잘 맞음.
- **시드 결정성**: 새 타일 배치를 시드 RNG로 — 오늘의 도전 즉시 편입 가능.
- **비용**: 소. 4종 중 가장 작은 볼륨으로 예상(보드 4×4, 규칙 단순).
- **리스크**: 장르 피로도(흔한 게임) — 원화·승급 연출로 차별화.

### 후보 3 — 간식 배달 길 찾기 (소코반/퍼즐 배달)

- **왜**: 머리 쓰는 완료형 퍼즐 — 점수 경쟁이 아니라 "풀었다"의 만족. 매치3 M3(목표 모드)과 같은 축.
- **형태**: 손제작 레벨 팩 30~50개 + 진행 저장. 시드 생성이 아니라 레벨 큐레이션이라 **오늘의 도전과는 결이 다름**(일일 레벨 지정으로는 가능).
- **비용**: 중(레벨 디자인이 본체). 레벨 에디터 없이 JSON 레벨 정의로.

## 3. 검토 후 보류/제외 후보 (이유 명시)

| 후보 | 판정 | 이유 |
| --- | --- | --- |
| 리듬/타이밍 게임 | **제외** | 무음 정책과 정면 충돌(리듬은 소리가 본체). 재론하려면 정책부터 |
| 실시간 협동·대전 (io류) | **제외** | 정적 파일+단일 서버 아키텍처 범위 밖 (로드맵 7절 기존 결정) |
| 카드 뽑기·수집(가챠) | **제외** | 사행성 인상 회피 (포인트 안내 원칙과 동일 축) |
| 신경쇠약(짝 맞추기) | 보류 | Discord 버튼형 기억력 게임과 중복 |
| 낚시·수집 방치 | 보류 | 방치형(idle)과 장르 중복 — idle 파견 확장(I2)으로 흡수 권장 |
| 타워 디펜스 | 보류 | 볼륨 대비 차별화 애매, 실시간 성능 부담. 생존전 고도화가 우선 |
| 텍스트 어드벤처(웹) | 보류 | 던전월드(Discord)와 중복. 덱 D3(이벤트 칸)으로 작법만 흡수 |

## 4. 추천 착수 방식

1. **후보 1(단어 데일리)부터** — 비동기 소셜 v1의 운영 데이터가 쌓이는 시기에 "경쟁 없는 데일리"라는 새 축을 검증하기 좋고, 볼륨이 작다.
2. 후보 2는 매치3 M1(특수 타일)과 시기를 겹치지 않게 (같은 퍼즐 축이라 신선도 분산).
3. 어느 쪽이든 계획서에 gameId·점수 정책(랭킹 유무)·오늘의 도전 편입 여부를 명시적으로 결정하고 시작한다.
