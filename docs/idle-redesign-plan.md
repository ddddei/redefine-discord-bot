# 방치형 리디자인 v1 계획서 — "살아있는 작업대"

작성: 2026-07-13. 상태: **승인 대기**. 근거 레퍼런스: 방치형 장르 설계 자료(designthegame·apptrove 외) — 코어 루프(탭→업글)를 정중앙에, 빠른 탭 피드백, 진행바·마일스톤 상시 노출, 떠오르는 숫자 티커, juice(모든 입력에 지각 가능한 반응).

## 0. 배경 / 문제

2026-07-13 사용자 피드백: "방치형은 디자인 전체를 다시 가야 할 것 같다."

현 상태 진단 (`public/idle/`):

- **아무것도 움직이지 않는다** — 공방 탭은 정적 그림(무대 장면) + 버튼 3개. 방치형의 생명인 "돌아가고 있다"는 감각이 0.
- **무대 장면이 장식이다** — 화면 상단 절반을 차지하는 `#stage-scene`이 보기만 하는 그림. 탭 대상은 아래쪽 별도 버튼(`#make-snack-button`).
- **진행이 숨어 있다** — 다음 승급까지 얼마나 왔는지는 승급 버튼의 숫자를 읽고 암산해야 안다. 진행바는 하단 퀘스트 1개뿐.
- **생산이 보이지 않는다** — 초당 생산은 헤더 숫자만 갱신. 간식이 "만들어지는" 모습이 없다.

선행: **PR #88(무대 원화 8종) 머지** — 이 계획은 그 원화를 무대 배경으로 그대로 쓴다. PR #87과는 파일 겹침 없음(순서 무관).
착수 게이트: 없음.

## 1. 전체 구조

- 수정 범위: `public/idle/index.html`, `styles.css`, `game.js`(렌더·입력 배선·연출).
- **`engine.js` 무수정** — 클릭/생산/승급/퀘스트 계산은 기존 함수를 그대로 호출한다. 장면 탭도 기존 `makeSnackButton` 클릭 핸들러와 같은 경로(`Engine.getClickAmount` 등)를 태운다.
- `content.js`는 표시 전용 필드 추가만 허용(v2 선례) — 이번 범위에선 필요 예상 없음.
- 저장 스키마 불변, env 없음, `deploy-commands.js` 무변경 → **`npm run deploy` 불필요**.

## 2. 접근 방식

- 레퍼런스에서 차용하는 3원칙: ① 코어 루프가 화면의 주인공 ② 모든 탭에 즉각 피드백 ③ 진행(다음 목표까지)이 항상 보인다.
- 참여자 맥락 반영: 경쟁·압박 연출 금지, 차분한 톤 유지 — "바쁘게 몰아치는" 방치형이 아니라 "따뜻하게 돌아가는 공방". 알림·뱃지 도배 금지.
- 저사양 예산: 동시 애니메이션 요소 ≤ 3, transform/opacity만, 탭이 백그라운드면 정지(`document.hidden`), reduced-motion 존중.
- 단계별 커밋, 독립 롤백.

## 3. 단계별 계획

### 3-A. 장면 = 탭 타겟 (코어 루프 중앙화)

수정: `index.html`, `game.js`, `styles.css`.

- `#stage-scene` 전체를 버튼화(또는 투명 오버레이 버튼) — **장면을 탭하면 간식이 만들어진다**. 기존 `#make-snack-button`의 핸들러 경로 재사용.
- 탭 지점에서 간식 파티클 1개(+N 숫자와 함께)가 튀어오르고 사라진다(기존 `popup-layer` 티커 확장, 400ms).
- 기존 "간식 만들기" 버튼은 장면 하단에 얇은 보조 버튼으로 축소(접근성·설명 역할 유지 — 장면 탭을 모르는 사용자를 위한 안내 문구 포함).
- 캐릭터(제빵사 초상)를 장면 안으로 이동 — 탭할 때 살짝 움직이는 반응(scale 0.96, 120ms).

### 3-B. 진행 상시 가시화

수정: `index.html`, `game.js`, `styles.css`.

- 무대 장면 바로 아래 **승급 진행바**: `간식 보유 / 다음 승급 비용`을 바+퍼센트로 상시 표시(기존 `Engine.findStage` 데이터 재사용). 승급 가능해지면 바가 가득 차며 승급 버튼이 활성 색으로.
- 헤더의 초당 생산 칩에 미세 틱 애니메이션(숫자 갱신 시 opacity 펄스 1회 — 상시 루프 아님).

### 3-C. 생산 티커 ("돌아가고 있다" 감각)

수정: `game.js`, `styles.css`.

- 초당 생산이 0보다 클 때, 장면 안에서 작은 간식 아이콘(기존 시설 SVG 재사용)이 **2~4초 간격으로 1개씩** 떠올라 사라진다(떠오르는 방향 고정, 랜덤 위치, 로직 무관 — `Math.random` 허용: idle은 시드 무관 장르라는 기존 결정 재사용).
- 동시 존재 티커 ≤ 2로 캡. `document.hidden`이면 타이머 정지. reduced-motion이면 미표시.
- 파견 진행 중이면 장면 구석에 작은 배달 가방 아이콘 + 남은 시간 표시(배달 탭 안 열어도 보이게).

### 3-D. 레이아웃 재배치

수정: `index.html`, `styles.css`.

- 현 구성(장면 → 큰 버튼 → 승급 카드)의 중복·여백 정리: 장면(탭 타겟)이 커지고, 진행바·승급이 한 카드로 통합되고, 보조 버튼이 얇아진다. 목표: 첫 화면에서 스크롤 없이 "장면(탭) + 진행바 + 승급 + 퀘스트"가 보인다 (375×812 기준).
- 시설 구매 소품(`scene-props`)의 장면 내 배치를 원화와 어울리게 재조정(바닥선 정렬).

### 커밋 구성

단계당 1커밋(A~D) + QA 수정. PR 1개.

## 4. 성공 기준

- **S1 (장면 탭)**: 장면 탭 → 간식 수 증가 + 탭 지점 파티클 확인. 기존 버튼 경로와 동일 수치 증가(엔진 경로 공유) 확인.
- **S2 (진행바)**: 승급 비용 대비 보유량이 바로 표시되고, 승급 직후 다음 무대 기준으로 리셋됨을 확인. 최종 무대(6)에서는 환생 안내로 대체.
- **S3 (티커)**: 초당 생산 > 0에서 티커 등장, 0이면 미등장, 백그라운드 탭 전환 시 타이머 정지(콘솔 로그로 확인), reduced-motion에서 미표시.
- **S4 (스크롤 없는 첫 화면)**: 375×812에서 장면+진행바+승급+퀘스트가 스크롤 없이 보임 (스크린샷).
- **S5 (로직 불변)**: `engine.js` git diff 0건, `check:release` 전체 통과, 기존 저장 데이터로 이어하기 정상.
- **S6 (성능·전송량)**: CPU 4x에서 탭 연타(초당 5회) 시 파티클 끊김 없음. 첫 화면 ≤ 400KB 유지(신규 래스터 없음 — 기존 에셋 재사용이라 여유 전망).
- **S7 (톤)**: 신규 카피(안내 문구 등)가 차분한 기존 톤과 일치 — 사용자 육안 승인.

## 5. 제약 조건

- CommonJS·무의존성·정적 파일. `engine.js`(순수 로직) 비접촉 — 시각·입력 배선 전용.
- 신규 래스터 에셋 없음(기존 원화·SVG 재사용). 새 아이콘이 필요하면 SVG + 가이드 규칙.
- 애니메이션 transform/opacity 한정, 동시 ≤ 3, 상시 무한 루프는 황금 간식(기존) 외 추가 금지 — 티커는 "간격 반복"으로 루프와 구분.
- 참여자 배려: 압박·조급함을 유발하는 연출(카운트다운 점멸 등) 금지.
- CLAUDE.md 금기 위반 없음.
