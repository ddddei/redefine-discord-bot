# 검은 종 생존전 고도화 v1 계획서 — 모바일·전투 체감·메타 진행·Discord 연동 (완성 배포판)

`public/dungeonworld-survivors/`의 고도화 v1 전체 명세입니다. **전 항목 구현 시 배포 가능한 완성 상태.** 시각 판단 기준은 [dungeonworld-survivors-design-direction.md](dungeonworld-survivors-design-direction.md)(다크 판타지 톤 유지)를 따릅니다.

## 0. 확정 설계 결정 (2026-07-05 사용자 확정 — 모바일 포함·오늘의 도전 제외·주간 랭킹만)

1. **모바일 지원 포함** — 가상 스틱 추가. 단 구현 1단계가 성능 실측이며, 실측 결과에 따라 개체 수·이펙트 예산을 조정한다(포기 분기 아님 — 예산 조정으로 반드시 통과시키는 것이 목표. 3절).
2. **기본 세션 = 10분 퀵 런** — 기본 URL이 퀵 런, 30분은 `?mode=long`, 데모는 유지. 랭킹 제출은 퀵 런만.
3. **Discord 연동 편입** — gameId `survivors`, 주간 랭킹만(오늘의 도전 제외 — 실시간 입력 의존이라 "같은 판" 보장 불가, 문서에 사유 명시).
4. 무음·무진동 유지, 다크 판타지 톤 유지(간식 톤으로 바꾸지 않음).

## 0.1 완성 정의

1. 모바일(가상 스틱·세로/가로 대응·safe-area)에서 퀵 런 전체가 플레이 가능하다
2. 저사양 프로파일(CPU 4x 스로틀)에서 최다 개체 구간 30fps 이상
3. 타격 피드백 6종(피격/처치/경험치/레벨업/상자/진화)이 서로 다른 감각으로 읽힌다
4. 보스전이 경고 배너·전용 체력바·패턴명으로 분리된다
5. 메타 진행(종잔향·해금 12종·도전 과제 12종)이 동작한다
6. `/게임랭킹 게임:검은 종 생존전`이 동작한다 (deploy 필요)
7. `check:release` 통과, 신규 로직 테스트, QA 매트릭스 통과

## 1. 작업 A — 성능 예산 확립 (구현 1단계, 다른 작업의 게이트)

- 실측: 데스크톱 Chrome CPU 4x 스로틀 + 375×812 뷰포트에서 퀵 런 최다 개체 구간(적 + 투사체 + 보석) 프레임 측정.
- 목표 예산: **동시 적 ≤ 120, 투사체 ≤ 80, 파티클 ≤ 60에서 30fps** — 미달 시 순서대로: 파티클 상한 하향 → 오프스크린 컬링 강화 → 적 상한 하향(스폰 밀도 유지하되 체력 상향으로 난도 보존).
- 확정 예산을 `content.js` 상수로 명문화하고 보고서에 실측표 첨부. 이후 모든 작업(B~F)은 이 예산 내에서.

## 2. 작업 B — 모바일 조작·뷰포트

- **가상 스틱**: 플로팅형 — 화면 왼쪽 60% 영역 터치 시작점이 스틱 중심, 반경 56px, 데드존 12%, Pointer Events(`setPointerCapture`), 이동 벡터만 산출(기존 이동 로직 함수에 주입 — 키보드 경로와 동일 코드 경로). 오른쪽 40%는 UI 영역(레벨업 카드·일시정지).
- 키보드 조작 공존(데스크톱 회귀 없음).
- 뷰포트: `viewport-fit=cover`·`100dvh`·safe-area·theme-color — 모바일 하드닝 계획서(3~5절) 스펙을 생존전에 동일 적용. 세로 모드: 캔버스 letterbox + 상하 UI 재배치(HP·시간 상단, 스틱 영역 하단). 가로 모드 권장 안내 1줄(강제 회전 없음).
- 레벨업 카드·결과 화면 버튼 44px 타겟, 엄지 존.
- 첫 화면 전송량 예산: 생존전은 데스크톱 전용이었으므로 첫 실측 — **≤ 500KB**(에셋 볼륨 감안, 3종보다 완화)로 설정하고 실측 보고. 초과 시 스프라이트 지연 로드.

## 3. 작업 C — 전투 체감 (방향서 1.1~1.4 구현)

| 피드백 | 스펙 |
| --- | --- |
| 피격(적) | 스프라이트 흰색 틴트 60ms + 2px 넉백 |
| 처치 | 스케일 1.2→0 페이드 150ms + 재화 팝 |
| 피격(플레이어) | 화면 가장자리 붉은 비네트 200ms (풀스크린 플래시 금지 — 광과민 배려) |
| 경험치 획득 | 보석 자석 흡인 곡선 + 획득 순간 게이지 펄스 |
| 레벨업 | 시간 정지 + 카드 등장은 기존, 추가로 플레이어 주변 원형 파문 1회 |
| 상자/진화 | 상자 개봉 모달의 헤더 구분(기존) + 진화는 전용 색 테두리·2배 파문 |
| 데미지 숫자 | 설정 토글(기본 켬), 개체당 최대 1개 표시·풀링(성능 예산 내) |

- 위험 전조: 전조 전용 팔레트(경고 호박색 계열)와 배경 분리, 전조는 항상 점멸 아님(0.5s 페이드 인) — 방향서 1.3.
- 보스: 등장 2초 배너("검은 종 파수꾼이 문을 등지고 섰다") + 상단 전용 체력바 + 패턴명 캡션(종파/탑 그림자/소환/십자 종압) — 방향서 1.4.
- 캐릭터: 클래스 스프라이트 6종(기존 지시서 `prompts/codex/survivors-class-sprites-v1.md` 스펙 흡수 — 64×64 PNG, 절차형 폴백 유지) + 적 스프라이트는 v1 범위 밖(실루엣·색 대비 개선만).

## 4. 작업 D — 세션 구조

- 기본 URL = 퀵 런(10분). `?mode=long`(30분)·`?mode=demo` 유지. 안내 문구·운영 문서([dungeonworld-survivors-web-game.md](dungeonworld-survivors-web-game.md)) 갱신.
- 런 목표를 퀵 런 기준으로 재조정(기존 목표 풀에서 시간 조건만 스케일).
- 결과 화면에 "다음 목표" 1줄(미해금 항목 중 가장 가까운 것 — 5절 메타와 연결).

## 5. 작업 E — 메타 진행 (localStorage `survivors-meta-v1`)

- **종잔향(재화)**: 런 종료 시 `floor(생존초/10) + floor(처치/5) + (보스 격파 ? 500 : 0)` (퀵 런 기준. long 런은 동일 공식 — 시간이 길어 유리하지만 재화는 랭킹이 아니므로 무해).
- **해금 12종** (가격 1차안 — 구현 중 조정·보고):

| 해금 | 단계 | 가격 |
| --- | --- | --- |
| 여관의 아침식사 (시작 HP +10/+20/+30) | 3 | 300/900/2000 |
| 길잡이 부츠 (이속 +4%/+8%) | 2 | 400/1200 |
| 낡은 호신부 (피격 무적 +0.2s) | 1 | 1500 |
| 큰 주머니 (보석 자석 반경 +20%/+40%) | 2 | 300/900 |
| 대장간 신세 (시작 무기 Lv.2) | 1 | 2500 |
| 검은탑의 지도 (시작 시 첫 웨이브 구성 미리보기) | 1 | 600 |
| 종지기의 기억 (레벨업 선택지 리롤 런당 1회) | 2 | 1000/3000(2회) |

- **도전 과제 12종**: 직업별 궁극기 달성 6 + 무피격 3분·진화 2개 동시·보스 격파 등 6. 달성 표시는 도감(업적 패턴 재사용), 보상은 종잔향 소액.
- 결과 화면에 이번 런 종잔향 획득·누적 표시. 해금 상점은 시작 화면(직업 선택 옆 탭).
- 해금은 난이도를 낮추는 방향만(공격력 직접 상승 없음 — 랭킹 공정성 고려, 단 시작 무기 Lv.2는 예외로 명시하고 점수 상한에 반영).

## 6. 작업 F — Discord 연동·랭킹

- `public/shared/link.js` 로드 + 결과 화면에 연결 섹션·주간 랭킹 섹션(gk 컴포넌트 — 다크 톤 위에서의 대비만 스타일 오버라이드).
- 점수(퀵 런만 제출): `생존초 × 10 + 처치 × 2 + (보스 격파 ? 2000 : 0)`. **maxScore = 600×10 + 1600×2(예산 기반 처치 상한) + 2000 = 11,200 → 12,000**(여유). `GAME_DEFINITIONS`에 `survivors: { rankable: true, maxScore: 12000 }` + `/게임랭킹` choices 추가(**deploy 필요**) + 오늘의 도전 비대상(`dailyCapable: false` — 매치3 계획서 variant 구조와 함께 daily 지원 플래그 도입).
- long 런·데모는 제출하지 않음(클라 가드 + 문서화). 응원은 자동 편입(랭킹 화면 공용 컴포넌트).
- 운영 문서: [webgame-rankings-ops.md](webgame-rankings-ops.md) 게임 목록·상한 표·주간 지급 대상에 생존전 추가(지급 정책 동일 적용 여부는 운영 결정 칸 1개 — 4게임으로 늘면 지급 총액이 커짐).
