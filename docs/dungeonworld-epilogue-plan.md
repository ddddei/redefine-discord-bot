# 던전월드 에필로그 회차(10~12) 계획

이 문서는 미니게임 개선 4순위 "던전월드 후속 콘텐츠"의 구현 계획입니다. **이 문서만 보고 다른 컨텍스트 없이 구현을 시작할 수 있도록** 수정 위치, 콘텐츠 스캐폴딩, 테스트 갱신 지점까지 명시합니다. 구현 전 [AGENTS.md](../AGENTS.md), [src/AGENTS.md](../src/AGENTS.md), [scripts/AGENTS.md](../scripts/AGENTS.md)와 [dungeonworld-minigame.md](dungeonworld-minigame.md)를 읽습니다.

## 0. 착수 게이트 (운영 판단)

구현 시작 전 운영자가 `/운영현황 종류:미니게임`의 던전월드 회차별 진행 수에서 **8~9회차 도달 참여자가 실제로 있는지** 확인합니다. 종반 도달자가 없으면 이 작업은 보류하고 참여 유도부터 검토합니다. (이 게이트는 운영자 확인 사항이며, 코드 구현 내용에는 영향이 없습니다.)

## 1. 배경과 목표

- `/던전월드`는 1~9회차로 캠페인이 완결되어, 9회차("검은탑의 마지막 문")를 끝낸 참여자는 더 할 것이 없습니다. 9회차 closingNote는 이미 "후일담"을 예고했고, `src/dungeonworld.js:433-437` 주석에 10회차 이상 추가 절차가 준비되어 있습니다.
- 목표: **판정 메커닉·저장 구조·명령 스키마를 전혀 바꾸지 않고, 콘텐츠 객체 3개(10~12회차 에필로그)만 추가**해 완주자에게 마무리 서사를 제공합니다.
- 범위 제외: 클래스 선택 시스템(구조 변경이라 별도 검토), 다단계 분기, 포인트 지급(던전월드 무포인트 원칙 유지).

## 2. 방식 결정 (대안 비교)

| 방식 | 판단 |
|---|---|
| **에필로그 3회차 콘텐츠 추가 (채택)** | 코드 로직 0줄 변경(콘텐츠 상수 + 등록만). 기존 주간 오픈·기록·리포트·내보내기가 자동으로 새 회차를 포함 |
| 클래스 선택 시스템 | 세션 스키마·로그 레코드·화면 구조 변경 필요. "구조 불변" 원칙과 충돌, 장기 과제로 보류 |
| 새 캠페인(시즌 2) 전체 | 9회차 분량 콘텐츠 제작은 반응 검증 없이 과투자. 에필로그 반응을 보고 결정 |

**슬래시 명령 스키마 무변경 → `npm run deploy` 불필요.**

## 3. 콘텐츠 설계

### 3-1. 스키마 (기존과 동일 — `SESSION_09_FINAL_GATE`를 본보기로)

각 회차는 `{ id, title, intro, closingNote, introVariants?, choices }` 객체입니다. `choices`는 정확히 3개, 각각 `{ id, label, approachLabel, outcomes: { strong, mixed, weak } }`. `approachLabel`은 기존 3종(`위기 넘기기`/`살펴보기`/`말로 풀기`)을 회차마다 하나씩 사용합니다.

**콘텐츠 품질 기준 (기존 회차 테스트가 강제하는 수준)**:
- 각 outcome 텍스트 200자 이상, NPC 대사(큰따옴표 인용) 1개 이상 포함.
- 현재형·차분한 문체, 기존 회차와 동일한 서술 톤. 에필로그는 회복·연결·마무리 정서 중심(과한 공포·상실 묘사 금지 — 참여자 배려).
- `closingNote`는 다음 회차로 이어지는 훅(10·11회차) 또는 시즌 마무리(12회차).

### 3-2. 등장인물·설정 (기존 회차에서 확립된 것만 사용)

마라(여관 `마른 참나무` 주인), 토른(마을 경비병), 렌(정보상, 지도 출처), 픽(고블린 길잡이·조력자), 작은 왕(뿌리 소굴의 고블린 왕), 검은탑·검은 종·문 그림자·파수꾼(9회차에서 마무리됨), 뿌리 길·물그릇 신전·안개. 새 고유명사는 최소화합니다.

### 3-3. 회차별 스캐폴딩 (프롬프트 수준 — 본문 집필은 구현 시)

| 항목 | 10회차 | 11회차 | 12회차 |
|---|---|---|---|
| id | `session_10_quiet_morning` | `session_11_piks_debt` | `session_12_new_map` |
| title | `10회차. 종이 멎은 아침` | `11회차. 픽의 갚음` | `12회차. 새 지도의 첫 줄` |
| 무대 | 탑에서 돌아온 다음 날 아침의 마을. 종소리가 멎고 안개가 걷히는 중. 마라·토른 중심 | 픽과 함께 뿌리 소굴로 — 작은 왕과 마을 사이의 새 관계 정리. 픽·작은 왕 중심 | 여관에서 렌과 함께 낡은 지도의 빈 곳을 채우는 밤. 마라·토른·렌·픽 모두 등장 |
| 선택지 3개 | 무너진 우물·종탑 잔해를 치운다(위기 넘기기) / 탑이 남긴 흔적을 조사한다(살펴보기) / 마을 사람들의 소문을 가라앉힌다(말로 풀기) | 소굴로 가는 함정 길을 안전하게 튼다(위기 넘기기) / 소굴의 달라진 사정을 살핀다(살펴보기) / 작은 왕과 새 통행 규칙을 정한다(말로 풀기) | 지도의 마지막 빈 칸에 먼저 발을 딛는다(위기 넘기기) / 렌의 원본 지도를 맞춰 본다(살펴보기) / 다음 여정의 동행을 약속받는다(말로 풀기) |
| closingNote 방향 | 픽이 소굴에 다녀와야 한다는 말을 남김 → 11회차 훅 | 렌이 여관에서 새 지도를 펼쳐 놓고 기다림 → 12회차 훅 | "검은 종 이야기는 여기서 마무리, 새 지도는 다음 시즌에" — 9회차 closingNote와 같은 '한 번 마무리' 톤 |
| introVariants | **필수** — 9회차 결과(strong/mixed/weak)에 따라 아침 분위기가 달라짐(`SESSION_01_BLACK_BELL.introVariants` 형식 그대로: default+3종) | 선택(없으면 intro 사용 — 10회차 결과가 자연 반영되면 추가) | 선택 |

- 회차 간 연속성 로직(`getDungeonworldContinuityContext`, `src/dungeonworld.js:549-554`)은 직전 회차 최신 결과 등급으로 `introVariants`를 고르는 기존 코드가 그대로 동작하므로 **코드 수정 없음**. 10회차에 `introVariants`만 넣으면 9회차 결과가 자동 반영됩니다.

## 5. 동작 규칙

- 주간 자동 오픈(`resolveAutoSessionId`)은 `SESSION_ORDER` 길이로 클램프하므로 코드 수정 없이 10~12회차가 주차 일정에 편입됩니다. **단, `DUNGEONWORLD_START_DATE`가 9주 이상 지난 서버는 배포 즉시 10~12회차 중 해당 주차가 열립니다.** 순차 공개를 원하면 배포 전 `/던전월드관리` 오버라이드로 현재 회차를 고정하거나 시작일을 확인하도록 문서에 명시합니다(운영 절차, 코드 변경 아님).
- 참여자 화면·기록·운영 리포트는 새 회차를 자동 인식합니다(`SESSIONS` 기반 집계). 별도 연동 작업 없음.
- 포인트 지급 없음 — 에필로그도 동일. 보상 관련 코드 접근 금지.

## 6. 테스트 방법

- 신규 3개: `node scripts/test-dungeonworld-session-10.js` / `-11.js` / `-12.js` (4절 기준, 마지막에 성공 1줄 출력).
- 갱신: `node scripts/test-dungeonworld-sessions.js` — 클램프 단언 갱신 후 통과 확인 (**갱신하지 않으면 이 테스트가 실패합니다** — 의도된 회귀 가드).
- 회귀: `node scripts/test-dungeonworld-flow.js`(무변경 통과 예상), `npm run check:release` 전체 통과.
- 수동 검증(선택): 테스트 서버에서 `/던전월드관리`로 10회차 오버라이드 → `/던전월드` 플레이 1회 → 9회차 결과가 있는 계정에서 인트로 변형 확인 → `/던전월드기록`과 `/운영현황 종류:미니게임`에 새 회차가 잡히는지 확인.

## 7. 롤백 방법

- 단일 브랜치/PR(`feat/dungeonworld-epilogue`) → `git revert` 한 번으로 복구. `npm run deploy` 불필요.
- 롤백 후 로그에 남은 10~12회차 플레이 기록은 무해합니다 — 집계(`getDungeonworldSessionCounts`)가 알려진 회차만 세므로 표시에서 빠질 뿐 데이터 조치가 필요 없습니다.

## 8. 주의사항

- **콘텐츠 품질이 이 작업의 본체입니다.** 기존 1~9회차를 최소 2개(1회차와 9회차) 정독해 문체·호흡·NPC 말투를 맞춘 뒤 집필합니다. outcome은 결과 등급별로 실제로 다른 전개여야 하며(성공/대가/예상 밖), weak도 "실패 벌주기"가 아니라 "다음으로 이어지는 다른 길" 톤을 유지합니다.
- 에필로그 정서: 완주자에 대한 보상은 포인트가 아니라 "마을과 관계가 회복되는 서사"입니다. 고립청년 참여자를 염두에 두고 재회·환대·다음 약속의 정서를 담되, 훈계·교훈조는 금지합니다.
- 이 계획서(`docs/dungeonworld-epilogue-plan.md`)도 브랜치에 함께 커밋합니다. 커밋 컨벤션은 CommonJS·2-스페이스·세미콜론·작은따옴표, 한국어 커밋 메시지(기존 이력 참조).
