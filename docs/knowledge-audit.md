# FAQ / Knowledge 점검 보고서

이 문서는 `data/faq.json`과 `data/knowledge.json`의 역할을 구분하고, 중복 주제, 누락 가능성이 있는 주제, keywords 보강 대상을 정리하기 위한 기준 문서입니다.

FAQ와 Knowledge를 정리할 때는 참여자가 짧게 물어볼 법한 질문은 FAQ에서 빠르게 답하고, 프로그램 구조나 운영 원칙처럼 설명이 필요한 내용은 Knowledge에서 보완하는 방향을 기준으로 삼습니다.

## 현재 데이터 상태 요약

- `data/faq.json`은 짧은 질문과 즉답 중심의 데이터입니다.
  - `/질문`에서 가장 먼저 검색됩니다.
  - 결석, 지각, 운영진 문의, DM, 캡처, 미션, 출석처럼 즉시 안내가 필요한 질문에 적합합니다.
- `data/knowledge.json`은 프로그램 구조와 운영 원칙 중심의 데이터입니다.
  - FAQ에서 매칭되지 않은 질문에 대해 보조 설명을 제공합니다.
  - 16주 여정, 72시간 온보딩, 경험트랙, Redefine Lab, 안전 원칙처럼 배경 설명이 필요한 항목에 적합합니다.
- `data/test-questions.json`은 FAQ와 Knowledge 매칭 품질을 확인하기 위한 점검 질문 모음입니다.
  - 데이터 수정 후 `npm run test:questions`로 의도한 항목에 매칭되는지 확인합니다.
  - 의도된 무관 질문은 Fallback으로 남겨 두어 관련 없는 질문이 잘 걸러지는지도 확인합니다.

## FAQ로 남기기 좋은 항목

FAQ는 사용자가 짧게 묻고 바로 안심하거나 다음 행동을 정할 수 있어야 하는 항목에 적합합니다.

- 결석, 지각, 불참
  - 당일 참여가 어려운 경우
  - 늦거나 중간에 나가야 하는 경우
  - 결석이 불이익으로 이어지는지 묻는 경우
- 운영진 연락
  - 문의를 어디에 남기는지
  - 급한 문의와 일반 문의를 어떻게 구분하는지
  - 운영진에게 DM해도 되는지
- DM, 캡처, 신고
  - DM을 보내도 되는지
  - 불편한 DM을 받았을 때
  - 캡처나 다른 사람 이야기를 외부에 공유해도 되는지
  - 불편한 상황을 어디에 알려야 하는지
- 커뮤니티 규칙
  - 규칙을 어디서 확인하는지
  - 존댓말, 장난, 욕설, 대화 예절
  - 채널을 잘못 사용했을 때
- 익명고민채널 사용법
  - 익명으로 질문이나 고민을 남겨도 되는지
  - 익명으로 남긴 내용이 어떻게 다뤄지는지
- 포인트, 미션, 출석, 랭킹
  - 오늘의 미션을 꼭 해야 하는지
  - 미션이나 출석을 놓쳤을 때
  - 포인트를 어떻게 얻고 어디에 쓰는지
  - 랭킹이나 경쟁이 부담될 때
- 참여 중단, 탈퇴
  - 잠시 쉬고 싶을 때
  - 참여를 중단하거나 탈퇴하고 싶을 때
  - 공개 채팅에 먼저 말해도 되는지

## Knowledge로 유지하거나 보강하기 좋은 항목

Knowledge는 한 문장 답변보다 배경 설명과 운영 원칙이 필요한 항목에 적합합니다.

- 리디파인 전체 소개
  - 프로그램 목적
  - 준비중 청년과 고립 청년의 의미
  - 참여 대상과 참여 흐름
- 16주 여정
  - 1~3주 진입 및 방향 설정
  - 4~13주 공동 창조
  - 14~16주 Redefine Day 준비와 마무리
- 72시간 온보딩
  - 온보딩의 목적
  - 0~24시간, 24~48시간, 48~72시간 단계별 안내
  - OT 전 확인사항
- 경험트랙
  - 낭독극, 무용극, TRPG 상세 설명
  - 경험트랙 선택이 부담될 때
  - 공연이나 발표가 부담될 때
- Redefine Lab
  - Atelier, Art Journal, Writer's Room, Band Session 상세 설명
  - 여러 Lab을 오갈 수 있는지
  - 잘하지 않아도 참여할 수 있는지
- 상시 프로그램
  - 명상
  - 자조모임
  - 원데이 클래스
  - 클럽 활동
  - 책이나 콘텐츠 추천
- Redefine Day
  - 공유회, 공연, 부스, 회고파티
  - 가족이나 친구 초대 부담
- 커뮤니티 안전 원칙
  - 개인정보와 캡처 공유 주의
  - 과한 친목과 DM 예절
  - 불편한 상황을 운영진에게 알리는 방식
  - 안전을 해치는 행동에 대한 운영진 조치
- 정신건강·위기 상황 안내
  - 힘들거나 위험한 마음이 들 때
  - 봇이 의료적 판단이나 상담을 대신하지 않는다는 점
  - 필요한 경우 운영진 또는 전문기관 도움으로 연결하는 안내

## 중복 주제와 역할 분리 제안

### TRPG

- FAQ 역할
  - "TRPG가 뭐예요?", "처음이어도 괜찮나요?"처럼 짧은 질문에 안심 중심으로 답합니다.
  - 룰을 몰라도 괜찮고 진행자 안내를 따라갈 수 있다는 정도로 짧게 안내합니다.
- Knowledge 역할
  - TRPG가 캐릭터와 선택을 통해 이야기를 만드는 활동이라는 설명을 더 자세히 다룹니다.
  - 역할극, 말하기 부담, 참여 방식 조정이 필요한 경우 운영진에게 문의하는 흐름을 설명합니다.

### 익명고민채널

- FAQ 역할
  - 익명으로 질문이나 고민을 남겨도 되는지 즉답합니다.
  - 바로 확인이 필요한 내용은 문의 채널이나 운영진 연락 방법이 더 적절할 수 있음을 안내합니다.
- Knowledge 역할
  - 익명고민채널의 공개 범위, 보관 방식, 민감한 내용 처리 원칙을 설명합니다.
  - 세부 내용은 운영진 안내를 기준으로 확인하도록 정리합니다.

### DM 예절

- FAQ 역할
  - DM을 보내도 되는지, 불편한 DM을 받으면 어떻게 하는지 짧게 답합니다.
  - 반복 DM이나 사적인 접근은 부담이 될 수 있음을 안내합니다.
- Knowledge 역할
  - 과한 친목, 사적인 접근, 상대의 응답 없음에 대한 예절을 더 넓게 설명합니다.
  - 불편한 DM은 혼자 참고 있지 말고 운영진에게 알려도 된다는 원칙을 정리합니다.

### 포인트/랭킹

- FAQ 역할
  - 포인트를 어떻게 얻는지, 어디에 쓰는지, 랭킹이 부담될 때 어떻게 하는지 답합니다.
  - 미션이나 출석을 놓쳤을 때도 FAQ에서 바로 안내합니다.
- Knowledge 역할
  - 포인트, 미션, 랭킹이 경쟁 강요가 아니라 참여를 돕는 장치라는 의미를 설명합니다.
  - 세부 적립 기준과 사용처는 운영진 공지를 기준으로 확인하도록 안내합니다.

### 참여 부담

- FAQ 역할
  - 말하지 않아도 되는지, 눈팅만 해도 되는지, 이모지만 눌러도 되는지 즉답합니다.
  - 음성 채널, 마이크, 카메라가 부담될 때 선택 가능한 참여 방식을 안내합니다.
- Knowledge 역할
  - 디스코드에서 조용히 참여하는 것도 참여 방식이라는 운영 원칙을 설명합니다.
  - 경험트랙이나 Lab이 부담될 때 가벼운 참여부터 시작할 수 있음을 안내합니다.

### 가족 초대 부담

- FAQ 역할
  - 가족이나 친구 초대가 부담될 때 꼭 무리하지 않아도 된다는 짧은 답변을 제공합니다.
- Knowledge 역할
  - Redefine Day의 목적, 공유 방식, 초대 범위가 운영 안내에 따라 달라질 수 있음을 설명합니다.

### 커뮤니티 규칙

- FAQ 역할
  - 규칙을 어디서 확인하는지, 존댓말이나 장난은 어디까지 괜찮은지 짧게 안내합니다.
- Knowledge 역할
  - 커뮤니티 약속의 전체 방향, 개인정보 보호, 캡처 공유 주의, 안전 원칙을 설명합니다.

### 참여 중단/탈퇴

- FAQ 역할
  - 잠시 쉬고 싶거나 그만두고 싶을 때 누구에게 말하면 되는지 안내합니다.
  - 공개 채팅에 먼저 자세히 말하지 않아도 된다는 점을 짧게 안내합니다.
- Knowledge 역할
  - 참여 중단, 탈퇴, 잠시 쉬기의 차이를 더 부드럽게 설명합니다.
  - 개인 상황에 맞는 안내는 운영진 확인을 기준으로 하도록 정리합니다.

## Keywords 보강 후보

### 경험트랙 선택 부담

보강할 만한 표현:

- `트랙 못 고르겠어요`
- `뭘 골라야 할지 모르겠어요`
- `나한테 맞는 트랙`
- `선택하기 어려워요`
- `바꿀 수 있나요`
- `추천받을 수 있나요`

(해결됨) `data/faq.json`의 "경험트랙을 고르기 어려우면 어떻게 하나요?" 항목에 위 표현이 모두 keywords로 반영되어 있습니다.

### Lab을 여러 개 오가도 되는지

보강할 만한 표현:

- `여러 Lab`
- `왔다 갔다`
- `바꿔도 되나요`
- `하나만 골라야 하나요`
- `다른 Lab도 해도 되나요`
- `중간에 바꿀 수 있나요`

(해결됨) `data/knowledge.json`의 Redefine Lab 관련 항목에 위 표현이 모두 keywords로 반영되어 있습니다.

### 전문기관 연계

(해결됨) `data/knowledge.json`의 "필요한 경우 전문기관 연계 안내" 항목에 `전문기관`, `상담기관`, `병원`, `긴급 지원`, `전문 도움`, `기관 연결`, `외부 도움`이 모두 keywords로 반영되어 있습니다.

위기 상황 답변은 의료적 판단이나 상담을 대신하지 않아야 합니다. 위험한 마음이 들거나 긴급한 상황은 운영진, 신뢰할 수 있는 주변 사람, 전문기관 또는 긴급 도움으로 연결하는 톤을 유지합니다. 다만 "병원에 가야 할지 모르겠어요", "상담 받을 수 있는 기관을 알려주세요"처럼 정신건강/의료 상담을 직접 묻는 표현은 FAQ/Knowledge가 아니라 `src/safety.js`의 `detectSensitiveQuestion`(`medicalCounseling` 분류)이 먼저 가로채 운영진 확인 흐름으로 보내야 합니다. 아래 "안전 분류(safety.js) 점검" 절을 참고합니다.

## 안전 분류(safety.js) 점검

`/질문`은 FAQ/Knowledge 검색보다 먼저 `src/safety.js`의 `detectSensitiveQuestion`으로 민감 표현을 가로챕니다. 이 함수는 부분 문자열(`includes`) 매칭이라 키워드와 정확히 겹치지 않는 표현은 놓칠 수 있습니다. `npm run test:questions`는 FAQ/Knowledge 매칭만 확인하므로 안전 분류 누락은 따로 점검해야 합니다.

점검 중 다음 표현이 안전 분류에 걸리지 않고 그대로 FAQ/Knowledge fallback으로 빠지는 것을 확인해 keywords를 보강했습니다.

- `상담 받을 수 있는 기관을 알려주세요` → `medicalCounseling`에 `상담 받을 수 있는 기관` 추가
- `병원에 가야 할지 모르겠어요` → `medicalCounseling`에 `병원에 가야 할지` 추가
- `친구가 같은 서버에 있으면 불편해요` → `unwantedContact`에 `같은 서버에 있으면 불편해요` 추가

`scripts/test-safety-detection.js`로 긍정/부정 케이스를 고정해 두었습니다. `safety.js`에 키워드를 추가할 때는 이 스크립트로 회귀를 확인합니다.

## 추후 정리 방향

1. 중복 주제별 역할을 구분합니다.
2. FAQ는 짧은 질문 대응 중심으로 정리합니다.
3. Knowledge는 설명형 답변 중심으로 정리합니다.
4. keywords를 보강합니다.
5. 데이터 구조와 JSON 문법을 확인합니다.

```bash
npm run validate:data
```

6. FAQ와 Knowledge 매칭 결과를 확인합니다.

```bash
npm run test:questions
```

## 실제 수정 시 주의사항

- `.env`는 읽거나 수정하지 않습니다.
- `src/deploy-commands.js`는 수정하지 않습니다.
- Slash Command 구조는 변경하지 않습니다.
- 데이터 수정 후 아래 명령어를 실행합니다.

```bash
npm run validate:data
npm run test:questions
```

- 명령어 구조가 바뀐 것이 아니라면 `npm run deploy`는 필요하지 않습니다.
- 실제 토큰, 실제 채널 ID, 실제 환경변수 값은 문서나 로그에 남기지 않습니다.
- Railway, GitHub, Discord 설정은 데이터 정리 작업 범위에 포함하지 않습니다.
