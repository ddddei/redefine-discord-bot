## 0. 확정 설계 결정 (2026-07-05 사용자 확정 — 랭킹 배제, 참여 수·맞춘 횟수 분포만 노출)

1. **랭킹 없음, 응원 없음, 점수 없음.** 노출하는 사회적 신호는 "오늘 N명이 도전했어요"와 시도 횟수 분포뿐. `GAME_DEFINITIONS.word = { rankable: false, dailyCapable: true }`.
2. **채점은 서버.** 정답을 클라이언트에 내려보내지 않는다 — 미연결·익명도 채점 API 사용 가능(토큰 불필요).
3. 하루 1단어, 시도 6회, 재도전 없음(이 장르의 문법) — 단 실패해도 "내일 또 만나요" 톤, 실패 통계는 어디에도 노출하지 않는다.
4. 라우트 `/game/word/`(트레일링 슬래시), 간식 스토리북 톤(v3 프레임·gk 컴포넌트).

## 1. 게임 규칙

- 정답: **한글 2글자 단어** (간식·부엌·일상 명사). 각 글자를 초성·중성·종성 3칸으로 전개 → **6칸 그리드**(종성 없는 글자는 종성 칸 "없음" 상태로 고정 표시 — 칸 수는 항상 6, 없음 칸도 맞춰야 할 정보에 포함).
- 시도 6회. 각 시도는 유효 단어(사전 목록)여야 함.
- 피드백(자모 단위): **자리 일치**(진한 잉크·채움) / **다른 자리에 존재**(호박색 테두리) / **없음**(회림). 복모음·복자음은 단일 자모로 취급(ㅘ는 ㅘ 그대로 — 분해하지 않음, 사전과 일관).
- 키보드: 화면 하단 자모 키보드(두벌식 배열, 44px 타겟, 엄지 존). 사용된 자모에 피드백 색 반영.

## 2. 콘텐츠·정답 보안

- `data/word-pool.json`(커밋 — 공개 무해): 정답 후보 풀 300단어 + 유효 추측 사전 1,500단어(정답 풀 포함). 초기 목록은 구현 PR에 포함하고 톤 검수(비속어·상처 줄 수 있는 단어 배제) 목록을 보고.
- **그날 정답 선택은 서버만**: `index = sha256(WEBGAME_WORD_SALT + ':' + dayKey) % pool.length`. `WEBGAME_WORD_SALT`는 env(미설정 시 서버가 `data/webgame-social.local.json`의 cheerSalt 재사용 — 어느 쪽이든 저장소에 커밋되지 않는 값). 풀이 공개여도 "어느 날 어떤 단어"는 숨겨짐(억지력 철학 일관).
- 소진 대응: 305일 후 순환 — 운영 문서에 연 1회 풀 확장 절차 1줄.

## 3. 서버 API (`webgameApi.js` 확장)

| 엔드포인트 | 동작 |
| --- | --- |
| `GET /game/api/daily?gameId=word` | `{ dayKey, participants, distribution: {1..6: n, fail: 집계하되 응답에서 제외}, myResult }` — **정답·시드 없음**. distribution은 성공 시도 횟수별 인원(실패 인원은 노출하지 않음 — 배려 원칙). myResult는 토큰 있을 때 `{ tries } | null` |
| `POST /game/api/word/guess` | `{ dayKey, guess }` → `{ valid, feedback: [6칸 상태], solved }`. 토큰 불필요. dayKey는 오늘/어제만 허용(자정 유예), 사전에 없으면 `valid: false` |
| `POST /game/api/score` (기존) | 연결된 사용자의 결과 기록: `{ token, gameId: 'word', score: 7 - tries (성공) 또는 0 (실패), challenge: 'daily' }` — 기존 저장소 재사용, rankable false라 랭킹 미노출. 서버는 word의 daily 판정을 시드 대신 dayKey 직접 수용(word 전용 분기: seed 없음) |

- guess 빈도 제한: IP당 분당 30회(연결 코드 리미터 패턴 재사용) — 사전 무차별 대입 억지.
- **하루 1회 원칙의 강제 수준**: 서버는 같은 사용자의 중복 결과 제출을 dayKey당 1건만 기록(이후 무시·200). 로컬은 오늘 진행 상태를 localStorage에 저장해 재입장 시 이어보기. 시크릿 창 우회는 가능 — 억지력 수준으로 수용(랭킹이 없어 이득도 없음).

## 4. 클라이언트 (`public/word/`)

- 구성: `index.html`·`styles.css`·`logic.js`(자모 분해·피드백 계산의 순수 함수 — **클라는 검증 표시용, 채점 진실은 서버 응답**)·`game.js`(DOM). 모바일 하드닝 스펙(viewport-fit·dvh·safe-area·theme-color·무음) 최초부터 적용.
- 화면: 상단 "오늘 N명이 도전했어요" → 6×6 그리드 → 자모 키보드. 성공 시: "정답이에요! N번 만에 만났네요" + 분포 막대(내 위치 강조) + **결과 복사 버튼**(이모지 그리드 🟫🟨⬜ + "오늘의 간식 단어 dayKey" — 정답 미포함, Discord에 붙여넣는 가벼운 대화 소재). 실패 시: "오늘은 여기까지예요. 내일 새 단어로 만나요" — 정답은 **공개하지 않음**(다음날 어제 단어 확인 UI도 두지 않음 — 유예 제출자 보호 + 단순성).
- 연결 섹션(선택): 연결하면 내 기록이 분포에 반영된다는 1줄. 미연결도 전 기능 플레이 가능(분포 반영만 안 됨).
- 오프라인/서버 다운: "오늘의 단어를 불러오지 못했어요. 잠시 후 다시 와 주세요." — 이 게임은 서버 채점이 본체라 오프라인 플레이 불가(4종과 다른 점, 운영 문서 명시).
