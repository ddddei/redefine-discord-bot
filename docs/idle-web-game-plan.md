# 방치형 브라우저 미니게임 v1 계획서 — `간식 공방 키우기` (Codex 실행용)

이 문서는 다른 컨텍스트 없이 단독으로 구현 가능하도록 작성된 계획서입니다. 구현 전 이 저장소의 [AGENTS.md](../AGENTS.md), [src/AGENTS.md](../src/AGENTS.md), [scripts/AGENTS.md](../scripts/AGENTS.md)를 먼저 읽어 주세요.

## 0. 선행 조건

- PR #54(매치3 `간식 맞추기`)가 `main`에 머지된 뒤 `main`에서 브랜치를 냅니다. 이 계획서는 매치3이 만든 서빙/테스트 패턴을 미러링하며, 테마도 매치3의 간식 세계관을 이어받습니다.

## 1. 개요와 설계 철학

모바일 키우기류(거지 키우기, 포세이돈 키우기)와 건설·경영류(쿠키런 킹덤, 클래시오브클랜)의 재미 구조를 따르는 브라우저 방치형 게임 **`간식 공방 키우기`** 를 만듭니다. 매치3 `간식 맞추기`와 같은 밝은 간식/디저트 테마를 공유하는 자매 게임이며, 던전월드 세계관과는 무관합니다.

단순 숫자 증가(쿠키 클리커식 시설 목록)만으로는 재미가 없다는 판단에 따라, v1부터 다음 다섯 축을 모두 포함합니다:

| 재미 축 | 참고 게임 | 이 게임에서의 구현 |
| --- | --- | --- |
| 성장하는 주인공과 무대 | 거지 키우기, 포세이돈 키우기 | 길거리 좌판에서 간식 왕국까지 **무대 6단계 승급** + 직함 변화, 승급마다 화면(장면)이 눈에 띄게 바뀜 |
| 환생 루프 | 키우기류 공통 | **비법 레시피(환생)** — 끝까지 키운 뒤 처음부터, 영구 배수를 들고 다시 시작 |
| 돌아올 이유(타이머) | 클래시오브클랜 | **간식 배달**(시간제 파견) — 보내 놓고 나갔다가 돌아와서 보상 수령 |
| 방향을 주는 목표 | 쿠키런 킹덤 퀘스트 | **순차 퀘스트 체인** — 다음에 뭘 하면 되는지 항상 한 줄로 제시 + 보상 |
| 능동 플레이 보너스 | 쿠키 클리커 골든쿠키 | **황금 간식** — 화면에 가끔 나타나는 보너스 탭 |

기존 웹게임(`public/dungeonworld-survivors/`, `public/match3/`)과 동일한 운영 원칙과 서빙 구조를 따릅니다.

- 브랜치: `feat/idle-web-game-v1`
- 배포 경로: 관리자 서버(`src/adminServer.js`)의 `/game/idle` 라우트
- 정적 파일 위치: `public/idle/`

## 2. 운영 원칙 (생존전·매치3과 동일 — 반드시 준수)

- Discord 계정 연동 없음. 포인트 지급/차감/베팅/랭킹 저장 없음.
- 진행 상태는 **브라우저 localStorage에만** 저장하며 운영 데이터 JSON에 저장하지 않음. 서버는 정적 파일만 서빙.
- `.env` 수정, `npm run deploy` 불필요. 신규 npm 의존성 금지 (순수 HTML/CSS/JS).
- 기존 버튼형 미니게임의 보상 정책은 변경하지 않음.

## 3. 화면 구성 (모바일 앱 형식)

세로 모바일 우선 단일 페이지. 하단에 모바일 게임식 탭 바 4개를 두고, PC에서는 가운데 폭 480px 카드로 표시합니다.

```
┌────────────────────────┐
│ 직함 · 간식 보유량 · +N/초 │  ← 상단 고정 헤더
├────────────────────────┤
│                        │
│   [현재 탭 내용]          │  ← 공방 / 시설 / 배달 / 기록
│                        │
├────────────────────────┤
│ 현재 퀘스트 한 줄 + 보상    │  ← 퀘스트 바 (항상 표시, 달성 시 강조)
├────────────────────────┤
│  공방 │ 시설 │ 배달 │ 기록 │  ← 하단 탭 바
└────────────────────────┘
```

- **공방 탭 (메인)**: 무대 장면(아래 4.1) + 주인공 캐릭터 + 큰 간식 만들기 버튼. 클릭 시 캐릭터가 반응(CSS 애니메이션)하고 `+N` 숫자가 튀어 오름. 무대 승급 버튼도 여기에.
- **시설 탭**: 생산 시설 목록 + 업그레이드 목록.
- **배달 탭**: 배달 의뢰 3종과 진행 중 타이머.
- **기록 탭**: 업적 도감, 통계(누적 생산량·클릭 수·환생 횟수), 비법 레시피 현황, `처음부터 다시 시작`.

## 4. 게임 설계 (v1 범위)

### 4.1 무대 승급 — 성장의 뼈대 (거지 키우기 방식)

주인공(견습 제빵사 캐릭터, 이모지 조합으로 표현)이 좌판에서 왕국까지 성장합니다. 무대가 곧 진행도이며, 승급할 때마다 **장면 배경·소품·직함이 눈에 띄게 바뀌고** 새 시설·기능이 열립니다.

| 무대 | 장면 컨셉 | 직함 | 승급 비용(간식) | 승급 시 해금 |
| --- | --- | --- | --- | --- |
| 1. 길거리 좌판 | 돗자리+🍓 | 떠돌이 견습생 | — (시작) | 딸기 텃밭 |
| 2. 포장마차 | 수레+천막 | 포장마차 사장 | 2,000 | 오렌지 과수원, 배달 탭 |
| 3. 동네 가게 | 간판+진열대 | 골목 제과사 | 50,000 | 사탕 기계, 황금 간식 등장 시작 |
| 4. 간식 공방 | 오븐+굴뚝 | 공방 파티시에 | 1,500,000 | 쿠키 오븐, 컵케이크 스탠드 |
| 5. 간식 공장 | 컨베이어+트럭 | 공장장 | 80,000,000 | 젤리 공장, 8시간 배달 |
| 6. 간식 왕국 | 성+깃발 | 간식 대왕 | 5,000,000,000 | **환생(비법 레시피)** |

- 장면은 이미지 에셋 없이 **이모지 + CSS 배경(그라디언트/도형)** 으로 무대마다 뚜렷하게 다르게 구성합니다. 승급 순간에는 짧은 전환 연출(장면 교체 + 축하 문구 + 직함 변경)을 보여 줍니다.
- 승급 비용은 지불형(잔액 차감)입니다. 승급 버튼은 공방 탭에 항상 보여서 다음 목표가 명확하게 합니다(부족하면 남은 양 표시).

### 4.2 생산 — 클릭과 시설

- 자원은 **간식** 단일 자원. 큰 수 표기는 한국식 단위(`1.2만`, `3.4억`, `5.6조`, 소수 첫째 자리).
- **간식 만들기 버튼**: 클릭당 기본 1개. 업그레이드로 성장(아래 4.3).
- **생산 시설 6종** (매치3 타일 재활용, 무대 승급으로 해금):

| 시설 | 이모지 | 해금 무대 | 기본 비용 | 초당 생산(1대당) |
| --- | --- | --- | --- | --- |
| 딸기 텃밭 | 🍓 | 1 | 15 | 0.5 |
| 오렌지 과수원 | 🍊 | 2 | 200 | 3 |
| 사탕 기계 | 🍬 | 3 | 3,000 | 20 |
| 쿠키 오븐 | 🍪 | 4 | 60,000 | 150 |
| 컵케이크 스탠드 | 🧁 | 4 | 500,000 | 800 |
| 젤리 공장 | 🍇 | 5 | 10,000,000 | 6,000 |

- 비용 공식: `기본 비용 × 1.15^보유수` (내림).
- 시설 구매 시 공방 탭 장면에 해당 이모지 소품이 하나씩 추가됩니다(무대당 최대 표시 수 제한) — 쿠키런 킹덤처럼 **내 공방이 채워지는 느낌**을 주기 위한 장치입니다.

### 4.3 업그레이드 (일회성, 시설 탭 하단)

| 업그레이드 | 비용 | 효과 | 노출 조건 |
| --- | --- | --- | --- |
| 튼튼한 손가락 | 500 | 클릭당 생산 +4 (총 5) | 처음부터 |
| 달콤한 레시피 | 8,000 | 전체 생산량 ×2 | 무대 2 |
| 간식 배달부 | 100,000 | 클릭당 생산이 초당 생산량의 1%만큼 추가 | 무대 3 |
| 공방 확장 | 2,000,000 | 전체 생산량 ×2 | 무대 4 |
| 야간 요정 | 50,000,000 | 오프라인 수익 상한 8시간 → 24시간 | 무대 5 |

### 4.4 간식 배달 — 시간제 파견 (클래시오브클랜 방식)

배달 탭에서 의뢰 하나를 골라 보내면 **실제 시간**이 흐른 뒤 보상을 수령합니다. 동시 진행 1건(v1). 오프라인 중에도 타이머는 흐르고, 완료된 배달은 재접속 시 수령 버튼으로 대기합니다.

| 의뢰 | 소요 시간 | 보상 | 해금 |
| --- | --- | --- | --- |
| 동네 배달 | 5분 | 초당 생산량 × 900 (15분치) | 무대 2 |
| 축제 납품 | 1시간 | 초당 생산량 × 10,800 (3시간치) | 무대 3 |
| 왕궁 진상 | 8시간 | 초당 생산량 × 115,200 (32시간치) | 무대 5 |

- 보상은 **수령 시점**의 초당 생산량 기준으로 계산합니다(파견 중에도 성장할 이유 유지).
- 시계 역행(`now < 시작 시각`) 시 타이머를 시작 시각 기준으로 재고정하고 완료 처리하지 않습니다.
- 배달이 "그냥 기다리기"가 되지 않도록, 진행 중에는 남은 시간과 예상 보상을 표시합니다.

### 4.5 황금 간식 — 능동 보너스 (골든쿠키 방식)

- 무대 3부터, 게임 화면이 보이는 동안 45~120초 랜덤 간격으로 화면 가장자리에 ✨🍩 가 7초간 나타납니다.
- 탭하면 둘 중 랜덤: ① 즉시 간식 지급(현재 초당 생산량 × 420, 7분치) ② 30초간 클릭 생산 ×7.
- 백그라운드 탭/오프라인에는 나타나지 않습니다(능동 플레이 전용 보상).

### 4.6 퀘스트 체인 — 항상 다음 목표 제시 (쿠키런 킹덤 방식)

순차 진행 단일 체인 20개. 화면 하단 퀘스트 바에 현재 퀘스트 한 줄과 보상이 항상 보이고, 달성하면 `보상 받기` 버튼이 강조됩니다. 퀘스트는 자연스럽게 튜토리얼 역할을 합니다.

예시 흐름 (전체 20개는 구현 시 이 패턴으로 작성, 보상은 해당 시점 생산 규모의 3~10분치):

1. 간식 10개 만들기 → 보상 20
2. 딸기 텃밭 1대 사기 → 보상 50
3. 딸기 텃밭 5대 → 보상 300
4. 포장마차로 승급하기 → 보상 1,000
5. 첫 배달 보내기 → 보상 2,000
6. … (시설 확장 → 승급 → 배달 → 업그레이드를 번갈아 요구) …
20. 간식 왕국 승급 → 보상: 환생 안내

### 4.7 환생 — 비법 레시피 (키우기류의 핵심 루프)

- 무대 6(간식 왕국) 도달 시 환생 가능. 환생하면 간식·시설·업그레이드·무대·진행 중 배달이 초기화되고 **비법 레시피**를 획득합니다.
- 획득량: `floor(√(누적 생산량 / 5,000,000,000))` — 첫 환생에 1개 이상, 오래 버틸수록 더 받는 표준 공식.
- 레시피 1개당 **전체 생산량 +10% (영구, 환생해도 유지)**. 기록 탭에 보유 수와 다음 1개까지 필요한 누적량 표시.
- 환생 전 확인 모달에 얻을 레시피 수와 초기화 범위를 명시합니다. 업적·통계·레시피는 유지.

### 4.8 업적 도감 (기록 탭)

12종, 달성 시 간식 보상 + 도감 칸이 채워짐. 예: 첫 시설 구매, 클릭 1,000회, 각 무대 도달(5종), 배달 10회 완료, 황금 간식 5회, 첫 환생, 시설 전 종류 보유, 누적 1억. 업적은 환생해도 유지됩니다.

### 4.9 오프라인 수익

- 저장 데이터의 `lastSeenAt`(epoch ms) 기준, 재접속 시 경과 시간 × 초당 생산량을 지급. 상한 8시간(야간 요정 구매 시 24시간). 60초 미만 경과는 모달 생략하고 조용히 지급.
- 지급 모달: "자리를 비운 사이 3시간 12분 동안 간식 45.2만 개가 만들어졌어요." 완료된 배달이 있으면 함께 안내.
- 시계 역행이면 오프라인 수익 0, `lastSeenAt`만 갱신.

### 4.10 저장/불러오기·루프·카피 톤

- localStorage 키 `redefine-idle-save-v1`, JSON 직렬화(`version: 1` 필드). 자동 저장: 15초 간격 + `visibilitychange`(hidden) + 구매/승급/환생/배달 조작 직후.
- 손상된 저장 데이터(파싱 실패, 필수 필드 누락, 음수 수치)는 조용히 버리고 새 게임 시작 — 콘솔 경고만.
- 기록 탭에 `처음부터 다시 시작`(확인 모달, 되돌릴 수 없음 안내 — 레시피 포함 전부 삭제).
- 틱은 `requestAnimationFrame` 기반이되 생산·타이머 계산은 항상 **경과 시간 기준**(프레임 수 의존 금지 — 백그라운드 스로틀링에도 정확해야 함).
- 카피 톤: 한국어, 차분하고 직접적으로 (기존 참여자 카피 컨벤션). 승급/업적 축하는 가볍고 따뜻하게, 과장/호들갑은 피합니다.

## 6. 기존 파일 수정

### `src/adminServer.js`

매치3 서빙 코드(`resolveMatch3Asset` / `serveMatch3Asset` / `/game/match3` 라우팅 블록)를 그대로 미러링해 4곳을 추가합니다. 라인 번호는 매치3 머지 후 달라지므로 명시하지 않습니다 — 매치3 코드 바로 아래에 같은 형태로 두세요.

1. 디렉터리 상수: `const IDLE_PUBLIC_DIR = path.join(__dirname, '..', 'public', 'idle');`
2. `resolveIdleAsset(pathname)` — `/game/idle` 경로, `IDLE_PUBLIC_DIR` 기준, 경로 탈출 방지 `startsWith` 검사 포함.
3. `serveIdleAsset(res, pathname)` — 인증 없음, `servePublicAsset` 호출.
4. 라우팅 블록: `pathname === '/game/idle' || pathname.startsWith('/game/idle/')`.

관리자 인증(`requireAdminAuth`)은 걸지 않습니다 — 기존 게임 경로와 동일하게 공개 경로입니다.

### `scripts/check-release.js`

## 7. 테스트

테스트 러너 없이 순수 Node + `assert`, 마지막에 성공 한 줄 출력 (기존 컨벤션, [scripts/AGENTS.md](../scripts/AGENTS.md) 참고).

### `scripts/test-idle-logic.js`

`vm.runInNewContext`로 `content.js` + `engine.js`를 로드한 뒤:

- **비용 곡선**: 시설별 0·1·10대 보유 시 비용이 `기본 비용 × 1.15^n` 내림값과 일치.
- **생산량 합산**: 시설 조합의 초당 생산량이 정의값 합과 일치. ×2 업그레이드와 레시피 보너스(+10%/개)가 곱연산으로 반영.
- **클릭 생산량**: 기본 1, `튼튼한 손가락` 후 5, `간식 배달부` 후 5 + 초당 생산의 1%.
- **구매/승급**: 잔액 부족 시 거부(상태 불변), 충분 시 차감·반영. 무대 승급이 시설·기능 해금 판정에 반영.
- **배달**: 시작 → 소요 시간 전에는 미완료, 경과 후 완료. 보상이 수령 시점 초당 생산량 기준으로 계산. 시계 역행 시 완료 처리되지 않음. 동시 1건 제한.
- **퀘스트**: 체인이 순서대로만 진행, 각 달성 조건 판정과 보상 지급 검증(대표 5개 이상).
- **업적**: 경계값에서 달성 판정, 환생 후에도 유지.
- **환생**: 무대 6 미만이면 불가. 레시피 공식(`floor(√(누적/5e9))`) 경계값 검증. 환생 후 초기화 범위(간식·시설·업그레이드·무대·배달 리셋 / 레시피·업적·통계 유지) 검증.
- **오프라인 수익**: 주입한 두 시각의 차이 × 생산량과 일치, 상한 8h/24h 절단, 시계 역행 시 0.
- **저장 왕복**: 직렬화 → 역직렬화가 원본과 일치. 손상 입력(빈 문자열, 잘못된 JSON, 음수 보유량, 버전 누락)은 `null`.
- **큰 수 포맷**: `9,999` / `1.2만` / `3.4억` / `5.6조` 경계값.
- **밸런스 안전망**: 모든 무대 승급 비용이 직전 무대에서 도달 가능한 생산 규모로 상수 정의돼 있는지(오름차순, 시설 해금 순서와 모순 없음) content 정의를 순회 검증.

### 수동 QA

`ADMIN_DASHBOARD_ENABLED=true` + 관리자 계정 환경 변수 설정 후 `npm start` → `http://localhost:3000/game/idle`:

- 퀘스트 바를 따라가는 것만으로 무대 2 승급까지 자연스럽게 도달하는지 (튜토리얼 역할 검증).
- 승급 시 장면·직함이 바뀌고 새 시설이 열리는지. 시설 구매 시 장면에 소품이 추가되는지.
- 배달: 5분 의뢰를 보내고 탭을 닫았다가 5분 뒤 재접속 → 수령 대기 상태인지. 진행 중 남은 시간 표시.
- 황금 간식이 무대 3부터 나타나고 탭 시 보너스가 적용되는지.
- 오프라인 수익: 저장 데이터의 `lastSeenAt`을 3시간 전으로 수정 후 새로고침 → 모달·지급량 확인. 25시간 전 → 8시간 상한 확인.
- 환생(개발자 도구로 무대 6 상태 주입): 확인 모달 → 레시피 획득 → 초기화 후 생산 보너스 적용 확인.
- 새로고침 후 상태 유지(localStorage 복원), `처음부터 다시 시작` 동작.
- 모바일 뷰포트(375px)에서 탭 4개 전 UI가 조작 가능한지, PC에서 카드 레이아웃인지.
