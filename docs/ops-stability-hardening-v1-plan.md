# 운영 자동화 안정성 보강 v1 계획서

**상태: 구현 완료·실환경 QA 대기 (2026-07-11)**

## 목적

Phase 3 리마인더와 주간 운영 리포트가 Railway 재시작, 중복 tick, 채널 장애, 이력 저장 장애 상황에서도 중복 발송이나 거짓 성공을 만들지 않도록 공통 운영 안정성을 보강한다.

## 범위

- 주간 리포트 잘못된 요일·시각 설정 경고와 안전한 기본값
- 프로세스 시작 즉시 실행, 동일 프로세스 tick 중첩 방지, 저장 이력 기반 재시작 중복 방지 검증
- 예약·완료 이력 읽기/쓰기 실패를 예외 누출 없이 명시적 reason으로 반환
- Discord 전송 성공 후 완료 이력 저장 실패를 `SENT_HISTORY_FAILED`로 구분하고 운영 경고 출력
- 수동 주간 리포트 발송을 기존 admin 감사 로그와 알림 흐름에 기록
- 운영 콘솔 375px 모바일에서 리포트 조회·발송 버튼과 카드가 넘치지 않도록 보강
- API·Discord payload의 참여자 ID 목록, 인증/DM 원문, 첨부·URL, 메모 비노출 회귀 검사
- 백업·복원·strict preflight·기존 admin/리마인더 회귀 검사

## 제외 범위

- 자동 재시도, 실패 예약 해제, 관리자 UI에서 강제 재발송
- 다중 Railway replica용 분산 잠금 또는 외부 DB
- 새로운 채널·환경변수·Slash Command
- 참여자 대상 메시지와 운영 데이터 스키마 변경

## 완료 기준

모든 실패 경로가 예외로 서버를 깨뜨리지 않고 명시적 결과를 반환하며, 전송 성공 여부와 이력 저장 성공 여부를 구분한다. 자동화는 계속 기본 off이고 전체 release gate를 통과한다.

## 구현 결과

- 잘못된 주간 스케줄은 경고 후 월요일 10:00 KST로 안전하게 정규화한다.
- 예약 이력 실패는 `RESERVATION_FAILED`, Discord 전송 성공 후 완료 이력 실패는 `SENT_HISTORY_FAILED`로 구분한다.
- 중첩 tick은 `TICK_RUNNING`, 재시작 후 동일 주차는 `ALREADY_RESERVED`로 발송하지 않는다.
- 수동 발송의 시도·거부·성공·중복 결과를 admin 감사 로그와 운영 알림 흐름에 기록한다.
- 375px 화면에서 주차 선택·버튼·요약 카드를 1열로 배치한다.
