# 웹게임 랭킹·비동기 소셜 운영 절차

`간식 맞추기`(match3), `간식 수호대`(deck), `간식 공방 키우기`(idle) 3종 웹게임에 Discord 계정 연결·서버 점수 기록·주간 랭킹·오늘의 도전·공동 목표·익명 응원 기능이 추가됐습니다([webgame-discord-link-plan.md](webgame-discord-link-plan.md), [webgame-async-social-plan.md](webgame-async-social-plan.md) 참고). 이 문서는 현재 운영 절차만 다룹니다.

## v1 범위와 원칙

- v1에서는 **포인트 자동 지급을 하지 않습니다.** 부정 방지가 완전히 검증되기 전까지 자동 지급은 위험하다고 판단해, 운영자가 랭킹을 보고 기존 포인트 명령으로 수동 지급하는 절차를 공식 루프로 둡니다.
- 실시간 멀티플레이는 범위 밖입니다. 랭킹은 "이번 주 최고 기록" 기준 비동기 경쟁이고, 오늘의 도전·공동 목표·응원은 부담 없는 비동기 참여 장치입니다.
- `간식 공방 키우기`(idle)는 개인 랭킹 대상이 아닙니다. 주간 누적 생산량 차이만 공동 목표 총합과 참여 인원으로 표시합니다.
- `dayKey`는 KST 날짜, `weekKey`는 기존 UTC ISO 주차입니다. 주간 경계는 월요일 09:00(KST)입니다.

## 참여자 사용 흐름

1. Discord에서 `/게임연결`을 실행하면 6자리 코드가 DM으로 발급됩니다(DM이 막혀 있으면 에페메랄 메시지로 대체). 코드는 10분간 유효합니다.
2. 웹게임(매치3/덱빌딩 결과 화면, 방치형 기록 탭)의 계정 연결 섹션에 코드를 입력하면 연결됩니다.
3. 매치3/덱빌딩은 게임 종료 시, 방치형은 기록 탭 진입 시 점수가 서버로 자동 제출됩니다(참여자가 별도로 할 일은 없습니다).
4. 매치3/덱빌딩은 `오늘의 도전` 버튼으로 서버가 알려준 그날의 시드 판을 시작할 수 있습니다. 실패 횟수는 기록하지 않고, 그날 최고 기록만 오늘 랭킹에 남습니다.
5. 랭킹 화면의 다른 참여자 기록에는 익명 `응원하기` 버튼이 보일 수 있습니다. 누가 응원했는지는 표시·알림하지 않습니다.
6. Discord에서 `/게임랭킹 게임:<선택> 기간:<이번 주|오늘의 도전>`으로 주간 랭킹 또는 오늘 랭킹을 확인할 수 있습니다. `간식 공방 키우기`는 공동 목표 진행 상황을 보여줍니다.
7. 재연결(기기 변경 등)은 `/게임연결`을 다시 실행하면 됩니다. 이전 토큰은 자동으로 무효화됩니다.

## 운영자 주간 점검 절차

1. 매주 월요일(또는 정기 점검일), 운영자가 `/게임랭킹 게임:<match3|deck> 기간:이번 주`로 지난 주 상위자를 확인합니다. `idle`은 `/게임랭킹 게임:간식 공방 키우기`로 공동 목표 진행 상황과 참여 인원을 확인합니다.
2. 운영 정책에 따라 기존 `/포인트관리` 명령으로 수동 지급합니다.
   - 지급 기준 (2026-07-04 운영 결정, 중복 지급 없음):
     - 1위: `3,000P`
     - 2위: `2,000P`
     - 3위: `1,000P`
     - 4위 이하 참여자(해당 주 제출 기록 1건 이상): `500P`
   - 순위 보상을 받은 참여자에게 참여 보상을 중복 지급하지 않습니다.
3. 지급 사유에는 게임명과 주차(예: `2026-W27`)를 남겨 `/포인트로그`에서 추적할 수 있게 합니다. 예: "간식 맞추기 2026-W27 주간 랭킹 1위".
4. `/admin`(활성화된 경우) `웹게임 운영 현황` 섹션의 `flagged 기록` 목록에서 이상치로 플래그된 기록(`flagged: true`)이 있는지 확인합니다. `weekKey`/`dayKey` 필터로 지급 대상 주차를 좁혀 볼 수 있습니다. 플래그된 기록은 랭킹·공동 목표 계산에서 자동 제외되지만, 필요하면 해당 참여자의 해당 주 지급을 보류하거나 직접 확인합니다. 자세한 화면 구성은 [operator-dashboard-guide.md](operator-dashboard-guide.md)의 "`/admin` 웹게임 운영 현황" 절을 참고합니다.
5. 같은 섹션의 `리플레이 검증(v2) · 최근 불일치` 표에서 이번 주 mismatch 기록이 있는지 확인합니다(9절 참고). mismatch는 기본적으로 랭킹에서 제외되지 않으므로, 명백히 조작된 것으로 보이면 해당 지급을 보류하고 직접 확인합니다.
6. 청년동 자판기 교환은 기존 `/상점` → `/교환` 흐름을 그대로 사용합니다. 이 흐름을 위해 신규로 개발한 부분은 없습니다.

## 오늘의 도전 운영

- 매치3와 덱빌딩에서 자동으로 매일 KST 기준 시드가 바뀝니다. 운영자 개입은 없습니다.
- v1에서는 일일 보상이 없습니다. 오늘의 도전 기록도 같은 점수 저장소에 남으므로 주간 랭킹에는 자연스럽게 포함됩니다.
- `/게임랭킹 게임:<간식 맞추기|간식 수호대> 기간:오늘의 도전`으로 오늘 참여 인원과 상위 기록을 확인합니다.

## 랭킹 없는 데일리 게임: 오늘의 간식 단어

- `오늘의 간식 단어`(`/game/word/`)는 랭킹, 점수 공개, 응원 기능이 없습니다. 참여자에게 보이는 사회적 신호는 "오늘 N명이 도전했어요"와 성공자의 시도 횟수 분포뿐입니다.
- 정답 채점은 서버의 `POST /game/api/word/guess`에서만 처리합니다. 정답 단어, 정답 인덱스, `WEBGAME_WORD_SALT`는 API 응답이나 클라이언트 코드에 넣지 않습니다.
- 연결하지 않아도 끝까지 플레이할 수 있습니다. 다만 분포에 반영되는 결과는 `/게임연결`로 연결된 사용자의 하루 1회 제출뿐입니다.
- 실패 인원은 화면과 API 응답 어디에도 노출하지 않습니다. 실패 화면은 "오늘은 여기까지예요. 내일 새 단어로 만나요." 톤을 유지하고 정답을 공개하지 않습니다.
- 정답 풀은 `data/word-pool.json`의 300개 후보를 사용합니다. 305일 주기로 순환되기 전에 운영자가 연 1회 이상 후보 풀 확장을 검토합니다.

## 공동 목표 운영

1. 매주 월요일 주간 점검 때 `/게임랭킹 게임:간식 공방 키우기`를 실행해 지난 주 달성 여부를 확인합니다.
2. 달성했으면 운영자가 공지 채널에 수동 공지하고, 그 주 `idle` 제출자가 누구인지 확인한 뒤 수동 지급 여부를 결정합니다.
3. 보상 금액: `500P` — 달성한 주의 `idle` 제출자 전원에게 수동 지급 (2026-07-04 운영 결정)
4. 기존 주간 랭킹 지급과의 중복 정책: **중복 지급 허용** — 공동 목표는 경쟁과 무관한 "함께" 보상이므로 주간 랭킹 보상과 독립적으로 지급합니다 (2026-07-04 운영 결정). 지급 사유 예: "간식 공방 공동 목표 2026-W27 달성".
5. 첫 주 운영 후 달성률을 보고 `WEBGAME_COMMUNAL_GOAL`을 조정합니다. 2주 연속 20% 미만이면 하향, 첫날 달성이면 상향을 검토합니다.

## 부정 방지 v1 요약 (참고용)

완벽한 검증이 아니라 억지력 수준입니다. 자세한 구현은 `src/webgameApi.js`를 참고하세요.

| 항목 | 기준 |
| --- | --- |
| 게임별 점수 상한 | match3 50,000점, deck 11,060점(도달 스테이지×1000+잔여 HP 이론상 최대), idle 상한 없음에 가까운 넉넉한 값 |
| 빈도 제한 | 토큰당 분당 3회, 일 50회 초과 시 429 |
| 이상치 플래그 | 직전 주 최고 기록의 3배를 초과하면 `flagged: true`로 기록만 하고 랭킹에서는 제외 |
| 리플레이 검증 | match3·deck 대상. 시드+행동 로그로 서버가 점수를 재현해 `verified`/`mismatch`/`missing` 기록(9절) |
| 응원 제한 | 토큰당 분당 10회, KST 하루 30회 |

## 리플레이 검증 (v2)

`src/webgameReplay.js`가 match3(`public/match3/board.js`+`scoring.js`)·deck(`public/deck/engine.js`)를 그대로 사용해 클라이언트가 신고한 점수를 서버에서 재현합니다. 자세한 설계는 [replay-verification-plan.md](replay-verification-plan.md)를 참고하세요.

- 대상: match3·deck만. idle·word·survivors는 대상 외이며 기록에 `replay` 필드가 없거나 `skipped`로 남습니다.
- 판정 3가지: `verified`(재현 점수 일치), `mismatch`(불일치·무효 액션·로그 없이 재현 실패), `missing`(로그 없음·버전 불일치·액션 초과·재현기 예외 - 전부 무해 폴백).
- **mismatch는 기본적으로 랭킹에서 자동 제외되지 않습니다.** 클라이언트 버그로 인한 오탐이 참여자를 억울하게 차단하지 않도록 하는 배려 원칙입니다. 운영자가 `/admin` 대시보드에서 직접 확인 후 판단합니다.
- mismatch 진단 기록은 `data/webgame-replay-mismatch.local.json`에 최근 50건만 순환 보관됩니다(로그 원문 포함, 개인 행동 데이터이므로 백업 대상에 넣지 않고 커밋하지 않습니다). `/admin` API·화면에는 참여자·게임·점수·시각 메타만 노출되고 로그 원문은 노출되지 않습니다.
- **strict 전환**: `WEBGAME_REPLAY_STRICT=true`로 설정하면 mismatch 기록이 즉시 `flagged: true`로 전환되어 랭킹·공동 목표 계산에서 제외됩니다. **전환 기준 제안(운영 결정 사항): 2주 연속 mismatch 0건이면 켜기.** 켜기/끄기 결정과 시점은 아래에 기록합니다.
  - 운영 결정 칸: `[ ]` 아직 미전환 / `[ ]` 전환일: ______ / `[ ]` 재검토 사유: ______

## 확인이 필요한 상황

- 특정 참여자의 점수가 비정상적으로 높아 보이면 `flagged` 여부와 무관하게 운영진 판단으로 지급을 보류할 수 있습니다.
- `/게임연결` DM이 계속 실패하는 참여자는 서버 DM 수신 설정을 확인하도록 안내해 주세요(에페메랄 메시지로도 코드를 확인할 수 있습니다).
- 랭킹/응원 데이터(`data/webgame-links.local.json`, `data/webgame-scores.local.json`, `data/webgame-social.local.json`)는 다른 local JSON과 마찬가지로 커밋하지 않습니다.
