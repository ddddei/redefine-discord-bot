# 주간 운영 분석 리포트

봇이 집계한 확정 숫자를 받아 추세·이상 신호·권고 액션을 얹는다. 숫자 집계와 Discord 발송은 봇(weekly-ops-report v1)의 책임이고, 이 스킬은 해석 계층이다. 전체 설계는 [references/weekly-ops-analyst-agent-design.md](references/weekly-ops-analyst-agent-design.md) 참조.

## 금지 — 위반 시 실패로 간주

- POST 요청, Discord 발송, 파일 커밋, env·데이터·상태 변경 일절 금지 (읽기 전용 에이전트)
- 숫자를 직접 집계하거나 기억에서 가져오지 말 것 — API 응답에 있는 값만 사용
- 사용자 ID·이름·인증 원문·비밀번호를 리포트에 쓰지 말 것 (합계·건수만)
- 확인 못 한 것을 추정으로 채우지 말 것 — "수집 실패"라고 적고 진행
- 접속 정보 값(사용자명·비밀번호·토큰)을 채팅 보고에도 쓰지 말 것 — 인증 실패 시 "인증 실패" 사실과 확인할 항목만 보고
- 검사를 실제 수행 없이 "정상 ✓"로 표기하지 말 것 — 각 검사는 아래에 지정된 명령/방법으로 확인한 결과만 적는다

## 절차

1. `docs/ops-reports/analyst-notes.md`와 가장 최근 `docs/ops-reports/weekly-*.md`를 읽는다 (없으면 "첫 실행"으로 기록).
2. `$ADMIN_BASE_URL/api/admin/weekly-report?weekOffset=-1`을 `curl -u "$ADMIN_USERNAME:$ADMIN_PASSWORD"`로 호출한다. **401이면 즉시 중단**하고 "🚨 admin 인증 실패 — 비밀번호 확인 필요"만 보고한다. 연결 실패는 5초 간격 2회 재시도, 그래도 실패면 중단·보고한다.
3. `weekOffset=-2,-3,-4,-5`와 `/api/admin/summary`, `/api/admin/webgames`를 같은 방식으로 호출한다. 이 소스들은 실패해도 계속 진행하되 해당 절에 "수집 실패"라고 적는다.
4. `gh pr list --state merged --limit 20`으로 지난주 머지 PR 제목을 모은다 (실패 시 절 생략).
5. 정합성 검사: ① 응답 주 시작일의 요일을 `date -j -f "%Y-%m-%d" "<주시작일>" +%A` (macOS) 또는 `date -d "<주시작일>" +%A` (Linux) 명령으로 **실제 실행해** 월요일인지 확인하고 명령 출력을 각주에 인용한다. ② 참여자수·체크인·인증·포인트·교환 필드가 전부 있는지, ③ 값에 example/demo/sample 흔적이 없는지 확인한다.
6. 아래 템플릿으로 `docs/ops-reports/weekly-<주시작일>.md`를 쓴다. 같은 파일이 이미 있으면 덮어쓰지 말고 `-rerun`을 붙여 저장하고 그 사실을 보고한다.
7. 채팅 보고: TL;DR + 권고 액션 + 🚨 블록(있으면) + 리포트 파일 경로. 한국어. 커밋과 Discord 공유 여부는 운영자가 결정한다고 끝맺는다.

## 리포트 템플릿 — 절 제목·순서 변경 금지

```markdown
# 주간 운영 리포트 <주시작일> ~ <주종료일>
## TL;DR (3줄 이내)
## 🚨 확인 필요           ← 없으면 "없음" 한 줄
## 주요 지표 (전주 대비)   ← 표: 지표 | 이번 주 | 전주 | 방향(▲▼—)
   지표: 참여자 수 / 체크인 수 / 인증 승인·대기·반려 / 포인트 지급·차감 / 교환 상태별 / 지연 신호
## 4주 추세               ← 문장 2~4개, 수집 실패 시 "추세 생략(사유)"
## 지난주 변경 사항        ← 머지 PR 제목 목록
## 전주 권고 이행 확인     ← 직전 리포트의 권고 액션별 이행/미이행/판단불가
## 권고 액션 (1~3개, 우선순위순) ← 각각 "무엇을·어디서·왜" 1문장씩
## 데이터 품질 각주        ← 아래 체크 7항목 결과 전부 명시 ("이상 없음" 포함)
```

## 에스컬레이션 — 발견 즉시 "🚨 확인 필요" 절에 사실만 기록 (해석 금지)

- 참여자 수 0 또는 전주 대비 -50% 이상 급감
- 주간 리포트 발송 이력에 `failed`
- example/demo/sample 레코드가 실데이터 응답에 노출
- flagged 웹게임 기록 존재
- 지연 신호 2주 연속 증가

## 데이터 품질 각주 체크 7항목

1. 참여자·거래 수 0 여부 / 2. 4주 숫자 전부 동일 여부 / 3. 주 시작일 불일치 여부 /
4. 필수 필드 누락 여부 / 5. 같은 주 아카이브 중복 여부 / 6. 백업·발송 이력 공백 여부(env 꺼짐 vs 고장 구분) /
7. 매월 첫 리포트에는 "이번 주는 수동 대조 주입니다" 리마인더 포함

## 잘 작동하는지 확인하는 테스트

1. **결함 주입**: 모의 서버로 ① 401 응답 ② 참여자 0 응답을 만들어 하위 모델에게 이 스킬을 실행시킨다. ①은 즉시 중단+인증 실패 보고, ②는 리포트를 완성하되 🚨 절에 기록해야 통과.
2. **금지 위반 검사**: 테스트 실행의 도구 호출 로그에 POST·커밋·발송이 없는지 확인.
3. **템플릿 준수**: 생성된 리포트의 절 제목·순서가 템플릿과 일치하고, 데이터 품질 각주에 7항목이 전부(이상 없음 포함) 있는지 확인.
